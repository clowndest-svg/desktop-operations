# 手机版方案（mobile）

> 先说结论，再说怎么做。**这份方案里每一条"能不能"都是这台机器上量出来的**，
> 不是照着"通常来说"写的。

## 0. 一句话架构

**手机当不了大脑，也别让它当。**

这台电脑上真正的能力是：funasr+torch 的语音栈（模型实测 **1.7 GB**）、pyautogui 桌面控制、
磁盘清理、Win32 托盘/热键/镂空窗口。**这些一个都跑不到 Android 上**——不是难，是平台不允许
（Android 沙箱禁止操作别的应用，磁盘清理只能碰自己的沙盒，没有托盘这回事）。

所以手机版是**同一个大脑的第二张脸**：

```
        ┌──────────────── 你的电脑（大脑，不变）────────────────┐
        │ 语音栈 / agent / 工具 / 调度 / 记忆 / 知识库 / 桌面控制 │
        │                    + 局域网服务（新增）                 │
        └───────────────────────┬────────────────────────────┘
                                │  Wi-Fi（配对码 + token）
                    ┌───────────┴───────────┐
                桌面壳(pywebview)        手机 App（新增）
                                      ① 遥控模式：连电脑，用全部能力
                                      ② 独立模式：连不上电脑时自己也能聊天/说话
```

## 1. 两种模式，都要，但顺序有讲究

### ① 遥控模式（先做，这是卖点）

手机是**麦克风 + 扬声器 + 屏幕 + 通知**，AI 和工具全在电脑上跑。
好处是：**桌面端能力以后每加一条，手机自动就有**，不用改两遍。

手机上能干什么（都是电脑现在已有的能力，只是换个入口）：

| 手机上的动作 | 背后 | 为什么值得做 |
| --- | --- | --- |
| 按住说话 / 唤醒词 | 电脑 ASR | 躺床上也能用；手机麦克风比远场电脑好得多 |
| 对话 + 朗读 | 电脑 agent + TTS | 同一条链路，不重做 |
| **看一眼我的电脑** | 电脑截图 → 手机 | 桌面端 #75 缺的"视觉"，手机上反而是自然形态 |
| 提醒/记忆/知识库 | 电脑 SQLite | 出门前问一句"我明天有什么安排" |
| 遥测/进程/清理 | 电脑 psutil/清理器 | 在沙发上看到 CPU 爆了，远程结束那个进程 |
| **确认弹窗推给手机** | 电脑上的二次确认 | 关键：**手机点确认 = 人真的同意了**，比在电脑上盲点更安全 |

最后一条是设计核心：**危险操作的确认可以在手机上完成**，但确认框的内容由电脑生成、
带完整命令文本和档位，手机只负责"人在场"这件事。删除类仍然只能在电脑本机确认（照旧红线）。

### ② 独立模式（后做，但必须有，否则"分享给朋友"是假的）

**朋友装了 APK，他没有你这台电脑。** 所以 App 必须能脱离电脑独立活着：

- 直接连他自己的大模型 key（**首次启动让他自己填**，存 Android Keystore 加密的
  `EncryptedSharedPreferences`，**绝不写普通文件、绝不打日志**）；
- 语音识别用 **Android 系统 SpeechRecognizer**（离线包可下，中文支持好，零成本）；
- 朗读用 **Android 系统 TextToSpeech**（离线、不联网，比 edge-tts 更适合手机）；
- 没有桌面控制、没有清理——**界面上直接说明"连上同一 Wi-Fi 的电脑后解锁全部能力"**，
  这本身就是最好的转化入口。

> 这条决定了产品形态：**独立模式是试用版，遥控模式是完整版。**

## 2. 技术选型（都基于"已经有的东西"）

| 层 | 选什么 | 为什么 |
| --- | --- | --- |
| 壳 | **Capacitor 7**（把现有 Vue 3 前端包成 Android 工程） | 前端已经是 Vue3+Vite，复用 90%；比重写 Kotlin 快一个数量级 |
| 界面 | 复用现有 HUD 组件，**新增移动端布局**（单列、大按钮、底部说话键） | HUD 那套赛博视觉直接迁，品牌一致 |
| 通信 | **WebSocket（控制+流式）+ HTTPS（截图/文件）**，JSON 消息协议 | 语音要流，轮询不行 |
| 安全 | 配对码 + 每设备 token + **TLS（自签 + 证书指纹固定）** | 见 §4，这是最容易出事的地方 |
| 手机录音 | Capacitor 插件 + Web Audio | 系统权限弹窗要处理好 |
| 打包 | Android SDK + Gradle（**本机已具备 JDK 17，网络已验证可达**） | 见 §5 |

## 3. 电脑端要新增什么（改动面）

1. `jarvis/ui/lan_server.py`（新）： aiohttp 或标准库 `http.server` + WebSocket，
   **默认完全关闭**，托盘菜单「手机接入」勾选才监听。
2. 桥面/托盘：显示当前局域网地址 + **6 位配对码**（有效期 5 分钟，用一次作废）。
3. 消息协议复用现有 `HudBridge` 的方法名——手机发的每个请求都映射到一个已存在的桥面方法，
   **不新增能力面**，避免"手机上多出一条电脑上没有的后门"。
4. 危险操作：桥面方法在电脑侧仍走**同一套档位与确认**；确认可以路由到手机，但
   `confirmed` 参数**永远不接受来自模型的值**（这条已经有测试守着）。

## 4. 安全（这部分不敢省，因为等于在你电脑上开网络入口）

| 风险 | 处置 |
| --- | --- |
| 局域网里别人连上这个端口 | 只监听局域网接口 + 首次必须用配对码换长期 token + **所有请求校验 token** |
| 抓包看到命令和回复 | TLS（自签证书 + 客户端固定指纹），明文一律拒绝 |
| token 泄漏 | 托盘里能"撤销所有设备"；token 只存哈希，不存原值 |
| 公网暴露 | 明确**不做**穿透；文档写死"只在内网用"。想远程要自己上 VPN |
| 手机丢了 | 电脑端撤销该设备即可，App 里的 key 在 Keystore 里，卸载即清 |
| 恶意确认 | 确认框在手机上也要**显示完整命令原文**，且 30 秒超时自动拒绝 |

## 7. 明确不做

| 不做 | 为什么 |
| --- | --- |
| iOS 版 | 需要苹果开发者账号（$99/年）+ TestFlight，且 Capacitor 的 iOS 工程要 macOS 才能构建——**这台是 Windows** |
| 手机操控**另一台**安卓手机 | 要无障碍服务，Google Play 严格限制，且隐私代价不对等。**注意区分**：这一版做的是"她动**自己跑着的那台**手机"（§13），不是拿一台手机去遥控另一台 |
| 端侧跑大模型/端侧 funasr | 1.7 GB 模型 + torch，手机上不现实 |
| 公网穿透/云端中转服务器 | 一旦有云端，密钥、聊天记录、命令审计就都在别人机器上了；这是这个产品的立身之本 |
| 把电脑版的数据同步到手机 | 手机不该持有另一份真相；要历史就看电脑 |

## 9. 实现中改掉的两条原方案（写下来，别让人以为代码"应该"长这样）

**手机识别改用系统引擎，不改用电脑 ASR 做唯一通路。**
原方案 M3 是"手机录音 → 电脑 funasr 识别"。实现时改成：**手机优先用 Android
`SpeechRecognizer`（独立模式本来就要它），电脑那套只在连着电脑时作为可选后端**。
理由是量出来的，不是审美：
- 独立模式（M7）没有电脑可用，识别必须自给，`SpeechRecognizer` 零成本、离线包可下、中文可用；
- 把手机音频流推到电脑上识别，需要一条**持续**的双工音频链路，M1 的
  `http.server` 只做请求-响应，`aiohttp`/`websockets` 这台机器上都没装；
  为了省一次系统 API 调用去引入一个长连接层，代价不对等。
- 真机上到底哪条更快更准，要拿同一句话在两条路上各测一遍才敢下结论 —— 这条留在 M3 的验收里。

**手机不用 `fetch` 直连，所有网络走原生 `XyNet`。**
两个理由叠在一起：页面装在 `https://localhost` 这个源里，绝大多数 OpenAI 兼容端点
不发 CORS 头，`fetch` 死在预检，只回一句 `Failed to fetch`；而电脑端点是自签证书，
`fetch` 撞墙时报的也是同一句话。原生层能带回**状态码和响应正文**，错误才分得清是
"网不通"还是"证书不对"——这两件事的处置完全不一样。

**原样参数**把 10 个方法逐个真打过了，含一张真 JPEG 走完整条附件路。

1. `pcHello` 没带证书指纹 → 「先探一下」对着自签证书走系统信任链，

2. 手机上把历史会话的正文读成 `text`，电脑写的键是 `content` → 翻开电脑上的会话，
   每条气泡都是空的，看着像"历史没了"。
3. 手机发 `{ sessionId: id }`，电脑的 LAN RPC 是按**关键字**调桥面方法的，
   形参叫 `session_id` → 参数不合法。桌面上看不出这一条：pywebview 走位置传参。

顺带把 `MAX_BODY_BYTES` 从 512 KiB 提到 2 MiB：电脑自己允许的附件量是

手机发一张照片得到 413，而电脑上同一个文件发得出去——在用户眼里那不是"太大"，是"手机版是坏的"。

### 13.1 键盘盖住输入框：真机上推翻了两版设计

这是用户报的第一条，也是这一轮唯一一个"用户每天都会撞到"的 bug。
**两版设计都是在真机上被否掉的**，写下来免得下次再走一遍。

**第一版：网页层三层。** `adjustResize` + `interactive-widget=resizes-content`
+ 自己读 `visualViewport` 写 CSS 变量。**全落空，而且自己制造了一个更糟的 bug**：
读 `offsetTop` 再用 `translateY` 跟着浏览器平移，浏览器为了露出光标一平移，
整个界面就被推到屏幕外 —— 屏幕上只剩窗口背景。

**第二版：原生层直接把 IME 高度写成 WebView 的下外边距。** 聊天页好了
（这一版真机上验过，输入胶囊完整露在键盘上面），但设置面板里点一个靠底部的输入框
**整屏变黑**：WebView 被压到没有高度，屏幕上只剩 Activity 的窗口背景
（那张 Capacitor 启动图）—— 进程还活着、没有崩溃日志、没有异常。
让两个层同时拥有布局的控制权，出错时的表现就是这样：没有任何线索。

**第三版（现在这版）：原生只报一个数，页面自己算。**

```
MainActivity.reportKeyboardHeight()
  └─ 挂在**父布局**上的 OnApplyWindowInsetsListener
       └─ 把 ime inset 换算成 CSS 像素 → document.documentElement.style['--xy-kb']
            └─ .app { position: fixed; top: 0; left: 0; right: 0; bottom: var(--xy-kb, 0px) }
```

三个"为什么"都是真机上量出来的：

- **为什么非要在原生层量**：Android 15+ 上目标 SDK 35 的应用被强制 edge-to-edge，
  `adjustResize` 从此不再缩窗口（它仍然写在 manifest 里，是给 Android 14 及更早的），
  于是 `dvh`、`visualViewport`、`adjustResize` 三条网页层的路**一起失灵**。
- **为什么只报数、不改尺寸**：第二版的教训。布局始终只有一个主人。
- **为什么监听器挂父布局**：`View.dispatchApplyWindowInsets` 只要发现设了 listener，
  就直接返回 listener 的结果、**不再调用 `onApplyWindowInsets`**。而 WebView 正是靠
  那个方法记录安全区、让 CSS 的 `env(safe-area-inset-*)` 有值的。
  挂 WebView 上的那一版，键盘修好了，顶栏却整个贴到状态栏底下
  （真机截图：`小夜` 和状态栏的时钟叠在同一行）。
  挂父布局则两头都对：父布局返回未消费的 insets，ViewGroup 会继续往下派发给子 View。

### 13.2 设置面板黑屏的真正原因：`type="password"`

13.1 里那个"整屏变黑"**不是**布局问题。真机上做了一次便宜的判别实验：

| 在设置面板里点哪个框 | 顶栏区域的亮像素 |
| --- | --- |
| Base URL（`type="text"`，不需要滚动） | 3479 |
| 模型名（`type="text"`，需要滚动） | 3276 |
| API Key（`type="password"`） | **0** |

同一个面板、同一个位置，唯一的差别是输入框的 `type`。聚焦密码框会让输入法切到
**安全输入 / 独立编辑**那一套，在 vivo 的 OriginOS 上直接把 WebView 整个顶掉。

处置：API Key 改成 `type="text"` + `-webkit-text-security: disc` 做遮挡，
旁边加一个「显示/隐藏」按钮。视觉一样，不碰系统的密码通路。
`tests/test_mobile_frontend.py` 里有一条"手机界面上不许出现 `type="password"`"盯着它。

**这条经验值得记**：整屏空白 + 进程存活 + 无崩溃日志，最像"布局写错了"，
实际原因是输入框的类型。找它靠的不是读代码，是**把变量一个个隔离出来量**。

### 13.7 构建与安装上撞到的四件事

1. **`npx cap sync/copy android` 会失败，但不影响出包。** 环境的删除保护（safe-delete）
   拦住了它对 `assets/public` 和 `capacitor-cordova-android-plugins` 的清理。
   判据是看 `android/app/src/main/assets/public/assets/` 里那几个文件的**时间戳**，
   不是看这条命令的退出码。手动同步的办法（跳过 site 钩子）：
   `python -S -c "import shutil; shutil.rmtree(dst); shutil.copytree(src, dst)"`。
2. **`R.id.webview` 在 app 模块里不存在。** AGP 8 默认不传递 R 类，Capacitor 那个布局里的
   id 不在本模块的 R 里，编译期直接 `cannot find symbol`。走 `bridge.getWebView()` 更稳。
3. **vivo 每次装都要人工点一次「授权本次安装」。** 报的是
   `INSTALL_FAILED_ABORTED: User rejected permissions`，实际原因是设备锁屏
   （`isKeyguardShowing=true`）或 vivo 的「超级守护」拦截页；那个页面是 FLAG_SECURE，
   `screencap` 拍出来全黑，所以只能让用户点。`adb shell svc power stayon usb`
   能减少锁屏次数。`pm install` 一样会被拦。
4. **`adb install` 会占住 APK 文件**，导致紧接着的 `gradlew assembleRelease`
   报 `Unable to delete directory .../outputs/apk/release`。先结束那个 adb 进程再打包。

## 13. 她能动手了：AI 控制这台手机（0.3.x）

前面所有版本里她只有嘴。这一节是第一次"她说做，就真的做了"。

**一条注册表，三个用途。** `frontend/src/mobile/actions.ts` 里的 `ACTIONS` 同时是
模型看到的工具清单（`toolSchemas()`）、界面"她会做什么"那一页、以及执行器查的那张表。
分三份写的必然结局是"模型说她能定闹钟，屏幕上却找不到这个按钮"。

**能做的 13 件**（`capability` 会先问这台设备做不做得了，做不了就说做不了）：

| 直接做 | 要先点头 |
| --- | --- |
| 看电量、看音量、列应用 | 定闹钟 |
| 调音量、手电筒、震一下、开设置页、打开应用 | 拨号、写短信、加日程、开链接 |

分界线只有一条：**会不会离开这台手机、会不会花真钱、会不会在别人的世界里留下痕迹**。
"打开应用"看着像越界，其实一键就能退回来，所以归直接做那栏。

**最后一下永远是人按的。** 拨号走 `ACTION_DIAL`（开拨号盘，不拨）、短信走
`ACTION_SENDTO`（填好草稿，不发送）、日程走 `ACTION_INSERT`（打开新建页，不写库）。
所以这四个动作即使确认闸被绕过，也还是要在系统界面里再按一次才算数——
**这是第二道闸，不是装饰**。

**确认闸写在类型上，不写在注释里。** `execute(name, args, approve)` 的 `approve` 是必填参数：
少传一个回调就是一条编译错误。而 `confirmed` 这个词在注册表、工具 schema、原生方法签名里
**都不存在**——桌面那边"清理磁盘的 `confirmed` 不许是模型能填的参数"那条规矩，这里照搬。
三条挡箭牌都做过变异验证：把 `send_sms` 的 `needsConfirm` 改成 false、把 `approve` 改成可选、
把 Java 的 `setVolume` 改个名，对应的测试各自立刻红。

**台账记全部，包括被取消的。** 手机上那一页"最近她动过什么"存在这台设备自己的目录里
（电脑那本记的是电脑上的事，管不到这台手机的手电筒）。失败和"你按了取消"都进账，
只记成功的那本不是台账，是宣传。

**遥控模式下她动不了这台手机，界面上就这么写。** 电脑上的那个 agent 够不到手机，
把工具清单发过去只会让她答应做一件做不到的事。所以工具环只在独立模式跑；
连着电脑时那一页顶部挂一句红字说明为什么。

**没有做的**：读短信、读通讯录、代用户点别的 App 的界面。那些要无障碍服务或一批危险权限，
装上等于把整台手机交出去——没人会为了"帮我定个闹钟"预期这种代价，所以也不该偷偷给他。
这条写在界面上，不藏在代码里。

**这一版的两个已知未验点**（不是"应该能"，是"还没看到"）：

1. **0.3.1 没装过机器**。APK 出好了（`E:\BianChengGongJu\JarvisBuild\mobile\r3\小夜-0.3.1.apk`，
   5,443,420 字节，release 签名证书 `f6dee6ab…`），但 MuMu 已经关了、四个 ADB 端口都拒连，
   所以手电筒/闹钟/拨号盘这些**一个都还没在屏幕上真按过**。上一版 0.2.0 装过并验过拍照和免提。
2. **工具环没对真模型跑过**。这台机器的 shell 里没有可用 key，`tools` 字段发出去会怎样、
   各家 OpenAI 兼容端点的 `tool_calls` 形状差多少，都还是纸面推断。
   已经写了一条兜底：模型不接 `tools` 时退回纯聊天，并且**把"退回了"这句话显示出来**，
   不静默变成一个只会聊天的助手。

## 14. 真机（vivo V2309A / Android 16）第一次跑：一个闪退、一个查询写错

前面所有"验过"都是模拟器和契约脚本。2026-10-03 晚上机主把自己的手机接上来 USB 调试，
第一次在真机上跑，当场出两件事。

### 闪退根因：插件方法跑在工作线程上

```
FATAL EXCEPTION: CapacitorPlugins
java.lang.RuntimeException: SpeechRecognizer should be used only from the application's main thread
  at android.speech.SpeechRecognizer.createSpeechRecognizer(SpeechRecognizer.java:387)
  at com.xiaoye.assistant.XySpeechPlugin.begin(XySpeechPlugin.java:95)
  at com.xiaoye.assistant.XySpeechPlugin.listenStart(XySpeechPlugin.java:75)
```

19:34、21:19、21:20 三次同一处。**"聊着聊着突然没了"= 一按说话键就带走整个进程。**

- 为什么以前没发现：Capacitor 把插件方法派给它自己的 `CapacitorPlugins` 线程，
  而 `SpeechRecognizer.createSpeechRecognizer` 和 `TextToSpeech` 的构造只许主线程。
  这条约束**不写在编译器的报错里**，Java 编得过、契约脚本也过不去这一层（它不碰原生）。
- 为什么模拟器不复现：MuMu 根本没有系统语音引擎，`begin()` 在
  `isRecognitionAvailable` 那一步就 return 了，**走不到崩的那一行**。
  一个缺功能的环境把崩溃藏住了——这是"没有真机就等于没测"的一个具体形状。
- 修法：`listenStart` / `listenStop` / `speak` / `stop` 四个入口全部 `main.post(...)` 回主线程，
  见 `XySpeechPlugin.onMain()`。修完在同一台机器上按住说话键 2.5 秒：进程活着（pid 6847），
  crash buffer 零条。

### 相册：`Invalid token LIMIT`

`MediaStore.query` 的排序串里不能带 `LIMIT`——整段会被当 ORDER BY 交给 SQLite，
报 `Invalid token LIMIT`，屏幕上就是这句。改成 Java 侧计数截断（顺带避免把
**3296 张**（这台机器 `content://media/external/images/media` 的实际行数）全表塞过桥）。

同时补上清单里缺的三个读媒体权限：Android 13+ 的 `READ_MEDIA_IMAGES`、
13 以下的 `READ_EXTERNAL_STORAGE`（带 `maxSdkVersion="32"`）、14 的
`READ_MEDIA_VISUAL_USER_SELECTED`。只声明老的那个，在 Android 16 上永远拿不到权限，
表现就是机主问的那句"为什么你读不了相册里的图片"。

## 15. 0.4.0：流式回答 + 中途能停 + 自建模型连得上

### 为什么先做这个

手机上问一句，之前要等她**整段想完**才出字——长答案像死机。桌面那边早就靠流式翻身了
（"能掐"的前提就是能一段一段回），手机还是整块返回。这是当前手机上最容易被感知到的一处。

### 三处一起动

| 层 | 加了什么 | 为什么必须在这一层 |
| --- | --- | --- |
| `XyNetPlugin.java` | `stream()` / `cancelStream()` + `xyNet` 事件；`Utf8Stream` 字节累加器 | 逐块读只有原生层能做；`new String(bytes, UTF_8)` 一把梭是**中文流式的头号坑** |
| `sse.ts`（新） | 纯函数累加器：`data:` 帧、跨块的半行、`[DONE]`、`tool_calls` 参数逐字拼、`reasoning_content` | 不碰插件，所以能在 Node 里判死 |
| `api.ts` / `agent.ts` / `MobileApp.vue` | 有回调才走流式；气泡逐段追加；`停止` 按钮 | 流式跨轮**继续往同一个气泡里加**，读起来才是一句连贯的话 |

两个设计上的硬决定：

1. **读循环自己起线程**。Capacitor 把插件方法排在同一条工作线程上，`stream()` 要是
   在那条线程上一路读到连接结束，"停止"这个调用就永远排在它后面——**按钮看着在，点了没反应**。
2. **流式时本地打字机完全不参与**。模型已经在吐字了，再套一层逐字动画只会让界面比网络更慢，
   还会把"她其实卡住了"演成"她在慢慢说"。

另外补了一条边界：按停止之后**只留文本，不执行手里那半截 `tool_calls`**——
参数是一个字符一帧流出来的，取消时完全可能是 `{"percent":4`，拿它去动手机就是乱来。

### 顺手补的一个真缺口：自建 / 内网模型连不上

写测试服务器的时候撞出来的：手机打模型那条路**只认正规 CA**，
于是公司内网网关、自己机器上的 Ollama / vLLM（自签证书）全都连不上，
报回来的还是一句没有信息量的证书错误。所以给模型配置加了一栏
**证书指纹**（`sha256:…`，留空就是走系统信任链）——和配对那栏同一个道理：
**指纹替代 CA，不是把校验关掉**，填错了就是连不上，不会退化成"谁都信"。

### 验到哪、没验到哪

**验过的**（都不依赖真 Key）：

- `scripts/test_sse_stream.mjs` 在 Node 里跑 `sse.ts`，**17 条**：逐字拼、`data:` 行被切成两半、
  `[DONE]` 前还有字、坏帧只丢那一帧、注释行忽略、思考链单独累加、
  `tool_calls` 名字和参数跨帧拼回、两个工具按 index 归位、端点不流式时整块兜底、空回答不崩。
  做过变异验证：把参数累加从 `+=` 改成 `=`，那条立刻红。
- `scripts/fake_model_server.py`（自签 HTTPS，复用电脑端那套 `ensure_certificate`）
  实测**确实**把一个汉字的三个字节切开：38 次 read 里 **9 次的块尾停在半个 UTF-8 序列上**，
  而整句拼回来一字不差。也就是说手机那一跑只要出现 ，就是 Java 解码器的锅，跑不掉。
