# 服务器部署手册（server-deployment）

> **这份文档回答一个问题：客户说"想放服务器上 / 手机要在外面也能连 / 干脆自建一个中转"，
> 你该怎么办。**
>
> 写这份文档的前提是**先说清楚一件事**，后面所有内容都建立在这上面：

---

## 0. 先认清：这不是一个服务端产品

**「小夜」是一个 Windows 桌面程序。** 它没有 web 控制台、没有账号体系、没有并发、
没有"多人同时登录同一个助手"这回事。托盘图标、全局热键、UAC 分档、宠物镂空窗口
全是 **Win32 直调**，所以它连 Linux 都跑不起来（见 C 篇）。

所以"部署到服务器"这句话，在客户嘴里和在你手里，往往是**四件完全不同的事**。
先把客户的话翻译成下面四种之一，再决定用哪篇：

| 客户原话 | 他真正想要的 | 走哪篇 | 是不是新开发 |
|---|---|---|---|
| "我想放云上，出差也能用" | 把"一台电脑"搬到云上，谁用谁远程桌面进去 | **A 篇** | 不是，纯部署 |
| "我想用手机在外面也能问她" | 手机当第二块屏，跨网可达 | **B 篇** | 局域网部分不是；跨网要配反代 |
| "你们这个能在 Linux 服务器上跑吗" | 想省一台 Windows 授权 / 想和别的服务放一起 | **C 篇** | ⚠️ **跑不了**，C 篇讲边界与替代方案 |
| "我不想让客户填 Key，你统一管" | 你持 Key，给客户发额度 | **D 篇** | ⚠️ **是新开发**，项目里没有这个功能 |

### 0.1 决策树（照着往下走）

```
客户要"部署到服务器"
│
├─ 他要的是"我自己用，换台机器"
│   └─ → A 篇：租 Windows 云主机，装打包版，远程桌面用
│
├─ 他要的是"手机能用"
│   ├─ 手机和电脑在同一个 Wi-Fi  → B 篇 §1（开「手机接入」即可，最简单）
│   └─ 手机在外面 / 用 4G/5G     → B 篇 §2~§4（要域名 + 反代 + 证书）
│
├─ 他坚持要 Linux
│   └─ → C 篇：先告诉他跑不了，再给三条替代路径（含"中转服务可以放 Linux"）
│
└─ 他要"不用自己管 Key"
    └─ → D 篇：自建 OpenAI 兼容中转。属于新开发，按加购项报价
```

### 0.3 这份文档的"验过 / 没验过"总表（先看这个，别看正文写得详细就以为都验过）

| 能力 | 状态 | 说明 |
|---|---|---|
| Windows 云主机上跑打包版 | 🟢 原理与本地部署一致 | 打包版在本机真机启动过（22 组件 / 窗口正常 / 0 ERROR） |
| `JARVIS_HOME` 重定向数据目录 | 🟢 真机实测 | 本机就在用 `E:\BianChengGongJu\JarvisData` |
| 远程桌面里跑 WebView2 界面 | ⚠️ **没验过** | RDP 会话的 GPU/沙箱与本地不同，可能要用 `--no-sandbox` 排障 |
| 开机自启（注册表 Run 键） | 🟢 代码与测试都有 | 但"云主机重启后自动起来"没在云主机上验过 |
| 手机接入网关（局域网） | 🟢 真机跑过 | 端点、配对、指纹核对、白名单都有自动化测试 |
| 手机**跨网**接入（反代 + 公网证书） | 🔴 **完全没做过** | 本项目设计上就假设"同一个 Wi-Fi"。跨网是新场景，见 B 篇 §2 的风险清单 |
| Linux 上跑本项目 | 🔴 **跑不了** | Win32 直调，见 C 篇 |
| 自建模型中转 | 🔴 **项目里没有这个功能** | D 篇给的是"你要自己搭"的方案，不是现成功能 |

**这张表的意思**：A 篇照做基本能用；B 篇的跨网、C 篇、D 篇
**第一次交付前，你必须自己按文档跑通一遍再给客户承诺**。

# A 篇 · 云端 Windows 主机跑桌面端

**目标**：把打包版装到一台云 Windows 主机上，你用远程桌面连上去用。
本质上不是"服务端化"，是**把一台电脑搬到云上**——所以仍然是单人使用。

**适用**：客户出差要远程用；展会/门店想固定一台机器常驻；本机太慢想换台好机器算力。

**不适用**：多人协作。问这个的一律引导到"每个人装一份，各自用各自的 Key"。

---

## A1. 选机器（这一步就决定后面顺不顺）

### A1.1 规格要求（来自实测，不是拍脑袋）

| 项 | 最低 | 建议 | 依据 |
|---|---|---|---|
| 系统 | Windows Server 2019+ / Windows 10/11 x64 | **Windows 11** | WebView2 在 Win11 自带；Server 版要自己装运行时 |
| CPU | 4 核 | 8 核以上 | 语音链路 + 3D 人物会吃满 |
| 内存 | 8 GB | **16 GB** | 语音加载后常驻 RSS 实测约 1.5–1.7 GB，加桌面宠物再多约 1.1 GB |
| 磁盘 | 40 GB | **100 GB SSD** | 程序 924 MB + 语音模型约 1.7 GB + 数据；还有首次下载权重的临时空间 |
| 显卡 | 无硬性要求 | — | 3D 人物走 WebGL，软渲染也能动，只是帧率低 |
| 网速 | 5 Mbps | 20 Mbps+ | 首次要下约 900 MB 模型权重 |

> **⚠️ Windows Server 的坑**：Server 版**默认没有 WebView2 运行时**，
> 也没装桌面体验。两个后果：① 界面起不来；② 没有声音设备，语音播报没声音。
> **能给 Windows 11 就别给 Server。** 如果客户坚持用 Server，先做 A5 的验证再付钱。

### A1.2 磁盘布局：**别把数据放 C 盘**

这是产品要求（不是可选项），本机就是这么做的。云主机上同样：

```
C:\                        系统盘（只放程序，或干脆也别放）
D:\XiaoYe\                 程序目录（解压出来的 小夜\ 文件夹）
E:\XiaoYeData\             数据根（数据库、日志、模型、审计）—— 如果只有一块盘，
                           就在同一块盘上分两个目录，关键是别用默认的 C 盘用户目录
```

## A2. 上机前的准备（在**你的**机器上做）

### A2.1 打出最新的包

**顺序不能反**：先构建前端，再 PyInstaller，中间不要碰 `jarvis/ui/web/`。

```powershell
# ① 进项目根目录（按你自己的路径改）
cd E:\DaiMa\AILiaoTianXiangMu

# ② 激活虚拟环境（项目约定用 .venv）
.\.venv\Scripts\Activate.ps1

# ③ 构建前端产物到 jarvis\ui\web\（需要 Node.js）
#    这一步会换掉 assets\ 下的文件名（带内容哈希），所以必须在下一条之前完成
python scripts\build_desktop.py

# ④ 打包。distpath / workpath 都指到非 C 盘，按轮次号建目录（r31、r32…）
#    注意：这会跑几分钟，且中途千万别再去跑 ③，否则产物会缺 assets\（见文末"坑"一节）
python -m PyInstaller packaging\jarvis.spec `
    --distpath  E:\BianChengGongJu\JarvisBuild\r31\dist `
    --workpath  E:\BianChengGongJu\JarvisBuild\r31\build

# ⑤ 【必做】核对界面资源真的进包了（这一步省掉会得到一个白屏的 exe）
dir E:\BianChengGongJu\JarvisBuild\r31\dist\小夜\_internal\jarvis\ui\web\assets\

# ⑥ 【必做】逐字节比对，确认打包产物和源码树一致
#    两个 index-<hash>.js / .css 的 MD5 必须和 jarvis\ui\web\assets\ 下的完全相同
Get-FileHash E:\BianChengGongJu\JarvisBuild\r31\dist\小夜\_internal\jarvis\ui\web\assets\*.js  -Algorithm MD5
Get-FileHash E:\DaiMa\AILiaoTianXiangMu\jarvis\ui\web\assets\*.js -Algorithm MD5

# ⑦ 在本地先启动一次，确认窗口能开（不对就别往云上搬）
E:\BianChengGongJu\JarvisBuild\r31\dist\小夜\小夜.exe
```

**⑤⑥ 为什么必须做**：PyInstaller 在**图解析阶段**就把 web 资源按**文件名**记进待收清单，
**真正拷贝在最后**。中途重跑一次 `build_desktop.py`（Vite 会换哈希文件名）的表现是
**打包正常完成、退出码 0**，只有两条 WARNING，然后产物里 `assets\` 整个不存在 → 窗口能起但白屏。
靠眼睛看不出来，只能靠上面两条核对。

### A2.2 打包交给客户的最省事做法

**把模型权重目录一起打给他**，他就不用下 900 MB：

```
E:\BianChengGongJu\JarvisData\models\      ← 整个目录一起压进 zip
```

### A2.3 压缩并算好校验值

```powershell
# 压缩。用 Compress-Archive（系统自带），或用 7-Zip 更快
Compress-Archive -Path E:\BianChengGongJu\JarvisBuild\r31\dist\小夜 `
                 -DestinationPath E:\交付包\小夜-r31.zip `
                 -CompressionLevel Optimal

# 算 MD5，写进交付单。客户传完文件要用它核对
Get-FileHash E:\交付包\小夜-r31.zip -Algorithm MD5 | Format-List
```

> **为什么一定要给 MD5**：几个 GB 的文件过微信/网盘，损坏是常事。
> 客户拿到一个"解压报错"的包，第一反应是"你软件有问题"，而不是"传输坏了"。
> 给一个校验值，这一轮扯皮就省掉了。

## A3. 云主机上开搞（客户机 / 你远程进去做）

以下命令在**云主机的 PowerShell（管理员）** 里跑。

### A3.1 解压 + 摆好位置

```powershell
# ① 建目录（D 盘放程序，E 盘放数据；只有一块盘就都在 D 盘，别用 C 盘用户目录）
New-Item -ItemType Directory -Force -Path D:\XiaoYe     | Out-Null
New-Item -ItemType Directory -Force -Path E:\XiaoYeData | Out-Null

# ② 解压交付包
#    -Force 覆盖；路径按实际改
Expand-Archive -Path D:\下载\小夜-r31.zip -DestinationPath D:\XiaoYe -Force

# ③ 核对解压结果：应该看到 小夜.exe 和 _internal\ 两样
Get-ChildItem D:\XiaoYe\小夜 | Select-Object Name, Length | Format-Table

# ④ 【必做】核对界面资源在（不在的话下面所有步骤都是白做，会白屏）
Test-Path D:\XiaoYe\小夜\_internal\jarvis\ui\web\index.html      # 期望 True
Get-ChildItem D:\XiaoYe\小夜\_internal\jarvis\ui\web\assets\      # 期望有 index-<hash>.js / .css
```

### A3.2 设数据目录（**在启动之前设**）

```powershell
# 用户级环境变量（HKCU\Environment）。用 User 而不是 Machine：
# 这台机器可能只给这个账号用，改 User 不影响系统其他用户，也不需要管理员权限做第二次确认
[Environment]::SetEnvironmentVariable("JARVIS_HOME", "E:\XiaoYeData", "User")

# 模型与工具缓存也跟着走，否则它们默认全落在 C 盘用户目录下：
#   %USERPROFILE%\.cache\huggingface   HF 权重
#   %USERPROFILE%\.cache\torch         Silero VAD
#   %LOCALAPPDATA%\pip\cache           pip 缓存
#   %USERPROFILE%\AppData\...\ms-playwright  Playwright 浏览器
# 项目里有个脚本一次设全，直接用它更省事：
#   powershell -ExecutionPolicy Bypass -File scripts\setup_env_paths.ps1 -Apply -Root E:\XiaoYeData

[Environment]::SetEnvironmentVariable("MODELSCOPE_CACHE",        "E:\XiaoYeData\models\modelscope",   "User")
[Environment]::SetEnvironmentVariable("HF_HOME",                 "E:\XiaoYeData\models\huggingface", "User")
[Environment]::SetEnvironmentVariable("TORCH_HOME",              "E:\XiaoYeData\models\torch",       "User")
[Environment]::SetEnvironmentVariable("PIP_CACHE_DIR",           "E:\XiaoYeData\cache\pip",          "User")
[Environment]::SetEnvironmentVariable("PLAYWRIGHT_BROWSERS_PATH","E:\XiaoYeData\cache\playwright",   "User")

# 【关键】上面写的是注册表，当前这个已开的窗口里 $env: 还没变。
# 必须开一个【新的】PowerShell 窗口，或者执行下面的广播让已开的进程刷新。
# 最稳的就是：关掉所有命令行窗口，重新开一个，然后验证：

# 新窗口里验证（应该打印出你设的路径，而不是 C 盘）
echo $env:JARVIS_HOME      # 期望：E:\XiaoYeData
echo $env:HF_HOME          # 期望：E:\XiaoYeData\models\huggingface
```

> **为什么反复强调"新开窗口"**：环境变量写进注册表后，**已经运行的进程不会自动看到**。
> 直接在当前窗口启动程序，它会读到旧的（空的）值 → 数据落在 C 盘 → 客户下次说
> "怎么还是占了系统盘"。这类问题排查起来非常费时间，不如一开始就新开窗口。

### A3.3 首次启动（先别急着配自启）

```powershell
# 前台启动，看它有没有正常报错。--voice 表示允许界面上的「启用语音」开麦克风
# 云主机没有麦克风时，不给 --voice，纯打字问答也能演
Start-Process -FilePath "D:\XiaoYe\小夜\小夜.exe" -PassThru | Select-Object Id, ProcessName
```

等 10 秒左右，然后**看日志**（别只看窗口，窗口白屏时日志可能是干净的）：

```powershell
# 看有没有 ERROR。正常启动应该有"22 个组件就绪"这类信息
Select-String -Path E:\XiaoYeData\logs\jarvis.log -Pattern "ERROR" | Select-Object -Last 20

# 看最后 30 行，确认启动流程走完了
Get-Content E:\XiaoYeData\logs\jarvis.log -Tail 30
```

## A4. 远程桌面（RDP）下使用：**这一步最容易翻车**

### A4.1 先做验证，再谈交付

```powershell
# 从你自己的电脑用远程桌面连上去后，在云主机里启动程序
D:\XiaoYe\小夜\小夜.exe

# 然后【截图看一眼】—— 只看日志和进程数不算验证过 GUI
```

**为什么必须截图**：这个项目踩过**整片黑屏而日志全绿**的坑 ——
pywebview 报告窗口成功、`webview.start()` 正常阻塞、0 个 ERROR，
唯一的错误在 WebView2 自己的控制台里。

### A4.2 如果界面是黑的：按这个顺序排

**① 先看程序自己打的排查提示**：程序会在 25 秒后把排查步骤打在控制台里。
看窗口留的那个控制台，或在日志里搜"没有加载完成"。

**② 给 WebView2 加 `--no-sandbox`（临时排障）**：

```powershell
# 【只用于排障】RDP / 受限环境里 Chromium 沙箱有时拿不到进程权限，渲染进程起不来
# 表现：窗口正常、内容全黑、日志无一字
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = "--no-sandbox"
D:\XiaoYe\小夜\小夜.exe
```

> **⚠️ 这不是正式配置。** 它会摘掉渲染进程的沙箱保护。
> 排障确认能用之后，要改用第 ③ 条的正路，**不要**把它写进系统环境变量常驻。

**③ RDP 的 GPU 与显示问题**：RDP 会话默认可能不带硬件加速；断开 RDP 后会话进入
"无显示器"状态，WebView2 可能无法渲染。几个处理方向：

- 用 `/admin` 模式连（`mstsc /admin`）有时能绕开部分会话隔离；
- 客户机侧用 **"将我的所有监视器用于远程会话"** 或调整显示缩放为 100%；
- 如果是"断开 RDP 后程序还在跑但要能出图"，考虑改成**常驻但不依赖渲染**的用法
  （即：远程连上去时才用界面；不用时让程序收进托盘）。

**④ 确认 WebView2 运行时在不在**：

```powershell
# 查已安装的 WebView2 运行时（有输出就是装了）
Get-ItemProperty "HKLM:\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}" `
    -ErrorAction SilentlyContinue | Select-Object pv

# 没有的话，去微软官网下 "Evergreen Standalone Installer"（约 150 MB）装上
```

### A4.3 断开 RDP 后程序会被挂起吗？

会。**RDP 断开后会话会进入"断开"状态**，某些资源（显示、部分音频）会被回收。
如果客户要的是"我断开之后它还继续跑、继续接手机"，那要么：

- 用**自动登录 + 计划任务在开机时启动**（见 A5），并把会话保持登录状态，
  或用 `tscon` / 保持一个不注销的会话；
- 要么接受"不连 RDP 时它只在后台，界面相关功能受限"。

**这一条没有现成的一键方案，属于强运维。** 客户如果是这个需求，
按 `01-报价与方案.md` 的加购项单独报价，别按 A 篇的 +¥800 糊过去。

## A5. 开机自启（注册表 Run 键）

**原理**：程序自己会写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的
`XiaoYeDesktop` 一项。**为什么用注册表而不是计划任务**：注册表是"登录时到底跑不跑"
的唯一真相，而且用户能自己在 `regedit` 里看见、删掉；计划任务更强但藏得更深，
出问题时清理起来像在做运维事故。

```powershell
# 方式一：在程序界面里开（推荐）。托盘菜单里有「开机自启」，勾上即可。
#         它写的就是下面这个位置。

# 方式二：手工确认/排查
Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" |
    Select-Object XiaoYeDesktop

# 手工删除（客户说"别开机自己起来"时用）
Remove-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" `
    -Name "XiaoYeDesktop" -ErrorAction SilentlyContinue
```

> **⚠️ 云主机上自启的真正难点不是注册表，是"谁来登录"**：
> 注册表 Run 键是**用户登录时**才触发。云主机重启后如果停在登录界面没人登录，
> 程序永远不会起来。要"重启后无人值守自动跑"，你需要的是：
> 自动登录（`netplwiz` 或注册表 `AutoAdminLogon`）+ 一个登录后的会话。
> **这件事涉及把账号口令写进注册表，安全上要客户自己拍板。**
> 本机没验过这条路，别照抄。

### A5.1 验证自启真的生效

```powershell
# 重启
Restart-Computer -Force

# 等云主机起来、登录后（几秒钟），再连 RDP 检查进程在不在
Get-Process 小夜 -ErrorAction SilentlyContinue | Select-Object Id, StartTime
# 期望：有输出，StartTime 接近重启时间
```

## A6. 数据备份与迁移（云主机尤其要做）

客户付了钱，数据丢了就是事故。要备份的东西**只有两个位置**：

| 位置 | 内容 | 备份频率建议 |
|---|---|---|
| `E:\XiaoYeData\` | 数据库、对话历史、记忆、知识库索引、配置、**偏好**、日志、审计 | 每天 |
| `E:\XiaoYeData\config\config.yaml` | 服务商/模型配置（含变量名，不含 Key） | 改了就跟 |
| `E:\XiaoYeData\mobile\` | 手机接入的自签证书 + 已配对设备清单（**含一个私钥**） | 做了手机接入就要备；不备的话重装后所有手机要重新配对 |
| `E:\XiaoYeData\voices\` | 自己录的克隆音色（是"用户做出来的东西"，不是能重新下载的权重） | 录过音色就要备 |

> **`mobile\` 和 `voices\` 这两个要单独点出来**：它们不是"能从网上下回来的东西"
> —— 证书删了要重新配对，音色删了没法恢复（是操作者自己录的）。
> 很多人备份时只看数据库，把这两个漏掉，恢复时才发现还得让所有手机重配一遍。

**API Key 不在备份里**，它在 `HKCU\Environment`（用户级环境变量）。换机器要重新填。
这是设计如此，也是文档要跟客户讲清的一点（"你的 Key 不会被我们的备份带走"）。

## A8. A 篇常见问题

**Q：双击 exe 没反应，任务管理器里有进程但没窗口。**
看日志 `E:\XiaoYeData\logs\jarvis.log`。如果日志里窗口事件只到 `before_load`
就没下文了 → 渲染进程死了 → 走 A4.2。

**Q：界面能开，但一片空白（不是黑，是白）。**
几乎必然是 `assets\` 没进包 —— 走 A3.1 的 ④ 核对。这是打包顺序反了导致的，
见 A2.1 的最后一段。

**Q：数据还是落在 C 盘了。**
99% 是"设了环境变量但没新开窗口"。新版窗口里 `echo $env:JARVIS_HOME` 确认一次。

**Q：语音点了「启用语音」一直不动。**
云主机通常**没有麦克风**。这是正常的 —— 不给 `--voice` 参数时，界面不会开麦，
打字问答照常可用。要在云主机上演示语音，得配虚拟音频设备，本项目没验过。

**Q：能不能多个人同时用这一个助手？**
不能。没有账号体系、没有并发。每个人装一份，各自用自己的 Key。

# B 篇 · 手机接入网关（同网 / 跨网）

**目标**：让手机成为这台电脑的第二块屏 —— 在外卖路上问一句、拍张图问一句、
开会时用手机看电脑上的状态。

**先把设计意图说清楚**（这决定了哪些事"做不到"是故意的）：

> **手机是"同一个大脑的第二张脸"，不是第二套能力。**
> 手机发的每一个请求都映射到一个**已经存在**的电脑端方法（白名单 28 个），
> 不新增能力面。手机拿不到的东西是**故意**给的少：
> 删除类（`disk_delete` / `process_kill` / `chat_delete` / `memory_forget_all`）、
> 开麦克风（`voice_enable`）、改设置、升权限档 —— 一个都不在名单里。
> 一句话：**手机是一块离开家的屏幕。** 能看状态、能对话、能建提醒；
> 删东西、开别人的麦、改权限，留在那台有人站在跟前的电脑上。

## B1. 同一 Wi-Fi 内接入（最简单，纯配置，已验证）

### B1.1 三步搞定

**第 1 步 · 在电脑上打开网关**

托盘图标右键 →「手机接入」。或走配置（见 B1.2）。
打开后电脑屏幕上会出现：**地址（`192.168.x.x`）+ 端口（默认 8737）+ 证书指纹 + 6 位配对码**。

**第 2 步 · 在手机上填这四样**

手机 App → 填地址、端口、**证书指纹**、6 位配对码。
指纹要**肉眼核对**（电脑屏幕上那串 `sha256:...` 和手机上要一致）。

**第 3 步 · 配对**

配对成功后手机拿到 token，此后不再需要配对码。

### B1.2 配置怎么改（`config.yaml`）

```yaml
mobile:
  enabled: false          # 【默认关】开了就等于在 Wi-Fi 上开了一个端口
  bind_host: 0.0.0.0      # 0.0.0.0 = 所有网卡（手机在同网才连得上）；
                          # 只想本机测试就写 127.0.0.1
  port: 8737              # 固定端口，这样配对界面打印的数字一直是真的
  pair_minutes: 5         # 配对码有效期。够从手机输入，又不至于让屏幕上的码一直敞着
  max_pair_attempts: 6    # 输错几次就作废当前码 —— 这才是锁，不是那 6 位数的数学
  max_devices: 8          # 配对设备上限，满了要先撤一个
```

**为什么默认是关的**：开了它，同一 Wi-Fi 上的**任何机器**都能尝试连这个端口。
所以它是托盘上的一个显式开关，而不是"装好就开着"。

### B1.3 为什么用自签证书 + 指纹，而不是普通 HTTP

**因为这个助手能移动鼠标、能跑命令行、能读磁盘。** 在家庭 Wi-Fi 上用明文 HTTP
传输指令，等于把每条指令摊在同一个网络上；隔壁的笔记本可以冒充服务器来应答你的手机。

**为什么不用正规 CA 证书**：地址是私有的 `192.168.x.x`，**没有 CA 会给它签**；
而且产品的立场是"这些流量不给任何第三方服务看"。所以电脑**自己生成一次证书**，
**手机钉住它的 SHA-256 指纹** —— 操作者从电脑屏幕上读指纹，跟读配对码一样。
**钉指纹取代了 CA，不是削弱了传输。**

**明文是被拒绝的，不是被降级的。** 这个模块里**没有** `--insecure` 之类的开关：
一个"证书烦人时就自动放行"的兜底，正是这个模块存在的意义要堵上的洞。

### B1.4 两个证书相关的常数（会咬人的那种）

| 常数 | 值 | 为什么是这个数 |
|---|---|---|
| 证书有效期 | **824 天** | 不是个整数 —— **Android 拒绝有效期超过 825 天的网络证书**。弄成 3 年会"配对成功、之后只在手机上失败"，而电脑那边给不出任何解释 |
| 提前续期阈值 | **60 天** | 剩余不足 60 天就重新生成。**静默过期**是"已配对手机突然握手失败、谁也复现不出来"的根源 |

**运维含义**：证书会自己续，但**续了之后指纹会变，手机要重新配对**。
客户如果抱怨"用一阵子突然连不上"，先看证书是不是到 824 天了。

### B1.5 安全边界（客户 IT 一定会问）

```powershell
# ① 网关只在打开时监听。想确认端口状态（应能看到 8737 的 LISTEN，关掉后消失）
Get-NetTCPConnection -LocalPort 8737 -State Listen -ErrorAction SilentlyContinue

# ② 已配对设备清单 + 自签证书，都在 $env:JARVIS_HOME\mobile\ 这一个目录里
#    （存的是 token 的 SHA-256 摘要，不是 token 本身）
Get-ChildItem   "$env:JARVIS_HOME\mobile"
Get-Content     "$env:JARVIS_HOME\mobile\devices.json" -Encoding UTF8 | ConvertFrom-Json

# ③ 撤销一台设备：手机 App 里撤，或编辑 devices.json 后重启程序
```

> **`mobile\` 为什么是独立目录而不是丢在数据根里**：它**装着一个私钥**（TLS 证书的），
> 所以必须是一个用户能够看着、指认、并且能整个删掉的地方 ——
> 而不是混在缓存或配置里让人不敢动。删掉这个目录 = 所有手机要重新配对一次。
> **换机器 / 重装时它要一起备份**，否则又是一轮"重新配对 + 重读指纹"。

**几个设计上的硬决定**（这些是"为什么安全"，客户问起照这个答）：

- **配对码只在内存里**，落盘的是 **token 的 SHA-256 摘要**，不是 token。
  理由很具体：这个目录在数据根下面，而随程序一起发的磁盘清理工具**会枚举并建议删掉**
  这个目录里的文件 —— 一个"装着活凭据的文件"不该出现在人们会清理的目录里。
  摘要被读到也**无法重放**：它认证的 token 只在下发的那一次出现过。
- **码和 token 都不进日志。** 日志只写"配对成功"和设备名。
- **6 位码有次数上限**：一百万种组合在局域网里几秒就能暴力完 ——
  **真正的锁是那个计数器，不是位数**：错几次当前码就烧掉，攻击者必须回到电脑前重新要一个。
- **设备名会被清洗**：来自不可信的手机，只留字母数字、中文和三个符号，最长 40 字符
  （一个 4 MB 的"名字"不是名字）。
- **未配对的请求得到 401 而不是 404**：隔壁在 Wi-Fi 上扫路由名的人，
  不该靠状态码的变化就摸清哪些路径存在。

### B1.6 白名单：手机到底能调什么

**28 个方法**，分四类（`jarvis/ui/lan_server.py` 的 `ALLOWED_METHODS` 是唯一真相）：

| 类别 | 方法 | 说明 |
|---|---|---|
| 只读状态 | `app_info` `state_snapshot` `voice_status` `snapshot` `activity_log` `computer_levels` `shell_levels` | 看电脑现在什么样 |
| 对话 | `chat_models` `chat_sessions` `chat_messages` `chat_ask` `chat_new_session` `chat_switch` `chat_rename` | 看/切会话、问一句 |
| 提醒与记忆 | `reminders` `reminder_add` `memory_list` `knowledge_state` | 能建提醒、能看记忆与知识库状态 |
| 语音 | `tts_voices` `tts_pick` `tts_preview_pcm` `call_readiness` `call_warmup` `call_turn` `call_speak` `voice_clone_list` `voice_clone_add` `voice_clone_remove` | 手机上的朗读与通话；录一个自己的音色 |

**故意不在名单里的**（问起来就这么答）：

| 不在名单 | 为什么 |
|---|---|
| `chat_delete` | **手机上不给删电脑会话的入口**。这是刻意的 |
| `disk_delete` / `process_kill` / `memory_forget_all` | 删除类。结束一个操作者已经习惯了的东西，留在家里 |
| `voice_enable` | 那是**开电脑的麦克风**。手机想说话，不该去开另一台机器的麦 |
| `settings_apply` / `computer_set_tier` | 改设置、升权限档，留在电脑上 |

**`tts_preview_pcm` 而不是 `tts_preview`**：后者从**电脑的扬声器**放音，
手机那边的人根本听不见。这个把采样交回给手机，让手机自己播。

### B1.7 端点一览（写反代 / 抓包时用）

| 方法 | 路径 | 要不要鉴权 | 说明 |
|---|---|---|---|
| GET | `/hello` | 否 | **未鉴权的广告**：够你认出是哪台机器，仅此而已 |
| GET | `/methods` | 是 | 列出白名单里的方法名 |
| GET | `/state` | 是 | 当前状态 |
| POST | `/pair` | 否 | **唯一未鉴权的入网口**：拿 6 位码换 token |
| POST | `/rpc/<方法名>` | 是 | 一次白名单调用 |

**鉴权头**：`Authorization: Bearer <token>`。
**请求体上限**：`2 MiB`（`MAX_BODY_BYTES`）。这个数是按真实约束算的：
一次拍照问答是 4 张 × 40 万字符 base64 ≈ 1.6 MB，卡低了会出现
"电脑端收得下同样一张图、手机端却被 413" —— 那读起来像"手机版坏了"，在手机屏幕上很难诊断。

## B2. 跨网接入：**这是新场景，先读完风险清单再动手**

> **⚠️ 重要前提：项目在设计上就假设"手机和电脑在同一个 Wi-Fi"。**
> 跨网（手机在外面用 4G/5G 连家里的电脑）**从来没做过、没验过**。
> 下面给的是**可行路径 + 你必须自己先跑通的风险点**，不是"照做就行"的现成方案。

### B2.1 为什么不能"简单地把端口映射出去"

网关的**整套安全模型建立在"局域网"这个假设上**：

1. **6 位配对码**：在局域网里，攻击者要猜码得先能连上；开到公网后，
   **一百万种组合从互联网上暴力**，速度比局域网快得多。虽然 `max_pair_attempts=6`
   仍然是硬锁（错 6 次作废当前码，且必须有操作者在电脑前重新生成），
   但**扫描/骚扰的流量**会真的打到你家宽带上。
2. **自签证书 + 指纹钉扎**：指纹是**手输**的。跨网时你没法把域名和指纹绑起来，
   中间人只要能让手机第一次连到他那，指纹核对时用户很容易"看着差不多就点了通过"。
3. **没有速率限制**：这个模块是给"自己家里一台手机"设计的，
   没有请求限流、没有 IP 封禁。公网暴露 = 需要额外一套防护。

**所以跨网的正确做法不是端口映射，是"手机永远只连一个你自己的、有正规证书的入口"。**

### B2.2 推荐架构（一条可信链路，手机只认一个域名）

```
[手机] --TLS(正规证书, 域名)--> [你的反向代理] --私网/TLS--> [家里那台电脑:8737]
        只认这个域名                 (nginx / Caddy)             自签证书 + 指纹
        Android 默认信任它           做鉴权、限流、日志          只对反代暴露
```

**关键点**：

- **手机侧看到的是你的正规证书**（域名 + Let's Encrypt 之类），
  这样 Android 默认信任，**不需要手输指纹**，也就没有了"指纹差不多就通过"的洞。
- **反代到电脑那一段仍然走自签 + 指纹钉扎**（或走一条私网隧道）。
  这一段不过公网，指纹是反代**预置**的，不是人眼看。
- **反代做三件事**：限制来源、限流、把访问写进日志。

### B2.3 nginx 参考配置（**未验证，需你自己跑通**）

> 下面这份是**思路参考**，不是实测配置。第一次做请在一个临时域名上先跑通，
> 再上客户环境。**特别注意 `/pair` 这个未鉴权端点**：它是最该被限流的。

```nginx
# /etc/nginx/conf.d/xiaoye.conf
# 作用：把 https://xy.example.com 转给家里那台电脑的 8737 端口
# 前提：这条反代和电脑之间有一条可达的私网链路（VPN / 隧道 / 同内网）

# 限流区：以 IP 为单位，每秒 5 个请求，突发 10 个。
# 为什么必须有：网关自己没有限流，公网上会是暴力枚举的靶子
limit_req_zone $binary_remote_addr zone=xiaoye_rl:10m rate=5r/s;

# 配对端点单独一个更严的区：每分钟 10 次。
# 为什么单独限：/pair 是唯一未鉴权的写入口，且它接受"猜一个 6 位数码"
limit_req_zone $binary_remote_addr zone=xiaoye_pair:10m rate=10r/m;

server {
    listen 443 ssl http2;
    server_name xy.example.com;          # ← 改成你的域名

    # 正规证书（手机默认信任，不用手输指纹）
    ssl_certificate     /etc/letsencrypt/live/xy.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/xy.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    # 别把请求体限制卡在 1 MB —— 手机拍照问答的正文可到约 1.6 MB。
    # 卡低了会在"拍照问一句"时返回 413，而普通文字问答完全正常，很难查
    client_max_body_size 4m;

    # 配对端点：最严的限流，且禁用缓存
    location = /pair {
        limit_req zone=xiaoye_pair burst=3 nodelay;
        proxy_pass https://10.0.0.5:8737;     # ← 改成电脑的内网地址
        proxy_ssl_verify off;                 # 电脑是自签证书；这一段靠私网保证
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 其余端点：常规限流
    location / {
        limit_req zone=xiaoye_rl burst=10 nodelay;
        proxy_pass https://10.0.0.5:8737;     # ← 同上
        proxy_ssl_verify off;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

        # RPC 可能等模型回答，超时要给够。
        # 给短了的表现是"手机上一句问出去转圈然后失败"，而电脑上明明答了
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;

        # 别让中间层缓存任何东西（返回里有会话内容）
        proxy_buffering off;
        add_header Cache-Control "no-store" always;
    }
}
```

**必须验证的四件事**（缺一件就不算跑通）：

```bash
# ① Android 默认就信任这条链路（没手输指纹也能连）
#    验证：手机浏览器打开 https://xy.example.com/hello ，应看到那台机器的广告信息，
#    且【没有】证书警告

# ② /pair 的限流真的生效
for i in $(seq 1 20); do
  curl -sk -o /dev/null -w "%{http_code}\n" \
    -X POST https://xy.example.com/pair \
    -H 'Content-Type: application/json' \
    -d '{"code":"000000","device":"probe"}'
done
# 期望：前几个 403（码错），后面开始出现 503（被限流）。
# 全是 403 = 限流没生效，不要上生产

# ③ 拍照问答不撞 413（这是最容易被忽略、又最容易踩的）
#    在手机上发一张真实照片问一句，确认能答。
#    只测文字问答【不够】—— 文字很小，撞不到 client_max_body_size

# ④ 手机问一句最长的那类问题不会超时
#    选一个需要模型思考比较久的问题，确认 proxy_read_timeout 够
```

### B2.4 跨网的其他选择（按"省事程度"排序）

| 方案 | 优点 | 缺点 / 风险 |
|---|---|---|
| **反向代理 + 正规证书**（B2.2） | 手机免手输指纹；可控、可观测 | 要域名、要一台常开的主机、要自己维护 nginx 与证书续期 |
| 隧道服务（Tailscale / ZeroTier / WireGuard 之类） | 不用域名、不用开端口；点对点 | 引入了第三方（ZeroTier 走他们的服务器做协调）；手机要装客户端；**这款产品的立场是"流量不给第三方看"，用第三方隧道要跟客户讲清楚** |
| Cloudflare Tunnel / frp 之类 | 上手快、有现成证书 | 流量经过第三方；免费版有限制；同样有"谁看得到"的问题 |
| **直接端口映射（UPnP / 路由器端口转发）** | 最"简单" | ⚠️ **不推荐**。B2.1 的三条风险一条都没解决：无限流的未鉴权口、自签证书、暴力枚举全暴露在公网 |

**给客户的话术**：
> "手机在外面连，技术上能做，但它不是把端口一开了事。
> 你们需要有域名和一台常开的主机做入口，证书我们来配。
> 这部分是加购项，而且**我们会在你们的域名上先跑通一次**才交付。"

## B5. B 篇常见问题

**Q：手机连不上，一直转圈。**
按顺序查：① 电脑上「手机接入」是不是开着；② 手机和电脑**是不是同一个 Wi-Fi**
（手机可能连了 5G 热点）；③ 电脑防火墙有没有挡 8737；
④ `Get-NetTCPConnection -LocalPort 8737 -State Listen` 看端口在不在。

**Q：配对码输对了但配对失败。**
大概率是**输错了次数用完了**（`max_pair_attempts=6`）。让电脑上重新生成一个码。

**Q：指纹核对总是不一致。**
证书可能刚续期过（满 824 天或剩不足 60 天）。在电脑上重新读一次指纹。

**Q：手机上语音按钮点了说"这台设备没有系统语音识别引擎"。**
手机没装语音引擎。**这是诚实报错，不是转圈骗人**。APK 里不带模型，
用的是系统的 `SpeechRecognizer` / `TextToSpeech`。

**Q：手机拍的图，电脑那边说模型看不见。**
模型得是**能看图的**那一类（如 `qwen-vl-plus`）。填纯文本模型时，
屏幕上留的是模型回的那句错，**不会假装她看见了**。

# C 篇 · Linux 服务器部署：**先说不行，再说能做什么**

## C1. 结论（一句话）

**「小夜」桌面端在 Linux 上跑不起来**，这不是"没装依赖"级别的障碍，是代码结构决定的。
`pyproject.toml` 里就写着 `Environment :: Win32 (MS Windows)`，这是**声明**，不是建议。

**但**：项目里有几个**不需要界面**的功能，理论上有机会在 Linux 上跑
（D 篇的模型中转更是完全应该放 Linux）。C 篇就是把这条线画清楚。

---

## C2. 为什么跑不起来（技术上到底卡在哪）

### C2.1 界面栈依赖 Windows

| 组件 | 依赖什么 | Linux 上的后果 |
|---|---|---|
| 桌面窗口 | `pywebview` → Windows 上走 **WebView2** | Linux 要换 GTK/Qt 后端，但那套**本项目没写过、没测过** |
| 托盘图标 | `pystray` → **Win32 通知区域** | Linux 要 X11/AppIndicator，行为与菜单都不同 |
| **全局热键** | `ctypes` 直调 `user32.RegisterHotKey` | **Linux 无此 API**。整个模块是 Win32 直调 |
| **桌面宠物** | `ctypes` 直调 `user32.SetWindowLongW` / `GetCursorPos` / `GetForegroundWindow`，`WS_EX_TOPMOST` | 镂空、置顶、跟随鼠标全是 Win32 语义 |
| UAC / 权限分档 | Windows 的权限模型 | 没有对应物 |
| 开机自启 | `winreg` 写 `HKCU\...\Run` | Windows 注册表，Linux 无 |

**不是"缺个依赖包"，是"这些功能的存在形式就是 Win32"。**
把它们移植到 Linux 等于重写一个 L5 层，那是**新项目级别**的工作量。

### C2.2 有兜底，但只是"不崩"，不是"能用"

代码里确实有几处 `sys.platform` / `os.name` 判断，作用是**在非 Windows 上优雅降级**
（比如 `jarvis/tools/disk_cleaner.py` 在非 Windows 上把 `LOCALAPPDATA` 当 `None`、
`jarvis/ui/hotkeys.py` 拿不到 user32 就不注册热键），
**目的是让人看懂"为什么这个功能没反应"，不是让功能在 Linux 上工作。**

> **别把"有兜底"理解成"支持 Linux"。** 这两件事差得很远。

---

## C3. 那么 Linux 服务器到底能干什么

### C3.1 能做的：**模型中转服务**（强烈推荐，且本来就该放 Linux）

D 篇描述的那个"你持 Key、给客户发额度"的中转服务，**是一个独立的 HTTP 服务**，
跟本项目没关系，当然放 Linux。**事实上它就该放 Linux** —— 便宜、稳、好运维。

→ 直接跳到 **D 篇**。

### C3.2 可能能做的：无界面的 CLI 模式（⚠️ 未验证）

项目有几个**不打开窗口**的模式。它们**不 import 桌面栈**
（`jarvis/__main__.py` 里 `jarvis.ui` 是**懒导入**，只有 `--desktop` 才用到），
所以理论上能在 Linux 上跑：

```bash
# 这几个模式在源码里不 import 桌面栈（jarvis/__main__.py 里 jarvis.ui 是懒导入，
# 只有 --desktop 才用到），所以理论上能在 Linux 上跑。
# 下面的开关来自 `python -m jarvis --help` 的真实输出（2026-10-03 在本机核对过）：

python -m jarvis --version              # 版本号，退出。用来确认"装上了且能起来"
python -m jarvis --tools                # 列出注册的工具 + 风险等级 + 当前安全策略
python -m jarvis --prompts              # 列出所有提示词模板 + 版本 + 变量
python -m jarvis --memory               # 显示记住了什么
python -m jarvis --memory --forget      # 清空记忆（会先问一次；--forget 必须配 --memory）
python -m jarvis --ingest <路径>         # 知识库入库（文件或目录）
python -m jarvis --ingest <路径> --force # 内容没变也重新嵌入
python -m jarvis --ask "你的问题"        # 问一句（需要 API Key）
python -m jarvis --ask "..." --thinking 4096   # 顺带打印它的推理，上限 4096 token
python -m jarvis --plan "目标"           # 让规划器拆一个计划（⚠️ 只出计划、不执行）
```

> **`--plan` 那一条要特别注意**：项目的 `planner` **只出计划，没有接执行**。
> 执行属于编排层，还没接。给客户演示时别说成"它能自己把事做完"。

> **⚠️ 这一条是"未验证"**：本项目**没有在 Linux 上跑过任何一个模式**，
> 也没有 Linux 上的 CI。上面是**读源码得出的判断**，不是实测结论。
> **要当真，你必须自己在一台 Linux 上跑一遍**，并把踩到的坑补进这份文档。

如果客户确实需要一个 Linux 上的"无界面问答/入库"服务，这一路值得试。
但要注意：

- **Windows 专属的工具会不可用**：磁盘清理（`LOCALAPPDATA` 语义）、
  进程表（`jarvis/tools/proctable.py` 在非 win32 直接返回空）、
  应用启动器（`winreg` + `EnumWindows`）。
  它们多数会**返回可读的错误而非崩溃**（这是项目的失败口径），但功能就是没有。
- **语音全链路不保证**：`sounddevice` / PortAudio 在 Linux 上能装，
  但**没有测过**；`funasr` / `onnxruntime` 在 Linux 上通常更顺，
  但同样**没有测过**。
- **`langgraph` 是基础依赖**，纯 Python，Linux 上没问题。

### C3.3 不能做的：**把桌面端"搬"到 Linux**

见 C2。这条路要重写 L5，**不要接这种单**，除非按"新开发"重新报价（那是另一个量级）。

# D 篇 · 自建模型中转服务（客户不用自己管 Key）

## D1. 这是什么，为什么会有这一篇

来自 `docs/分发与分享.md` §4 里那条红线：

> **你不能把你的 Key 打进包里给客户用** —— 那等于把你的账单挂在你自己头上。
> 想让客户零配置试用？唯一正路是做一个**你自己的中转服务**并给他额度。

D 篇就是这个"中转服务"。

> **⚠️ 先把最重要的一句话放前面：项目里没有这个功能。**
> 「小夜」是一个**客户端**，它只会说"OpenAI 兼容协议"。
> 中转服务是**你自己要写、要部署、要运维的另一套东西**。
> 这一篇给的是方案与骨架，**不是现成产品**，也不是"改个配置就行"。

---

## D2. 为什么客户端可以直接用（协议这一层是通的）

好消息：**客户端这一侧不用改代码**。因为「小夜」的服务商是**纯数据**配置 ——
只要对方说 OpenAI 兼容协议，填个 `base_url` + 变量名就能接：

```yaml
llm:
  default_provider: relay           # 默认走你的中转
  providers:
    relay:
      base_url: https://ai.yourdomain.com/v1   # ← 你的中转服务，注意 /v1
      models:
        - gpt-4o-mini-relay          # 你在中转里定义的名字
        - gpt-4o-relay
      default_model: gpt-4o-mini-relay
      api_key_env: RELAY_API_KEY      # 客户机器上设这个变量 = 你发给他的额度 key
      cost_input_per_1m: 0.0
      cost_output_per_1m: 0.0
```

客户拿到一个 key，填进客户端界面 → 从此不用管上游是哪家模型。

客户端也支持**一把钥匙都不发**的连接方式：服务商行上勾「这个端点不需要 API Key」，
请求里就不带 `Authorization` 头 —— 本机 Ollama / LM Studio / llama.cpp 走的正是这一条。
**你自己的中转不许照这个来**：需求 3 的鉴权是这套方案唯一的安全边界，
去掉它 = 谁扫到端口都能刷你的额度。

**所以 D 篇的工程量全在服务端。**

---

## D3. 服务端要做什么（需求清单，照这个报价）

| # | 需求 | 为什么必须有 |
|---|---|---|
| 1 | **OpenAI 兼容的两个端点**：`POST /v1/chat/completions`、`GET /v1/models` | 客户端只认这套协议 |
| 2 | **流式（SSE）与非流式都支持** | 客户端默认可能是流式；不支持会出现"界面一直转圈" |
| 3 | **鉴权**：每个客户一个 key | 不然谁拿到地址都能用你的额度 |
| 4 | **额度与限流**：按 key 计 token、设上限、超了拒绝 | 不做这个，一次泄漏就是一张账单 |
| 5 | **上游 key 只存在服务端** | 这是整个方案存在的理由 |
| 6 | **透传"思考/reasoning"相关参数** | 本项目的思考强度是靠 token 预算实现的，中转必须原样透传，别吞掉 |
| 7 | **日志**：谁、什么时候、用了多少 token | 计费与排障的唯一凭据 |
| 8 | **错误可读**：额度用完 / key 无效 / 上游挂了，要回人话 | 客户端会把这句直接显示给用户 |
| 9 | **模型名映射**：客户看到的 `-relay` 名 → 真实模型 | 换上游时不用动客户端配置 |
| 10 | **TLS（正规证书）** | 客户端地址栏接受 `http://`（本机与内网模型就靠它），所以它拦不住你把中转挂成明文 —— 明文等于把客户的 key 在网络上裸奔 |

**其中 3、4、7 是"必须自己写"的，没有现成轮子能直接抄。**
这一条要写进报价说明里。

### D4.3 `app.py`

```python
"""OpenAI 兼容中转：持有上游 key，按客户 key 限额。

为什么这么写（三条关键判断）：
  1. 上游 key 只出现在这个进程的内存里，任何响应、日志都不回显它。
  2. 鉴权用一个独立表，一个客户一个 key —— 这样才能单独停某个人。
  3. 额度按 token 记，超了就拒绝，而不是"先答应再报警" ——
     后者意味着你已经替客户花了钱，再吵也吵不回来。
"""

from __future__ import annotations

import os
import sqlite3
import time
from contextlib import asynccontextmanager
from typing import Any, AsyncIterator

import httpx
from dotenv import load_dotenv
from fastapi import FastAPI, Header, HTTPException, Request
from fastapi.responses import JSONResponse, StreamingResponse

load_dotenv()  # 从 .env 读上游地址与 key

UPSTREAM_BASE = os.environ["UPSTREAM_BASE_URL"].rstrip("/")
UPSTREAM_KEY = os.environ["UPSTREAM_API_KEY"]
DB_PATH = "relay.db"
DEFAULT_QUOTA = int(os.environ.get("DEFAULT_QUOTA_TOKENS", "2000000"))

# 客户看到的模型名 → 上游真实模型名。改上游时只动这张表，不用碰客户端配置。
MODEL_MAP: dict[str, str] = {
    "gpt-4o-mini-relay": "deepseek-chat",
    "gpt-4o-relay": "deepseek-reasoner",
}


def _db() -> sqlite3.Connection:
    conn = sqlite3.connect(DB_PATH, timeout=10)
    conn.row_factory = sqlite3.Row
    return conn


def init_db() -> None:
    """建表。只建一次，重复调用是安全的。"""
    with _db() as conn:
        conn.execute(
            """
            CREATE TABLE IF NOT EXISTS clients (
                key         TEXT PRIMARY KEY,   -- 发给客户的 key
                name        TEXT NOT NULL,      -- 备注：发给谁了
                quota       INTEGER NOT NULL,   -- 总额度（token）
                used        INTEGER NOT NULL DEFAULT 0,
                created_at  REAL NOT NULL,
                disabled    INTEGER NOT NULL DEFAULT 0   -- 1 = 停用
            )
            """
        )
        conn.execute(
            """
            CREATE TABLE IF NOT EXISTS usage_log (
                id          INTEGER PRIMARY KEY AUTOINCREMENT,
                key         TEXT NOT NULL,
                at          REAL NOT NULL,
                model       TEXT NOT NULL,      -- 客户端请求的名字（不是上游的）
                prompt_tokens     INTEGER NOT NULL DEFAULT 0,
                completion_tokens INTEGER NOT NULL DEFAULT 0
            )
            """
        )
        conn.commit()


@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    init_db()
    yield


app = FastAPI(lifespan=lifespan)


def _client_row(conn: sqlite3.Connection, key: str) -> sqlite3.Row:
    row = conn.execute("SELECT * FROM clients WHERE key = ?", (key,)).fetchone()
    if row is None:
        # 不认识这个 key。回 401 而不是 500：客户端会把这句话显示给用户
        raise HTTPException(status_code=401, detail="这个 key 不在这台服务器上")
    if row["disabled"]:
        raise HTTPException(status_code=403, detail="这个 key 已被停用，请联系服务方")
    if row["used"] >= row["quota"]:
        # 额度用完。注意用的是 403 而不是 429：
        # 这是"你的账户没额度了"，不是"你请求太快了"，客户端会原样显示这句话
        raise HTTPException(status_code=403, detail="额度已用完，请联系服务方续费")
    return row


def _auth(authorization: str | None) -> str:
    """从 ``Authorization: Bearer <key>`` 取出客户 key。"""
    if not authorization or not authorization.lower().startswith("bearer "):
        raise HTTPException(status_code=401, detail="缺少 Authorization: Bearer <key>")
    return authorization.split(" ", 1)[1].strip()


@app.get("/v1/models")
async def models(authorization: str | None = Header(default=None)) -> dict[str, Any]:
    """客户端会用它列出可选模型。这里只回我们映射表里的名字。"""
    _auth(authorization)
    return {
        "object": "list",
        # 客户端认这个形状；格式不对时它的下拉框会是空的
        "data": [{"id": name, "object": "model", "owned_by": "relay"} for name in MODEL_MAP],
    }


@app.post("/v1/chat/completions")
async def chat_completions(
    request: Request,
    authorization: str | None = Header(default=None),
) -> Any:
    """把请求原样转给上游，再把响应原样转回来。

    关键：**除了模型名和上游 key，别动别的东西**。
    本项目用"思考 token 预算"实现思考强度，那些参数必须原样透传 ——
    中转吞掉了它们，客户端上那个旋钮就变成了装饰。
    """
    key = _auth(authorization)
    body = await request.json()

    with _db() as conn:
        _client_row(conn, key)

    wanted = str(body.get("model") or "")
    upstream_model = MODEL_MAP.get(wanted)
    if upstream_model is None:
        raise HTTPException(status_code=404, detail=f"没有这个模型：{wanted}")

    upstream_body = {**body, "model": upstream_model}
    # 上游 key 在这里注入，**只在这一处**。它不来自、也不回到客户端
    headers = {
        "Authorization": f"Bearer {UPSTREAM_KEY}",
        "Content-Type": "application/json",
    }
    url = f"{UPSTREAM_BASE}/chat/completions"
    is_stream = bool(body.get("stream"))

    if is_stream:
        # 流式：把上游的 SSE 原样转出去。
        # 为什么必须支持流式：客户端用流式时，不支持的表现是"界面一直转圈然后失败"，
        # 而普通问答完全正常 —— 这种 bug 从手机/客户端那一侧几乎查不出来
        async def relay() -> AsyncIterator[bytes]:
            # 超时给长一点：推理模型"想很久"是正常值，不是异常
            async with httpx.AsyncClient(timeout=httpx.Timeout(300.0, connect=15.0)) as client:
                async with client.stream(
                    "POST", url, json=upstream_body, headers=headers
                ) as response:
                    async for chunk in response.aiter_bytes():
                        yield chunk
            # 注意：流式下拿不到上游返回的 usage（除非它支持 stream_options）。
            # 折中做法是按字符数估算，或者干脆只记"调用次数"。
            # 这里选择不记 —— "宁可少记，不要假记"：编一个 token 数比不记更坏
            with _db() as conn:
                conn.execute(
                    "INSERT INTO usage_log (key, at, model) VALUES (?, ?, ?)",
                    (key, time.time(), wanted),
                )
                conn.commit()

        return StreamingResponse(relay(), media_type="text/event-stream")

    async with httpx.AsyncClient(timeout=httpx.Timeout(300.0, connect=15.0)) as client:
        upstream = await client.post(url, json=upstream_body, headers=headers)

    if upstream.status_code >= 400:
        # 上游的错误原样带回，但**不要**把上游的响应体整个透出 ——
        # 有些上游会在错误里回显请求头
        return JSONResponse(
            status_code=upstream.status_code,
            content={"error": {"message": f"上游返回 {upstream.status_code}，请稍后重试"}},
        )

    data = upstream.json()

    usage = data.get("usage") or {}
    total = int(usage.get("total_tokens") or 0)
    if total:
        with _db() as conn:
            conn.execute(
                "UPDATE clients SET used = used + ? WHERE key = ?", (total, key)
            )
            conn.execute(
                """
                INSERT INTO usage_log
                    (key, at, model, prompt_tokens, completion_tokens)
                VALUES (?, ?, ?, ?, ?)
                """,
                (
                    key,
                    time.time(),
                    wanted,
                    int(usage.get("prompt_tokens") or 0),
                    int(usage.get("completion_tokens") or 0),
                ),
            )
            conn.commit()

    return data
```

### D4.6 放到公网（nginx + 正规证书）

```nginx
# /etc/nginx/conf.d/relay.conf
# 客户端的 base_url 会是 https://ai.yourdomain.com/v1
server {
    listen 443 ssl http2;
    server_name ai.yourdomain.com;
    ssl_certificate     /etc/letsencrypt/live/ai.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/ai.yourdomain.com/privkey.pem;

    # 这个服务本身有额度上限，但仍然要防刷：一个 key 被猜到或被滥用时，
    # 限流让你有时间反应
    limit_req_zone $binary_remote_addr zone=relay_rl:10m rate=20r/s;

    location / {
        limit_req zone=relay_rl burst=40 nodelay;
        proxy_pass http://127.0.0.1:8080;

        # 流式必须关缓冲，否则回答会"憋着一起吐"，失去流式的意义
        proxy_buffering off;
        proxy_cache off;

        # 推理模型可能想很久。给短了的表现是"客户端上说服务不可用"，
        # 而后台明明在正常算
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## D6. 安全清单（这份清单不做完，别把地址给客户）

```
[ ] 上游 key 只在 .env（chmod 600）与服务进程内存里，不进代码、不进日志、不进响应
[ ] 上游返回的错误体【不要】整个透传给客户端（有些上游会回显请求头）
[ ] 每个客户独立 key（能单独停用），不是所有人共用一个
[ ] 额度是硬上限（超了拒绝），不是"先答应再告警"
[ ] /v1/models 也要鉴权（不鉴权等于对外暴露你在卖什么模型）
[ ] 限流已开，且实测过（故意刷一下，确认看到 503）
[ ] 用正规证书（HTTPS），客户端 base_url 也是 https
[ ] 服务用低权限用户跑（systemd 里 User= 不是 root）
[ ] 证书自动续期已配（certbot.timer 或等价物）
[ ] 日志里【没有】任何客户端 key 的完整值（要留就留前 8 位）
[ ] 备份 relay.db（额度记录丢了 = 对不了账）
```

**最后一条经常被忽略**：`relay.db` 是你**唯一**的计费凭据。
服务器重装没备份，就等于所有客户的用量记录全没了 —— 到时候只能免费送。
