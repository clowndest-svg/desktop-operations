# 第 110 轮方案：扩展页要有推荐、图标、详情页，三颗按钮在两个位置都能按

写于 2026-10-12 上午，用户给了一张实拍（扩展弹窗打开着，搜索框下面一片空）并说：

> 图片上这里可以显示一些推荐扩展给我看，查询显示的扩展每个都要有图标和点击图标能有详细介绍页弹出，
> 在查询显示页和详情页面里我都能点击安装或者删除或者更新，另外你说的第三条也给我做完

"第三条"= 上一轮我列的没验到的第 3 条：**拖动她之后重启位置还在**（`pet.origin` 只有单测，
打包版没跑过）。这一并做，见 §7。

---

## 1. 现在到底有什么（读代码得到的，不是猜的）

| 位置 | 现状 |
| --- | --- |
| `jarvis/extensions/sources.py` | 三路并发：精选清单（作者那台服务器 12 条）、npm、GitHub。每路单独带回失败原文 |
| `CatalogItem`（`types.py`） | 有 `name/summary/homepage/stars/downloads/needs/pinned/install`，**没有图标、没有长说明、没有版本** |
| `ExtensionsService`（`service.py`） | `state()` / `search()` / `install(id)` / 手工加 http / 启停 / 删 server / 日志尾巴。装**只认刚才搜出来的 id** |
| `installer.py` | 技能：取 `SKILL.md` + 同目录文本文件写进 `扩展/skills/<slug>/`，写完读一遍，读不过来就回滚。**装完没记下"这份是从哪来的"** |
| `ExtensionsPopup.vue` | 三格（搜索 / 已装 / 运行环境）。搜索那一格在 `searched=false` 时**只有搜索框和两行勾选**，其余是空的；结果行只有文字 + 一颗「装上」；确认卡在勾选那一行下面（上一轮刚从视口外挪进来） |
| 已装那一格 | 有启停、有"删掉这一份"（二次确认），但**它和搜索结果之间没有任何联系** —— 屏上看着同一件东西，两处不知道彼此 |

三条硬约束先钉住，它们决定了下面所有设计：

1. **桥面不接受页面传来的命令行**（`install` 只认我们发出去的 id）—— 这条是"这一页不是命令输入框"
   的实现，详情页和更新都不能把它绕过去。
2. **够不到的能力不许 advertise**（本项目老规矩）—— 判断不了的"更新"就不给那颗按钮，
   但要写明为什么没有，不能悄悄不放。
3. **删除一律二次确认**，且只动它自己那一个目录 / 那一条登记。

## 2. 推荐那一格（打开就看得见，不用先搜）

- 新增桥面门 `extensions_recommended()`：读的就是**精选清单那一路**（作者逐条验过能装的那 12 条），
  不新造一份数据。后端 `ExtensionsService.recommended()` 把 `curated_items()` 的结果缓存五分钟
  （复用 `SearchCache` 的思路，单独一个键），**失败要回原文**，界面上写"这份清单没读到：……"，
  不写成"没有推荐"。
- 打开「搜索」那一格时，如果还没搜过，就先画这一格推荐；搜过之后推荐收起，出一颗
  「看推荐」的按钮能切回去。〔我定的：不并排画，因为搜索结果里也含精选那一路，并排会出现两条一样的。〕
- 推荐条目**同样进 `_by_id`** —— 否则"没搜过就不能装"那条闸会把推荐变成一排永远灰着的按钮。
  这一步是本轮最容易做错的地方：装的动作要求 id 在服务端认得，而"服务端认得"不等于"人搜过"。

## 3. 图标：三条路各自的答案

| 来源 | 图标从哪来 | 拿不到时 |
| --- | --- | --- |
| 精选清单 | 服务器那份 JSON 每条加一栏 `icon`（emoji，随清单一起发，不多一次网络请求） | 空串 → 首字母方块 |
| GitHub | 仓库搜索响应里就有 `owner.avatar_url`，带进 `CatalogItem.icon` | 同上 |
| npm | registry 搜索响应**没有**图标字段（本轮实测：`objects[].package` 里只有 name/version/description/keywords/score） | 首字母方块 |

两条规矩：

- **域名白名单**：只认 `https://avatars.githubusercontent.com` 和作者清单那台主机。图标是页面去
  加载的一张图，白名单外的一律丢进首字母方块 —— 不挡的话，一份被改过的清单能让用户的浏览器
  去访问 `http://127.0.0.1:任意端口`，那是拿她的界面替别人扫本机端口。
- **首字母方块不是"假图标"**：它是名字生成的头像，详情页那一栏会明写
  "这一格的图是名字首字母生成的，来源没给图标"。〔我定的：宁可承认没有，不摆一张看起来像的。〕

## 4. 详情页：一张内嵌卡，不另开窗

桌面已经有很多层窗（设置 40、助手 44、扩展 46），再开一张"详情"窗就要再付一次遮挡与关闭的账。
所以详情页是**扩展弹窗内部盖上来的一张卡**（同一张 `.ext__box` 里，`z-index` 只在它上面），
内容按 kind 分：

- 共同：图标、名字、这是什么（长说明，没有就写"来源没给长说明"）、出处链接、要本机有什么命令、
  这一条现在装没装、装在哪、什么时候装的、审计里最近那一笔。
- MCP：那条**完整命令行**原样摊开（和确认卡同一份内容）、transport、要哪些环境变量名
  （**只有名字，永远不回显值**）。
- 技能：会写进哪一个目录、钉在哪个 ref、取回的是哪几个文件、正文多少字。
- 三颗动作：**装上** / **删掉**（要二次确认）/ **更新**（语义见下一节，判断不了就不出现，
  并写明为什么）。

新门 `extensions_detail(item_id)`：同样只认发出去的 id；返回**一整份形状**，读不到也带空形状 + 原因。

## 5. "更新"到底是什么意思（这条最容易做成假的）

| kind | 能判断吗 | 怎么做 |
| --- | --- | --- |
| 技能 | **能，但要先记来源** | 装的时候在技能目录里落一份 `.xiaoye-source.json`（repo/ref/path/装的时间/`SKILL.md` 的 sha256/清单 id）。更新 = 按那份记录重新取一次文件、**比 `SKILL.md` 的 sha256**：一样就说"这份和来源现在的内容一模一样，没动"；不一样才替换。比的是文件本身，不是版本号 —— 技能前言里写不写 `version` 完全看作者心情 |
| 技能（旧版装的，r108/r109 那几份） | **不能** | 盘上没有来源记录 → 详情页写"这一份是上一版装的，当时没记下来源，只能删掉重装"。不给一颗点了什么也不会变的按钮 |
| MCP · npm | **没有"更新"这回事** | 那条命令行是 `npx -y <包>`，**每次起进程都现拉最新版**。所以这里不给更新键，写明白这句话 |
| MCP · 精选/手工 http | 能 | 清单里那条登记变了（命令行/地址/要的环境变量）就重写这一条登记，保持它原来的启停状态，然后当场连一次 |

新门 `extensions_update(item_id)`：技能走"重取 + 比 sha"，MCP 走"重登记 + 连一次"；
两种都把结果写成一句能上屏的话，失败原文不许咽。

## 6. 删除：从两个位置删同一件东西

- 已装那一格的删除**保持原样**（二次确认、只动一个目录 / 一条登记）。
- 搜索结果与详情页的删除：新门 `extensions_remove_item(item_id, confirmed)` —— 它按 id 找到
  那条 catalog 记录，再解析成"技能 slug"或"server 名字"，然后走**同一套**已有的删除实现。
  不在页面里拼 slug：页面拼出来的那个名字和后端 `slugify()` 的结果迟早会不一样，
  而删错东西没有回滚。
- 没装过的条目：那一颗是"删掉"并且灰着，写明"这条本来就没装"。

## 7. 顺带做完的欠账：拖动之后重启位置还在

打包版上跑一遍真流程：起 r110 的 exe → 读她当前窗口矩形 → 用壳递给拖放的那条回调
（`PetController.set_dragging(False)` 走的正是松手那一下）把新位置写进偏好 → 杀进程 →
重开 → 再读窗口矩形比对。**真鼠标的部分仍然要点**（CDP 到不了 Win32 那层），但"写进去、
重启读回来、落在同一个像素"这三步能在产物上验死。判据要自证那一下真点到了：比对的是
两次启动各自读回来的坐标，不是我改过的变量。

## 9. 验收判据

源码侧（每条都要有对应测试，且做完自己跑一遍变异）：

1. 没搜过时 `recommended()` 把条目放进 `_by_id`，**推荐里的条目能直接装**；
2. 精选清单没读到 → 回的是失败原文，不是空列表；
3. 白名单外的图标 URL 进不了界面（后端就丢，不给前端判断的机会）；
4. 技能装完盘上有 `.xiaoye-source.json`，内容与实际取回的文件一致；
5. 更新：来源没变 → 说"没动"并且**不重写文件**（mtime 不变）；来源变了 → 替换并说明；
6. 旧版装的（没记录）→ 不给更新，写原因；
7. npm 那条 → 不给更新，写"每次起都现拉最新版"；
8. `remove_item` 删的是后端解析出来的那一个，删错/删多了测试要红；
9. 四扇门在没有扩展层时都回完整形状（`test_bridge_surface` 那套规矩）。

打包版侧（CDP，同一时刻只许一个实例）：

1. 打开扩展 → 没搜过 → 推荐那一格有条目、每条有图标；
2. 点图标 → 详情卡出现，`elementFromPoint` 证明命中的是卡不是遮罩；
3. 详情卡里「装上」→ 出确认卡 → 真装 → 已装那一格多一条（**跨格核对，不是只看那一格**）；
4. 同一件的详情里那颗变成「删掉」/「更新」，按下去走的是同一条后端路径；
5. 日志 0 条 ERROR，事件日志无新增 APPCRASH。

## 10. 〔我定的〕（你说别问，所以我按我认为最优的走）

1. **详情页用内嵌卡，不另开一张窗。** 代价：小屏上那张卡会盖住列表，得靠"关闭"退回。
2. **图标用 emoji（精选）+ GitHub 头像（真图标）+ 首字母方块（兜底）**，不引入图标字体、
   不下任何图片文件进包。代价：npm 那一路全是首字母方块，看起来不如"有图"。
3. **图标 URL 走域名白名单**，白名单外一律丢。代价：以后想给某条自定义图标要改代码。
4. **"更新"按 kind 分开讲**，判断不了的一律不给按钮 + 写明原因。代价：npm 那一路永远没有
   更新键，有人可能以为坏了 —— 那句话就写在它的位置上。
5. **来源记录放技能目录里那个 `.xiaoye-source.json`，不放数据库**：技能目录本来就该自解释，
   拷走目录 = 连来源一起拷走；放进 `servers.json` 那种集中登记反而会让"删了目录"和"记录还在"
   同时成立。
6. **推荐只读精选那一路**，不掺 npm/GitHub 的"热门"。理由：只有这一路是我逐条验过能装的，
   而"推荐"两个字一旦来自星标数，就是在替用户决定，而星标不是质量（这条 `sources.py` 里早写了）。
7. 旧版装的技能**不猜它的来源**（不拿目录名去反推仓库），只说"删掉重装"。
