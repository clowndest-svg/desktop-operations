# 知识库自充实 · 服务器用途 · 交付包买家风险（r107）

用户一次交代三件事：① 这台 4 核 4G 的腾讯服务器对本软件能干什么；② 交付包发给各个买家
会不会出事，要对应看下；③ 要 AI 能根据对话和联网搜索自己充实知识库。要求先出详细方案再
按方案执行，做完一次功能测试交付，并明确"别问，按你推荐的最优方案做"。

这份文档是方案 + 已执行的结果。**没量到的地方一律写"未核实"**，判断的地方写"判断"。

## 一、服务器：先量，再决定做什么

现场读数（SSH 直连，2026-10-12 02:3x）：

| 项 | 实测 |
| --- | --- |
| 系统 | OpenCloudOS 9.6，内核 6.6.119 |
| CPU | AMD EPYC 7K62，4 vCPU，**有 avx2、无 avx512** |
| 内存 | 3655 MB 总，已用 648 MB，可用 3006 MB |
| 磁盘 | 40 G，已用 6.3 G，剩 34 G |
| Docker | 29.9.0，**零容器在跑**（本机只有 redis:7-alpine、hello-world 两个镜像） |
| 1Panel | 监听 12088，进程占 178 MB |
| 80 端口 | 安全组**放行**：临时监听后从本机打过去 http_code=200、47~53 ms |

### 做了什么

**只读发布清单端点**（`xiaoye-release` 容器，nginx:alpine，80 端口，挂载
`/opt/xiaoye-release/www` 只读）：

- `latest.json` —— 版本、构建轮次、包体积、SHA256、更新说明、下载地址；
- `models.json` —— 语音等模型该下哪些、多大、SHA256、**官方直链**；
- 首页一句话说明这是什么、怎么下线（`docker rm -f xiaoye-release`）。

软件这一侧加了一条工具 `check_update`：问一次清单，回一句人话。
**只在人问的时候发这一个 GET**，不下载、不自动装、开机不检查。

### 为什么不随包发模型 / 不做模型中转

| 候选 | 结论 | 依据 |
| --- | --- | --- |
| 服务器托管 900 MB 语音模型给买家下载 | **不做**，只发清单 | 40 G 盘 + 按流量计费：每个买家拉一次就是近 1 G 出口。清单里给官方直链，效果一样而服务器不经手字节，也躲开"再分发"的许可问题 |
| 服务器上跑 llama.cpp 给买家当云端模型 | **不做**（且**未核实**具体 tok/s） | 想量的那次没量成：GitHub API 拿 release 资产返回空（带 UA 后 api 是 200 但资产列表里没匹配到 `bin-ubuntu-x64.zip`），脚本按设计直接退出，没硬编。判断依据只有两条已知事实：这台机**没有 GPU**，而随包 4B 在**有 GPU 的** 1650 上单条请求要 130~300 秒。CPU 推理只会更慢，而买家自己机器上本来就带着 0.6B/1.7B/4B —— 拿它当"云端大脑"是降级 |
| 联网搜索中转（作者付 key，买家共用） | **不做** | 三件事叠在一起：查询内容离开买家机器（对外文档承诺"没有遥测"就破了）、作者替所有买家付钱且无法限损、买家机器上那条路变成"关掉自己的网就废了" |
| 买家遥测/心跳回传 | **红线，不做** | 交付红线里写着"演示不用本人 key、密钥只进环境变量"，同一条脉络 |
| 项目主页 / 文档站 | **可以，下一轮** | 1Panel 有现成的 OpenResty 与证书；但主页要放真截图和真数字，那些得先按下面第三节全部核一遍 |
| CI 跑门禁 | **可以，下一轮** | 全量 pytest 现在 3 分 08 秒（188.67 s 现读），4 vCPU 扛得住；但门禁依赖 Windows 专属那一层（分层窗、注册表、剪贴板），Linux 上只能跑子集，价值要打折 |

## 二、她自学：只认"真上过网"的那一轮

### 为什么不做"每轮聊天都自动提炼事实"

用户原话是"根据对话和联网搜索充盈自己的知识库"。对话那一半**早就有着落** —— 他说
"记一下"时走 `add_knowledge` / `remember`（r89 补的写半）。剩下那一半"每轮自动提炼"
要**额外叫一次模型判断**，而随包 4B 一次 130~300 秒，等于把每轮问答拖成两倍；
更要紧的是 r88 那次「离线啥都问不了」的三条真因里就有一条是**资料库提示污染**。

所以这一层的形状是：**这一轮真调过 `search_web` / `fetch_url` 才存**。有来源、有时间、
可核对、可整批删。

### 落点与判据

`jarvis/app/knowledge_growth.py`，挂在 `ChatService` 工具循环之后：

- 落在 **`数据/笔记/_自学/`**（`notes_dir` 就是 `数据/笔记` —— 我一开始在注释里写成
  `数据/知识库/_自学`，被前端子代理回源时抓到，已改）；
- **去重按问题指纹**：抹掉标点和空白再哈希。第一版只去空白，于是
  「北京今天天气如何？」和「北京今天天气如何」算两条，同一问题问两遍存两份；
- **每天上限**（默认 20 条）、**回答太短不存**、**失败的那一轮绝不存**
  （把"连不上 28181"存成事实，下一次提问就带着错前提）；
- 每一次"没存"都带一句能念给人听的原因，进日志；面板读 `stats()` 显示
  「开着 · 今天 N 条（上限 M）· 一共记过 K 条 · 存在哪」；
- **不阻塞回答**：索引一条笔记要做切块 + 向量化，所以丢给一条命名过的一次性线程
  （`jarvis-learn`），测试把这条线程换成同步执行；
- 界面：助手弹窗 → 知识库那一页顶部一节，开关用**读回来的值**刷新，
  「只删她自学的」走内联二次确认，删完重新拉一次列表而不是本地减数字；
  列表里自学条目带「自学」小标签。

### 端到端测到了什么

`tests/test_app_knowledge_growth.py` 18 条，用**真** `KnowledgeService`（真 SQLite +
真 HashingEmbedder + 真笔记目录）、**真** `ToolService` + **真** `search_web`
（只把网络换成开在回环上的假 HTTP 服务）：搜一条 → 她存下一条带 URL 的笔记 →
同一句话再问一遍不会存第二份 → 一键清只清 `_自学` 里的那些、人喂的一条不动。

### 没改、但必须知道的（要一台干净机器）

1. **无显卡 / 无 ComfyUI 的买家**：她会答应画，然后每次回"这一张没画成：连不上
   127.0.0.1:8188…云端这边也没配好"。面板初始只写"还没检测过"，要按一次才见红字。
   要不要改成"探不到就不注册 `generate_image`"是个**取舍不是 bug**：那样买家后开
   ComfyUI 就得重启软件才看得见这条能力。这一轮先只把措辞和面板初值改清楚，
   注册策略留到有一台干净机器能真验的时候再动。
2. **语音首启 900 MB**：失败话术是英文 + `repr`，没有"查网/重试"这句；下载进度在
   `console=False` 下全程不可见。
3. **OneDrive 桌面 / Program Files 解压**：文档现在点名禁止了，但代码里
   `mkdir` 抛 `PermissionError` 被吞掉、静默回落 `%LOCALAPPDATA%`（就占 C 盘了）——
   这条**只改了文档，没改代码**。
4. **未签名 exe + 内嵌 adb/scrcpy**：全仓零签名痕迹。文档教了 SmartScreen
   "更多信息→仍要运行"和杀软加白，但没给 Defender 的具体入口，也没说 SHA256 值从哪拿。
5. **`MODELSCOPE_CACHE`/`HF_HOME`/`TORCH_HOME` 已被买家设过的时候**，模型不再重定向 →
   落 C 盘，与"不占 C 盘"矛盾。

1. 拿一台**干净 Win10**（无显卡、无 Android Studio、无 WebView2、解到 D 盘），
   照 `04-买家安装与使用说明.md` 从头走一遍。重点验第 1 条那个白屏 —— 现在它应该弹
   一句人话而不是白着。
2. 把 `01`/`04` 的体积、SHA256、APK 版本再核一遍（脚本现读，但**发货前**要重跑一次，
   因为包可能又变了）。
3. 决定第 1、3、5 条要不要在这轮做进代码 —— 我的判断：第 3 条（回落要说出来）
   代价最小、最容易咬人，下一轮先做它。

## 五、按方案做完之后，设计改了一处（这一节才是真话）

### 检查更新认的不是版本号，是构建轮次

上面第三节写的是「清单里给 `version`，和本机 `__version__` 比」。**这句在落地当天就被证伪了**：
`__version__` 从项目第一版起就是 `0.1.0`，从来没有谁去改过它。拿一个逐轮不变的数去比清单，
结果只有两种，而且都是假话 —— 清单写 `0.1.0` 就人人"已是最新"（拿着 r83 的人也是），
清单写 `0.1.1` 就人人"有新版"且永远消不掉。

逐轮真的在变的只有那个 `rNN` 目录名。所以定稿改成：

| 位置 | 做什么 |
|---|---|
| `packaging/jarvis.spec` | 从 PyInstaller 给的 `--distpath` / `--workpath` 里认那一段 `rNN`，写进 bundle 里的 `buildinfo.json` 的 `round` |
| `scripts/release_manifest.py:round_from` | 认的逻辑放这儿而不是放 spec：spec 没法 import，而这个数是每个买家那一句的唯一依据，它必须有一条跑得起来的测试 |
| `jarvis/__init__.py:release_round` | 读那一份；**非 frozen 一律回空串** —— 源码那边读得到上一次在这台机器上打包留下的 `build/buildinfo.json`，不挡掉的话"我是第几轮"取决于这台机器干过什么 |
| `jarvis/app/update_check.py:parse_round` | 认不出来回 `None`，**不回 0**：0 会让任何真实轮次都"比它新"，于是打包配方哪天漂了 = 所有买家永远"有新版" |
| `scripts/deliver_release.ps1` | 新门：自检报告里 `build.round` ≠ `-Round` 就 throw，不压包 |

清单的形状因此是 `{"round": "r107", "size_mb": …, "sha256": …, "notes": …, "url": ""}`，
`version` 那一栏留着也没人读；`url` 必须为空 —— 这台服务器不放文件，填了就是给买家一个假链接。

### 还敞着的一处：清单是 http 明文，只有 IP，没有域名和证书

`check_update` 的信道目前是 `http://124.220.54.64/latest.json`。中间人改一份清单，
买家会照着一个错的 SHA256 去校验，然后"对上了"。这一轮**没有**解决它，只是把话说清楚：

1. 这条工具**只读、不下载**，所以被改坏的清单最坏是让人误判新旧 + 拿错校验值，不会直接落盘任何东西；
2. 要收口：上域名 + 腾讯那批免费证书（1Panel 有入口），或者把 SHA256 改走另一个渠道发（网盘说明里那份
   `清单.txt` 本来就在包内，可以作为第二条对照）；
3. 没做的原因不是"以后再说"，是这轮先保证"答的是真话"这一半 —— 一个答假话的更新检查比一个没有更新检查更坏。

### 服务器现在到底承担了什么（实测，别写成能承担一切）

- 一个 nginx:alpine 容器 `xiaoye-release`，宿主 `/opt/xiaoye-release/www` **只读**挂进容器，
  `--restart unless-stopped`；盘 40 G 用了 6.3 G；80 端口从外网可达（第一次探它拿到的是 404 —— 
  说明通，只是那份 `latest.json` 当时还没写进去）。
- 只放这一份几百字节的 JSON。**不放模型、不放包、不做搜索代理、不收遥测**，
  理由都写在上面第三节那几张表里。
- `models.json` 仍然没有：语音模型清单没逐条核过，不拿猜测填一份看起来完整的清单。
