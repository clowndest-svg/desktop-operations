# 扩展市场、技能与「对话框里要能用」（r108 方案）

用户原话：「加一个插件页面，要能像 qoder、zcode、codex 这些工具一样按 skills、mcp、插件装；
页面要有搜索功能、能联网搜索；装完要能配置到本软件上并且能用，对话框里要能使用；
其他地方你看着办；写方案 → 执行 → 功能测试；我要去睡觉了，有问题按最优方案做，别问我。」

这份文档先写**量到的现状**和**为什么这么设计**，再写分阶段与验收判据。方案本身定了就不改，
被砍的项会在末尾写明为什么砍，不悄悄不做。

## 4. 设计决定（每条都带理由，页面上也要能看见这些理由）

**4.1 市场里只卖两种货：技能（markdown=数据）和 MCP server（外部进程）。`plugin.yaml` 那种 Python 代码包不进市场。**
 loader 继续存在（人自己往目录放仍然能用），但它不是可搜索/可一键装的东西。
 理由一句话：从网上下载代码再 import 进助手自己的进程 = 给每台买家机器开一条远程代码执行通道，
 出事没人负责；而 MCP 是**进程隔离**的，且**装之前那条命令行摊给人看过**。这条差异要写在页面上，不偷偷。

**4.2 三路并发搜索，每一路单独交代。** 返回形状里带 `每源：命中数 / 耗时 / 失败原因原文`。
 全空时屏上必须是"三查两空：GitHub 那路超时、npm 没匹配"，不能是一句"没有结果" ——
 用户没法区分"市场里没有"和"我这网不通"，那是本仓库反复在治的那一类失败。

**4.3 精选清单放在作者自己那台服务器上。** 定位是"我逐条验过的"，与 npm/GitHub 的"搜天下"并列成两个 tab 级来源。
 它保证买家在受限网络里至少有一路出结果，且这一路的内容由我控制质量。清单里每条都写安装方式与验证时间。

**4.4 装 MCP = 写 `数据/扩展/servers.json`，绝不动 `config.yaml`。**
 装配点把这个文件合并进 `mcp.servers`，**config.yaml 里同名的优先**（人手写的东西赢）。
 装完立刻真连一次：连不上就回滚这次写入，并把客户端原话显示在页面上。
 （`SettingsService.apply` 是按字段写的 bespoke 编辑器，塞不进 `mcp.servers.<name>` 这种嵌套结构，
   所以另开一个扩展自己拥有的文件，而不是把 config.yaml 用 yaml.dump 重写一遍 —— 那会毁掉用户注释。）

**4.5 安装的前提是运行环境在。** `runtime.py` 检 `node` / `npx` / `python` / `uvx` 各在不在，
 结果直接印在页面第三格。缺 `npx` 时那条 npm 条目的安装按钮是**灰的并且写着为什么灰**。
 理由：注册一条永远失败的路是本项目被反复要求停止生产的那类失败（见 [[proj-capability-surface]] 的三条检查）。

**4.6 对话里"能用"分三条通路：**
 - **MCP 工具**：注册进同一张工具表（现有实现），模型直接按名字调；
 - **技能**：已启用技能的 `name + description` 进系统提示（**有硬上限**），正文由工具 `use_skill(name)` 按需取 ——
   渐进披露。19 份说明书全塞进 4K 窗口是把别的能力挤没，Qoder/Claude 也是这么做的；
 - **可回答**：`extensions_list()`（只读）让她答得出"我装了哪些、哪个没连上、为什么"。

**4.7 本地小模型的路由必须给扩展工具兜底。** 规则：`source` 以 `mcp:`/`skill:` 开头的工具进兜底集合，
 与 `GENERAL` 同批带给随包模型，受现有"装不下就扔清单并在屏上说"的机制约束。
 并给这条兜底路径写一条**不参数化**的测试当变异靶子（参数化的一个 nodeid 收多例，变异器会判这批不可信）。

**4.8 默认全关，且装 ≠ 开。** `mcp.enabled` / `plugins.enabled` 保持 `false`。页面上第一颗开关叫
 「允许她运行外部扩展程序」，点开时明说：那个进程**用你当前账户的权限**跑，能读你能读的一切。
 每次真正启动子进程都写审计。这不是过度谨慎 —— 这是装第三方程序的应有仪式。

**4.9 删除走「扫描 → 二次确认 → 执行 → 审计」**，且只允许删 `数据/扩展/` 里面的目录与自己写进 servers.json 的条目；
 边界同 `delete_path`：挡的是路径来源，不是"看起来危险"。

**4.10 审计两行制**：`logs/extensions.jsonl` 先写"准备装什么、从哪个源、命令是什么"，再写结果。
 装挂掉的那一次才留得下来（命令行工具那条同一招）。

**4.11 页面上不出现任何密钥回显。** 有的 MCP server 要 API key（`env` 字段）：key 只进环境变量/不进日志、
 页面永远只显示"已设置"，与现有 `api_key` 那套同一条规矩。

| 阶段 | 内容 | 验收（要能自己说"那一下真做到了"） |

## 7. 明确不做（写下来免得下轮从头讨论）

| 不做 | 为什么 |
| --- | --- |
| 解析 `skills.sh` 的 HTML 当清单 | 它没有 JSON API；别人改版那天这路会**静默返回空**，而页面上看到的是"没结果"。要么有可校验的结构，要么不做 |
| 市场里一键装 Python 代码插件 | §4.1 |
| 自动更新已装扩展 | 装是人按的；偷偷换掉盘上的东西就是流氓更新器（和 r107 的 `check_update` 只读同一条理由） |
| 把每扇桥面门都变一条工具 | 工具越多选错越多；只接"不接她就答错"的那三条（§4.6） |
| 在扩展页里做"跑脚本"的能力 | 已有 `run_powershell` 那把独立的锁，不该从市场这条路绕过去 |
| 给模型 `extensions_install` | 安装 = 人点头。给模型 = 她自己往机器上装东西 |

## 8. 执行状态（做完一项改一项，被砍的写明原因）

| 阶段 | 状态 | 量到了什么 |
| --- | --- | --- |
| A 技能 | **做完** | `jarvis/skills/`：社区那一份 `SKILL.md` 形状（frontmatter 的 name/description/license/homepage，CRLF 与软链接都拒），索引硬上限 12 条 / 1800 字，正文由 `use_skill(name)` 按需取；关掉的那份不进索引也不许被 `use_skill` 取回。 |
| B 装配 | **做完** | 桌面第一次真起 MCP / 技能 / 扩展三层；`servers.json` 与 `config.yaml` 在内存里合并，**同名以 config.yaml 为准**，`enabled` 取两边之或。真 stdio 子进程用测试里我自己写的那个 Python server 验（写标记文件 + 回显一个环境变量）。 |
| C 市场 | **做完，且真机验过** | 三路并发：真打一次 5~7 秒，精选 12 条 / npm 真条目 / GitHub 真仓库；每路带命中数、耗时、**失败原文**。装只认刚搜出来的 id；技能装完**回读一遍**才算装上（写→`read_directory`→失败回滚）；缺 npx 时那条装不了，理由在屏上。 |
| D 界面 | **做完** | 顶栏「扩展」+ 三格（搜索 / 已装 / 运行环境）；10 扇门全部走 `test_bridge_surface`（含"参数名不许叫 window 那一族"）；打包版 CDP 真点：搜索→33 行→装 `canvas-design`→确认卡写着落盘目录→盘上 2 个文件 / 正文 11566 字→「技能 · 1 份」→启停双向翻得动。 |
| E 交付 | **做完** | 门禁：black / ruff / mypy --strict **383 文件** / pytest **3762 passed, 5 skipped** / vue-tsc + vite 全绿；变异 **33 条全杀**；包 `小夜-电脑+手机-r108.zip` **9861.9 MB**，全 CRC 回读绿，exe 自报 round=r108，日志 0 ERROR。 |

**这一轮改出来的两个真 bug（都不是"缺功能"，是"接了但用不上"）**：

1. **对话框里永远用不上**。`select_tool_names` 的关键字路由里没有扩展工具这一族，界面装得再好、
   随包 4B 那一次请求里就是没有它，而且不报错。修法：`mcp:` / `skill:` / `plugin:` / `extension:`
   四种来源进兜底集合；判据必须走真 `ChatService._tool_schemas` —— 第一版只调那个纯函数，
   于是把 ChatService 里 `extra=` 整段删掉测试仍然全绿。
2. **Windows 上 `npx` 是 `.cmd` 壳**。`shutil.which` 报有、`CreateProcess` 拿裸名字起不来，
   表现是"检测说有、连接说没装"，市场里 npm 那一整类每条都能"装成功、连不上"。
   修在 `jarvis/core/commands.py`：检测与启动共用同一个解析器，`.cmd` 经 `cmd.exe /c`，
   并且拒绝 `& | < > ^ %` 这些会被 cmd 重新解释的字符。

**§4.4 有一条没照原样做**（写明，不悄悄）：原写"装完立刻真连一次，连不上就回滚这次写入"。
实际做的是**装完当场连一次、连不上不回滚**，理由：第一次 `npx` 拉一个包可能要几分钟，
那笔下载没有理由让用户丢掉刚点下安装的东西；失败原文留在页面上那一行，「重连」那颗按钮也一直在。
这条由 `TestInstallingRightAwayConnectsIt` 四条测试钉住（含"没接 MCP 那一层时要说清楚"和
"连接抛异常不许把页面带下去"）。

**打包版实测抓出来、留到下一轮的**：① 确认卡排在三十条结果下面，掉出视口 ——
"摊开给人看清楚再按"这一句的表现形式失效；② `.hud-field` 从来没有宽度规则，
35 处输入框全在吃浏览器默认 ~150px，中文提示语必然画不完（用户报的"被按钮挡住"）。
两条都在 r109 修掉并复量。

**明确没做**：解析 `skills.sh`（纯 HTML、无 JSON API，改版那天会静默返回空）；市场里装 Python
代码插件；自动更新已装扩展；把每扇桥面门都变一条工具；给模型 `extensions_install`。

## 9. 交付与收尾（沿用每轮那六步）

前端 build + 门禁（`scripts/run_gates.py --frontend`）→ 打 r108 → 按产物独立回读
（exe 里有没有这几个新包、自报轮次、服务器清单与盘上 sha 一致）→ 快捷方式改指并读回 `.lnk` →
文档（对外文案按当轮产物现数；**没验到的必须写进手册**）→ 记忆。
旧包不自动删（要人点头）。推送只走 `docs/分发与分享.md` §9 的公开分支配方，三道机器校验跑在 `write-tree` 上。
