## 4. OPT-01：翻译主链路

### 修改方案

1. 将翻译配置与聊天模型配置分开。默认可继续复用随包模型，也能指定独立的翻译模型；界面显示实际提供方、模型及本地/联网属性。切换聊天模型不得静默改变“离线翻译”策略。
2. 去掉“命中一个英文虚词就跳过”的决定规则。增加保守的语言判断，短句、混合语言和低置信度输入进入翻译；人工选择“原文已是英文”可作为高级选项。语言检测工具先以当前评测集验证，再决定是否引入轻量依赖。
3. 输出检查分三层：响应完整性、目标语言、关键语义。检查空输出、`finish_reason=length`、解释文字和明显未翻译文本；使用评测和必要的二次核验检查数量、否定、左右关系、颜色与动作。检测不确定时提示复核，不伪装成已验证正确。
4. 长输入按模型上下文和输出预算分句/分块，保留顺序与指代；超出可可靠处理的长度时明确拒绝。禁止按字符直接截断后继续生成。
5. 将 LoRA 名称、模型名、路径、权重表达式等作为受保护片段处理；翻译后检查片段是否完整恢复。对生成模型的负面描述与自然语言否定分别处理。
6. 缓存键包含源文本、目标语言、翻译策略版本及实际模型标识；缓存数量和总字节均有上限。模型或策略变化后避免复用过期结果。
7. 保留原文、英文、实际来源与耗时。默认一键生成；提供可选的“先看译文再生成”，方便复杂提示词核对。
8. 本地图片与本地视频共用同一接口；云端视频增加服务商级语言策略（强制英文/服务商原生语言），默认规则在界面说明，不再使用一条隐含策略覆盖所有服务商。

### 验收

- 固定至少 12 种语言、120 条描述，覆盖中文、英文、日、韩、法、西、德、俄、阿拉伯语等，并单列混合语言与提示词语法；两入口使用同一组样本。
- E01、E02 的复现样本必须修复；受保护语法、明确数量与否定等关键用例 100% 通过。普通样本人工语义合格率目标不低于 95%，逐项记录失误。
- 长输入截断、模型不可用、无 Key、网络失败、缓存切换均有有效失败路径；不完整输出不得进入生成队列。
- 固定短句集热模型翻译 p95 初始目标不超过 3 秒；单列冷启动。以真机测量校准目标，不能通过缩短译文达标。
- “任意语言绝对准确”不作为可兑现承诺；支持范围由样本和真实用户回归逐步扩大。

## 5. OPT-02：任务、停止和恢复

### 修改方案

1. 引入共享 `MediaTaskService`，为每次请求分配 task_id、独立取消令牌、参数快照、引擎 prompt_id/云端 task_id。图片和视频保留各自工作流构建职责。
2. 状态明确为排队、翻译、加载、采样、编码、下载、完成、取消中、已取消、失败。状态只允许合法迁移；被拒绝的新请求不能更改旧任务状态。
3. 立即修复取消位在抢锁之前被清除的问题；独立任务机制完成后移除共享取消位。加入请求去重，防止连点、桥接重试造成重复出图或重复计费。
4. 本机默认单任务执行，支持有上限的等待队列；对话和弹窗统一查询、停止和重试。
5. 本地取消区分排队任务和正在运行的任务。对共用外部 ComfyUI，仅在确认运行项属于本软件时调用 interrupt；不能误停别人的工作流。具体行为依据已安装引擎能力探测。
6. 云端区分“停止本地等待”“服务商确认取消”。没有取消 API 的服务商明确显示仍可能在后台执行，并允许凭 task_id 重新查询。
7. 翻译结束、提交之前和下载过程中都检查取消；同步阻塞客户端至少设置明确超时。界面先确认收到请求，后台收到引擎确认后再显示“已取消”。
8. 重启只管理本软件拥有的进程；重启中拒绝新任务，超时保留错误，不显示假成功。
9. 持久化最小任务记录。重启后查询外部任务是否仍在运行；无法恢复的本地任务标为中断，不自动再次发起付费请求。

### 验收

- 交叉运行“图片→停止→视频请求”“视频→停止→图片请求”“两入口同时提交”，取消令牌与活动状态不串任务。
- 连续 50 轮任务生命周期测试无卡死、串状态、重复提交；故障后可继续提交下一任务。
- 停止按钮收到请求的界面反馈目标小于 500ms；引擎实际停止时间单独记录，不把界面响应当作停止完成。
- 应用退出、服务商超时、引擎崩溃、磁盘写满、窗口重开均有可解释状态与恢复路径。

## 6. OPT-03：非 C 盘路径与空间

### 修改方案

1. 统一数据、模型、临时目录、WebView2 用户目录和引擎缓存的路径策略；检查源码运行、打包运行、首次启动和子进程启动四条路径。
2. 现有打包钩子已设置程序旁数据目录，不能误当成完全未做；重点补上 JARVIS_HOME 缺失、程序放 C 盘、目标目录只读、D 盘不存在等情况的闭环。
3. 本机新增内容默认进入 `D:\AI\XiaoYe\` 下的 data/models/cache/tmp/build/qa 等目录。其他用户首次选择可写的非系统盘目录；找不到则说明原因，不静默退回 C 盘下载模型。
4. 生成、解压与更新前估算临时空间、最终占用、保留旧版本所需空间；空间不足在执行前拦截。
5. 设置页显示路径与分类用量，提供迁移向导。迁移包含停服务、复制、校验、更新引用、恢复服务；原数据到验证成功后才进入清理候选。
6. 清理仅处理本软件可证明拥有的缓存、失败临时文件和旧版本；保留当前版与一个可回退版，作品和对话默认不清。

### 验收

- 干净 Windows 用户环境中测试：启动、聊天、加载模型、图片、视频、更新的应用数据与模型写入均位于选定目录。
- 以文件写入追踪检查第三方缓存，不只检查环境变量。Windows 自身日志、驱动缓存等系统行为单列，不承诺操作系统 C 盘零字节变化。
- 无 D 盘、只读目录、中文及空格路径、磁盘满和迁移中断均有失败恢复测试；原数据校验一致。

## 7. OPT-04：云端错误、下载和结果校验

1. 统一网络错误模型：错误码、服务商、可重试性、脱敏 request_id。界面不直接显示整段响应正文和带查询参数的 URL。
2. 对响应回显的密钥、提示词、签名下载地址、Authorization 等做脱敏；服务商返回不可信文本，不能依赖“它通常不回显”。
3. 视频流式下载到 D 盘 `.part` 文件，分块检查取消、实际大小和磁盘余量，结束后原子改名；显式检测超限与 Content-Length 不符。
4. MP4 的 `ftyp` 只能做初筛；完成后用媒体探测检查可解码、时长、帧数、尺寸与可用轨道。失败不加入作品列表。
5. 重试区分提交和轮询：轮询与下载可按策略重试；创建付费任务只能在有服务商幂等保障或人工确认后重试。
6. 自定义服务商配置只发送到用户确认的端点；处理重定向时不把授权头带到无关主机。授权模板与额外请求头分别校验。

验收：覆盖错误回显含假密钥、JSON 错误、401/429/500、重定向、下载中断、残缺 MP4、超限文件、磁盘写满；诊断与界面不出现完整测试密钥和签名参数。

## 8. OPT-05：低显存与性能

1. 统一协调聊天模型、翻译、ComfyUI 和语音模型的 CPU/RAM/VRAM 需求；不要只在图片和视频之间加锁。先实测它们在本机的实际驻留，不假定都占 GPU。
2. 以 GTX 1650 4GB 建立三个入口档：稳定、平衡、实验；默认只提供已通过真机测试的组合。显存外推可用于提示，不能替代认证档位。
3. 采样前检查空闲显存、系统内存、引擎当前模型与任务状态；必要时排队或卸载闲置模型，避免同时冷启动多个重模型。
4. 内存不足时允许用户选择降低尺寸、减少帧数、降低批量；任何影响结果的调整都在提交前显示实际参数。采样步数不作为主要解决显存不足的手段。
5. OOM 后尝试释放当前任务资源并恢复引擎，自动降档最多重试一次，且仅对本地任务适用。保留原参数及降档原因。
6. 测量阶段细分翻译、加载、采样、解码/编码、保存，记录峰值 RSS/VRAM；常规诊断默认不记录提示词。
7. 加速与画质共同评估：固定种子至少 4 个、固定提示词和参数，再比较耗时、稳定性、清晰度、闪烁与主体一致性。保留当前可用配置作回退。
8. 更大视频模型作为独立实验模块，先审核硬件、许可、依赖与实测结果；本机 4GB 不默认安装未经验证的重模型。插帧与超分单列耗时、占用和处理方式，不把插帧当成新增原生运动内容。

验收：稳定档连续图片生成 20 次、短视频 10 次无 OOM；混合聊天/语音/媒体场景至少持续 2 小时。以固定基线报告成功率、p50/p95 耗时和峰值占用；不预先承诺生成提速百分比。

## 9. OPT-06：真实进度与统一任务中心

1. 对接 ComfyUI WebSocket 的执行节点、采样步数与错误事件，断开时退回 HTTP 查询；事件必须关联 prompt_id，不能显示其他客户端的进度。
2. 翻译、加载、采样、编码、下载分别显示当前阶段。只有有明确分母的阶段显示百分比；预计完成时间来自同硬件、同参数历史分布，读数不足则只显示已用时。
3. 引入全局任务状态，弹窗只作为视图。关闭后继续执行，重新打开、切换对话均能找回任务；任务中心提供有限队列、停止、失败原因和重试。
4. 检测、重启、保存配置与生成使用独立的界面状态，避免一个 busy 同时代表不同操作；连接错误不继续被空 catch 隐藏。
5. 云端“自动”模式提交前显示实际使用的引擎、是否联网及配置可得的预计费用；费用未知时说明未知。

验收：关闭并重开弹窗、切会话、WebSocket 断线恢复、后台完成通知均与服务端一致；不出现假的全程百分比和无来源的剩余时间。

## 10. OPT-07：作品管理与播放

1. 统一图片与视频作品索引：任务 ID、原文/英文、来源、模型与工作流版本、种子、参数、耗时、文件校验值和创建时间。默认只存本地，允许删除提示词记录。
2. 支持重用参数、固定种子、复制译文、打开目录、筛选与缩略图；对话卡片与弹窗引用同一作品记录。
3. 视频改为受限的本地媒体读取端点，使用短期令牌与产物白名单、支持 Range 请求，减少 base64 整文件复制。不得开放任意磁盘读取。
4. 检查删除文件后失效的记录和缩略图；索引与作品备份分开选择，避免用户以为只备份数据库就包括所有视频。

验收：超过 32 MiB 的有效 MP4 可在应用内播放与跳转，播放内存不随文件大小整份复制；未授权路径与目录穿越被拒绝；参数复用完整。固定种子仍可能因依赖、设备差异产生非逐字节一致的结果，需要记录运行版本。

## 11. OPT-08：云端接入

1. 将常用服务商做成有版本的配置预设，保留高级 JSON 模板；普通界面只填写必要字段，复杂请求取值路径放高级设置。
2. 提供“检查配置”“连接测试”“生成最小样本”三种不同动作；连接测试成功不能显示成生成能力已验证，付费样本明确提示。
3. 独立记录认证方式、可用模型、尺寸/时长组合、提交/轮询/取消/下载契约。当前客户端固定 Bearer 的行为不能被描述成任意服务商都已适配。
4. 用户提供有效账号后，每个正式支持的服务商完成真实英文与非英文样本、失败响应、超时和结果解码验证；其他只标记实验配置。
5. 云端翻译两家也分别进行真实 Key 实测，核对语种、数量、否定和错误切换，保留脱敏回执。

验收：默认预设至少一家通过真账号完整出片后才标记已验证；没有账号时保留“契约测试通过、真实服务待验证”。

## 12. OPT-09：桌面密钥与诊断

1. 使用 Windows DPAPI 当前用户范围加密凭据，密文保存在选定 D 盘数据目录；配置继续只存凭据引用。保留从环境变量读入的兼容方式。
2. 迁移前列出由本软件管理的变量，仅迁移用户选择的项。成功读取加密凭据后再提供清理旧用户环境变量的选项，不能删除其他软件依赖的变量。
3. 外部引擎子进程按需要传递最小环境，避免继承无关服务商密钥。
4. 扩展现有 self-check/diagnostics，提供用户主动导出的脱敏诊断包：版本、指纹、硬件、模型清单、目录可写性、错误码、阶段耗时。
5. 默认不含聊天、原始提示词、语音、作品、密钥和签名 URL；导出前展示包含项。机器绑定加密的凭据不作为可移机备份，换机器后重新填写。

验收：当前用户正常使用；其他用户及另一台机器不能直接解密该默认凭据文件；迁移失败可回退；报告扫描和伪造错误回显测试均不泄露假密钥。DPAPI 不被描述成能抵御当前用户权限下的一切恶意程序。

## 13. OPT-10：交付、升级与回退

1. 提供“程序”“基础聊天模型”“生图/视频引擎与模型”“手机端”独立模块，以及仍可离线安装的完整包。不要通过删除必要依赖盲目缩包。
2. 模型按内容校验值复用，默认更新程序时不重复下载模型；初版先做程序增量模块替换，再评估文件级差分的收益与维护成本。
3. 稳定的 D 盘启动器或 current 入口管理各版本，桌面快捷方式指向稳定入口，避免每轮手动改 rNN 路径。
4. 升级流程：下载到 D 临时目录→校验来源、签名和哈希→停止自有服务→备份配置/数据库→安装到新目录→自检→切换入口。失败回到前版；新数据库迁移不能直接交给不兼容旧程序，需恢复对应备份。
5. 更新保持用户主动触发；初次安装提供 D 盘路径选择、WebView2/显卡驱动/空间预检，开发者机器通过不替代干净机测试。
6. 程序包与更新清单加入可验证签名；Windows 可执行文件签名作为分发专项。签名材料不进仓库与普通交付包，取得证书等外部流程单独安排。
7. 清理最后执行：只有新版本启动、生成与回退检查通过后，旧产物才进入可清理名单。保留当前和一个回退版；应用数据、作品与模型不随旧程序删除。
8. 应用“关于”显示发行轮次、功能版本、源码指纹、实际程序路径与数据目录，直接回答“桌面这版是不是最新”。

验收：只改界面时更新内容不含未改变的模型；断网、下载中断、校验失败、迁移失败、启动失败都可恢复；非管理员干净 Windows 环境安装与升级成功；桌面快捷方式在升级后仍有效。

## 14. OPT-11：对话、语音、知识库专项

以下为下一阶段审计与增强，不能把尚未评估的能力认定为当前缺陷。

- 对话：建立工具路由与自然语言生成参数回归集，测试多轮上下文、否定指令、切换模型、取消流式回答、同一请求重复执行。高影响操作继续遵守现有执行确认设计。
- 语音：分别测量唤醒命中/误唤醒、识别结束到首段回复、朗读中断和回声重触发；先定位瓶颈，再决定是否引入流式识别或新 TTS。默认不为评测保存私人录音。
- 知识库：建立含来源页码/片段、相似文档、旧版本与无答案问题的问答集，测检索 Recall@k、引用正确性和无依据回答；先审计当前召回再决定嵌入/重排方案，原文与索引删除分别处理。
- 桌面控制：README 明确 OCR/浏览器底层没有完整接入聊天工具表。按读取→规划→预览→执行验证逐步接入；“能截图”不能等同于“能可靠自动操作任意软件”。
- 数据：补用户可理解的备份/恢复流程，采用数据库一致性快照，区分聊天配置、知识索引、原始资料与媒体作品；在新目录恢复后核对数量和抽样内容。

验收：每项先提交现状基准与失败样本，再给提升目标；无基准的指标不承诺百分比改善。大型新模型与自动化能力单独评审，不挤占 P0 修复。

## 15. OPT-12：维护、测试与发布证据

1. 逐步拆分职责：`desktop.py` 本轮约 5057 行，`image_gen.py` 约 1488 行，`video_gen.py` 约 872 行；先提取媒体桥接、任务控制、引擎适配和产物访问边界，不做一次性大重写。
2. 视频服务通过公共接口访问引擎、配置和任务，减少直接访问图片服务 `_cancel/_active_base/_environ` 等私有字段。
3. 统一任务与桥接数据契约，减少前后端手写字典的偏差；参数范围和错误码有同一份定义或一致性检查。
4. 固定引擎、自定义节点、推理运行时、模型版本及校验值，保存运行依赖清单和许可；仅有哈希不足以说明版本兼容和分发许可。
5. 分层测试：快速契约/并发回归；打包自检；双入口真机；真账号云端；干净系统安装。既有静态检查与测试保留；跳过项写明原因，fake 通过不标为真实生成成功。
6. 增设媒体基准命令，输出 JSON/HTML 到 D 盘 qa；每份回执包含版本指纹、环境、参数、开始/结束、结果与限制。正式发布绑定唯一回执，不只维护手写测试总数。
7. 统一能力矩阵作为 README、交付说明和界面提示的依据，扫描旧轮次、旧包大小、过期能力文案。长运维日志保留历史，但与当前安装说明分开。
8. 公开代码沿现有 `public-main → origin/main` 流程；排除商业材料、真实配置、用户数据、模型权重与凭据，并机器比较功能源码是否一致。

验收：主链路不改变时，职责拆分前后端到端行为一致；每个候选包可追溯到源码与测试回执；发布检查能拦住错误指纹、隐私文件、失效模型和过期说明。
