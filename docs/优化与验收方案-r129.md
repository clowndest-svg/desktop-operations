# r129：历史检索、置顶与完整导出

2026-10-26，从已交付 r128、干净开发工作树 `42eb159` 开始。保留现有聊天、人物、语音、图片、视频及手机功能。

## 审查结论与本轮范围

| 发现 | 处理 | 验证 |
|---|---|---|
| 历史入口只取最近 50 场，没有下一页和全文检索 | 本机标题/正文搜索、命中片段、每页 50 场及加载更多 | 超过 50 场的旧记录可检索、分页无重复、特殊字符按原文匹配 |
| 常用会话被新消息挤走 | 持久化置顶、只看置顶，置顶不修改聊天时间 | 旧库迁移、重启保留、取消置顶、缺失记录报错 |
| 列表先连接并统计所有消息后才 LIMIT | 排序索引先取一页，再利用消息索引统计本页 | 大样本查询耗时和查询计划对比 |
| 状态刷新反复读取最近 200 场，较早的已打开对话丢失统计 | 仅按当前打开的 ID 读取标题、时间、轮数 | 超过 200 场后打开旧对话，统计仍准确 |
| 导出调用界面 200 条消息接口，旧会话标题也受最近 50 场限制 | 独立完整快照读取标题与消息，导出文件独占创建 | 260 条以上消息、旧标题、并发同名导出及读取失败 |
| 搜索/加载与删除可能交错，原改名依赖原生 prompt | 请求序号拒绝旧结果；筛选清除勾选；全选明确只含已加载；内联改名 | 实际页面操作、慢请求与错误返回、窄窗口 |

搜索在本机数据库执行，不调用模型或云服务。中英文按子串匹配（英文 ASCII 忽略大小写），支持 `%`、`_`、引号等原文；关键词最长 200 字。全文子串搜索仍需扫描候选消息，不将其宣称为全文索引。

## 扩展取舍

历史检索与复用作为本轮完整实现。云端同步需要账号与服务端设计；重型本地模型受 4 GB 显存限制；工作流事件触发需要单独梳理事件生命周期。这些方向保留为后续建议，不把占位按钮计入本轮功能。

## 已取得的开发验收证据

- 合成 2,000 场 / 400,000 条消息，SQLite 内存库预热后 7 次中位数：旧列表 413.203 ms，新列表 1.688 ms；旧快照统计最近 200 场 387.849 ms，现只统计 3 个已打开会话 0.071 ms。这是查询基准，不代表所有电脑上的界面耗时。凭据：`reports/audit-r129/benchmark.json`。
- 实际 pywebview 源码窗口验证：旧记录分页、正文片段、筛选清勾选、置顶、内联改名、262 条完整导出、420 px 窄窗、取消/确认删除、慢搜索返回不能覆盖新搜索、打开失败留在历史页。发现并修复历史弹窗被聊天容器裁切的问题，改由页面顶层显示。
- 首次全量检查期间并行重建前端，导致图标测试读取 `index.html` 时该文件正被重建而失败；这次结果不作为最终门禁。最终门禁串行执行，期间不改源码或重建前端。
