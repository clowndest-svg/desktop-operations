## 0. 现状（逐条回源，不是估计）

### 0.1 宠物这一屏是怎么来的

| 事实 | 证据 |

| 两扇窗：pywebview 的渲染窗（被挪到屏幕外）+ 一个自建 Win32 分层窗吃 PNG | `jarvis/ui/pet.py:511`（`?mode=pet`）、`jarvis/ui/compositor.py:945` `AlphaWindow` |

柴犬 12 段  Attack Eating Gallop Gallop_Jump Idle Idle_2 Idle_2_HeadLow
            Idle_HitReact1 Idle_HitReact2 Jump_ToIdle Walk Death
狐狸 12 段  （同一族）

小法师 15 段 Punch PickUp RecieveHit RecieveHit_2 Roll Run Spell1 Spell2 Staff_Attack …
牧师 11 段  同一族（含 Spell1、RecieveHit）

而 `frontend/src/avatar/gallery.ts:45-48` 的 `pickClip` **只挑 `Idle`**（退一步挑名字里含
idle 的，再退一步挑第一条），`:104-107` 播完就一直停在那。全仓没有第二处 `clipAction`，
也就没有换段、没有 crossFade、没有定时器。

**这条决定了本轮的性质**：不是"给宠物做动作"，是"把已经在文件里的动作接出来"。
不用新美术、不用联网、不增大包。

### 0.3 设置那一格现在有什么

`frontend/src/components/SettingsPanel.vue:604-613`：只有一句 `petSummary` 文本 + 一颗
「生成或换」按钮。**没有任何大小/缩放开关**。宠物相关偏好键只有两个：
`pet.enabled`（bool）、`pet.figure`（str）（`jarvis/app/preferences.py:355,363`，注册在 `:403-404`）。
新增一个键必须同时改：常量 + `PREFERENCE_TYPES` —— 因为 `Preferences.set:588-591`
对未注册的键只写一条 warning 然后回 `False`，**看着像存住了**（这条已经踩过两次）。

### 0.4 界面那两条

- **文字被遮挡**：`styles/hud.css:411 .hud-field` 从头到尾**没有宽度规则**，35 处输入框
  （6 个组件）全在吃浏览器默认的 ~170px。中文 placeholder 排开要 200+px，于是"要达成什么，
  例如「把 C 盘清出 10G」"必然画不完 —— 用户看到的是"被按钮挡住了"。
  这不是那一处的问题，是**所有**输入框的问题，所以本轮不用手改一处，改成量一遍。
- **自动化那一屏**：顶部一行术语统计 + 两颗语义不同的按钮（`刷新`=重读现状、
  `重新读取`=让后端重扫 workflows 目录）+ 三段常驻解释，而且上一颗按钮留下的
  `重新读取：0 个工作流` 会**跨页签活着**挂在最顶上（`AssistantPopup.vue:472-479` 的
  `select()` 清了二次确认条，没清 notice）—— 于是它看起来像这一屏的标题。

## 1. 方案

### 1.1 大小：四档，不是一根滑杆

新增偏好键 `pet.scale`，取值 `small / normal / large / giant` 对应倍率 `0.75 / 1.0 / 1.35 / 1.7`，
默认 `normal`。基准 420×640 不变，窗口尺寸 = 基准 × 倍率。

**〔我定的〕用四档而不是滑杆**：用户要的是"设置做简单一些"。滑杆要多一步精确操作、
还要理解百分比；四档一眼看完一次点中，而且**每一档旁边能写实测数字**（见 1.5）。
代价是想精确到 1.1 倍做不到 —— 我认为这个代价可以接受。

- 改尺寸时**底边中心不动**（她站在桌面上，缩放不该让她飘走或钻进任务栏）。
- 前端 canvas 是 100% 视口，所以尺寸一变，渲染分辨率自己跟着变，不需要前端第二份真相。
- 分层窗的 rect 从渲染窗抄，所以只有一条路径要改。

### 1.2 点击互动：接 HitReact，不新做动作

点身体一下 → 播这一只模型的"受击/反应"段（`Idle_HitReact1/2`、`RecieveHit`、`HitRecieve`
按名字族匹配），同时气泡出一句短话；**连点**有冷却（同一句不重播、动作不排队），
拖动过程中不算点击（沿用 `GRAB_SLOP=6` 那条已有判定）。

**〔我定的〕反应句是本地写好的几句随机，不走模型**：一次点击换一次模型调用 = 花钱、
慢 2~5 秒、还可能答非所问；"被戳一下"要的是**立刻**。模型那条路留给用户真的跟她说话。

**〔我定的〕不选"点两下打开主界面"**：主界面已经有托盘、热键、顶栏三个入口，
再给宠物加一颗会误导成"点她=叫她出来干活"，而本轮的点击语义是"逗她"。

族匹配规则（写死在源码注释里，因为它是判据本身）：

| 用途 | 取段顺序 | 找不到时 |
| --- | --- | --- |
| 待机 | `Idle` → `Idle_*` → 第一条 | 不动（全息/VRM 走 mood） |
| 点她 | `*HitReact*` → `RecieveHit*` → `No` → 待机段 + 抖一下 | 只出气泡 |
| 自己动 | `Dance` / `Yes` / `No` / `Jump` / `Eating` / `PickUp` / `Spell1` / `Walk` / `Bite_Front` 里随机 | 退回待机 |
| **永远不自动播** | `Death`、`Attack*`、`Gallop*`、`Run` | —— |

**〔我定的〕`Death` 与攻击/奔跑类不进随机池**：定时蹦一段"倒地死亡"或"挥拳"，用户读到的
是"她怎么了/她在干嘛"，跟"简单动作"是反的。跑/奔腾需要位移，而她的位置是钉在桌面锚点的，
播完会站在奇怪的地方。

### 1.3 每隔一段时间自己动一动

一个前端定时器（**不加新线程、不加新帧**）：每 25~70 秒随机挑一段"自己动"池里的动作，
播完 crossFade 回待机。以下情况**不触发**：正在说话（那 30fps 是她的台词）、正在被拖、
窗口隐藏/最小化到托盘、用户关了那颗「她会自己动一动」。

**〔我定的〕随机区间取 25~70 秒**：更短会变成"抽搐"，更长就跟没有一样。真机跑起来如果觉得
烦，那颗开关就在设置里，不用改代码。

### 1.4 VRM 与默认全息那条路

这两套不是 .glb clip，是 `driver.ts:41-52` 的六档 mood pose。给它们一个**同一语义**的实现：
定时在 mood 之间轻移一次，点击时插一次"晃一下"的姿态偏移。这样"点她/她自己动"对三种形象
（内置 .glb、照片生成的剪影、VRM）都成立，而不是只对 11 只内置模型成立。

### 1.5 设置那一格顺手做简单

现在那一格只有一句摘要 + 一颗按钮，本轮加东西的同时**不减反增**是危险的，所以：

- 「大小」四档 + 每档一句实测（见 1.6）；
- 「她会自己动一动」一颗开关；
- 其余说明文字**从三行压成一行**，细节收进鼠标悬停；
- 位置记住（拖到哪，下次开还在哪）—— 这条是"大小可调"的自然搭档：能改大小的人必然也想
  改位置，而重启就回中点是会让人骂的。

### 1.6 数字必须实测，不能写"更吃 CPU"

`特大档更吃 CPU` 这种话不算信息。本轮真机量四档各 30 秒的进程 CPU（psutil 两种口径都记），
把**当轮那台机器的读数**写进设置那一格和本文件 §5。量不出来就写"没读数"，不许抄上一轮。

### 1.7 界面那两条

- **输入框**：先在全量屏上量（`need` = placeholder 按控件自身字体排开要多宽，
  `room` = 内容区实宽，`covered_by` = 从右端打 `elementFromPoint` 命中了谁），
  一次把 `.hud-field` 的宽度规矩定下来（`min-width:0` + 表单里 `flex:1 1 260px`），
  修完复量，**目标是 bad 列表为空**，不是"截图那一处好了"。
- **自动化那一屏**：术语统计拆进两个小节标题；两颗按钮并成一颗「重新读取」
  （重扫目录 + 重读现状，一次点完全好）；notice 换页签就清掉；三段解释只在需要时说
  （空状态说"下一步做什么"，有内容时不再啰嗦）。**不删任何门、不删任何能力**。

## 2. 爆炸半径

动的：`pet.py`（尺寸/锚点/点击分发/位置持久化）、`compositor.py`（点击事件带出到 controller，
不改穿透判定）、`gallery.ts`/`PetStage.vue`（换段、反应、定时器）、`driver.ts`（mood 那条路）、
`preferences.py`（新键 3 个）、`desktop.py`（新门 2~3 扇）、`SettingsPanel.vue`（那一格）、
`hud.css`（输入框宽度规矩）、`AssistantPopup.vue`（自动化那一屏）。

不碰：语音链路、唤醒、投屏、生图、文档生成、清理、告警、扩展市场（r108 刚做完）、
`config.yaml` 的读法、桥面参数名黑名单那一族。

风险最大的两条，先说清：

1. **CPU**：空闲本来就是主动 10fps 在烧。换段只改"画什么"，不改"多久画一次"，
   所以理论基线不变 —— 但**必须实测**，四档各 30 秒，写进 §5。
2. **点击与拖动的边界**：现在按下即开始拖，tap 判定靠位移阈值。加"点她"之后，
   误判的表现是"我想拖她结果她先打了个滚"。判据：位移 >6px 的那一次**只**算拖，不算点。

| B 点击 | **做完** | 发一次 react → 段名 `Idle` → **`Idle_HitReact1`**（冻结包里真换了段）；连点 4 下只说一句（1.2 秒冷却），动作照动 |
| C 自主动作 | **做完** | 读到 `Eating` —— 那 8 秒没人碰她，是壳的定时器放的；`Death/Attack*/Gallop*/Run` 一次都没出现；开关、说话、拖动、隐藏四条不触发路径各有单测 |

| E 界面返工 | **做完** | 输入框逐屏审计：修前 87 个框 / 报坏 62（真被裁 2，其余 60 是"弹窗开着、后面主界面被遮罩盖"这种假阳性，判据补了"两边在不在同一层"）；修后主屏 6/0 坏、自动化 7/0 坏。自动化那一屏：两颗按钮并成一颗、术语统计拆进小节标题、notice 换页签就清 |
| F 交付 | **做完** | 门禁 3785 passed / mypy --strict 383 文件；变异 14 条全杀；包 r109 全 CRC 绿、exe 自报 r109、快捷方式读回 |

**这一轮最贵的一条：换大小这个功能我自己写崩了。** 第一版是"关掉旧分层窗、按新尺寸重建一扇"，
打包版三次运行崩了两次（事件日志 `0xc0000005` / `0xc0000096` / `0xc000041d`，时间点都在
`pet_set_scale` 之后几秒）。根因：`close()` 只 join 两秒 —— 泵线程退了、窗口不一定被销毁，
WNDPROC 那个 ctypes 回调随对象被回收，系统再投一条消息就是这一下。
修法是**根本不重建**：那一层早就"跟着像素走"（帧尺寸变了自己重建位图，`UpdateLayeredWindow`
带新尺寸），换档只需要让页面视口变大 + `move_to` 挪一下锚点。提交 `7665b4f`。

**由此立一条规矩**（写进手册）：新代码只要碰"关掉一个 Win32 窗再开一个"，收尾必须
① 在打包版上把那个动作连做十次；② 查一次事件日志有没有新的 `小夜.exe` APPCRASH。
这种崩溃 Python 层看不见 —— 测试全绿 + 日志 0 ERROR 都抓不到它。

**没验到的**：① 真人拿鼠标点她身体那一下（CDP 到不了 Win32 那层，留给用户）；
② "演完一段自己回待机"没读到 —— 那 8 秒她正好自己演了 `Eating`，机制在（`LoopOnce` +
`finished` → crossFade 回 Idle），打包版读数没有；③ 拖动后重启位置还在：单测有，
