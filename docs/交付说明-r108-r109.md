## 四、我这一轮自己弄出来的问题（以及它是怎么被抓出来的）

**换宠物大小那次崩溃是我引入的。** 第一版实现是"关掉旧的分层窗、按新尺寸再开一扇"。
打包版跑了三次，崩了两次（Windows 事件日志：`0xc0000005` / `0xc0000096` / `0xc000041d`，
时间点都在改大小之后几秒）。根因是关掉那一层时只等了两秒：泵线程退了、窗口不一定被销毁，
而窗口过程那个回调对象跟着被回收，系统再投一条消息进来就是这一下。

**修法不是把等待时间加长**，是这条路根本不该存在 —— 那一层早就"跟着像素走"
（帧尺寸变了它自己重建位图）。现在换档只让页面视口变大 + 把窗口挪一下，
Win32 生命周期一条都不碰（提交 `7665b4f`）。

这条留下一个规矩，已经写进手册：**凡是新代码要"关掉一个 Win32 窗再开一个"，
收尾必须在打包版上连做十次，并查一次事件日志有没有新的 APPCRASH。**
因为这种崩溃 Python 层根本没看见 —— 测试全绿、日志 0 ERROR 都抓不到它。
