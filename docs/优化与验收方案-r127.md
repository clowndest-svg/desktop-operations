## 实施顺序

### 1. 代码与构建基线

- 独立审查完整开发差异和接手时未提交差异：逐行逻辑、删除行为、跨文件契约、语言/平台陷阱、包装器、复用、简化、性能、根因层次和项目规范。
- 每个候选问题核对真实触发条件；对确认的问题补回归测试，不依靠猜测重写代码。
- 使用既有 `scripts/run_gates.py` 运行 Black、Ruff、`mypy --strict jarvis tests`、全量 pytest、前端测试/类型检查/构建；记录命令、范围、耗时、失败及跳过原因。
- 检查前端依赖审计、Python 依赖一致性、未使用资源、错误日志，以及当前 APK 的签名/源码指纹。

### 2. 图片与视频

关键路径：`jarvis/app/image_gen.py`、`jarvis/app/video_gen.py`、`jarvis/app/media_prompt.py`、`jarvis/app/video_cloud.py`，以及相应 bridge 和前端弹窗。

- 延续关键帧后动态扩散的方向，查明噪声/粗糙画面的原因，使用同一明确模型、种子和参数对比结果，不以换样例掩盖问题。
- 图片检查尺寸、译文、主体与提示词关系；视频检查真实帧数/帧率/时长、抽帧画面与前后帧变化，避免“静态图片编码成视频”冒充生成效果。
- 通过实际软件入口生成中文描述的图片和视频；检查同一服务的聊天入口与弹窗入口。
- 验证取消、再次生成、共享 GPU 锁、错误恢复、显存不足提示，以及不误杀用户外部引擎。
- 云端适配跑完整契约测试；未提供实际账号时验证缺少凭据的明示行为，不能声称已消费真实云服务。

### 3. 形象、声音与桌面体验

关键路径：`frontend/src/avatar/`、`frontend/src/components/`、`frontend/src/audio/`、桌面偏好保存与 voice bridge。

- 逐一核对 20 个角色：待机、最大开口、眨眼、表情切换、面部配准与画面边缘；查看真实渲染截图。
- 用实际音频验证口型、云雾语音球及中断闭嘴；检查视线跟随开关和减少动态效果。
- 验证形象/推荐音色/自定义音色保存、失败回退、重启恢复；检查小窗口和手机网页布局。
- 打开主页的各类功能入口，检查搜索、关闭、键盘操作、空态与错误提示，不恢复旧版冗余按钮。
- 验证实际托盘/窗口退出路径、快捷方式指向和残留子进程；危险电脑操作只用无害测试或拒绝路径，不拿作者数据试删。

### 4. 独立买家运行时

复用 `scripts/place_bundled_model.py`、`scripts/place_media_engine.py`、`scripts/place_voice_models.py`、`scripts/derive_runtime_edition.py` 和现有完整性检查。

- 包含桌面依赖、llama.cpp 与量化模型、ComfyUI/独立 Python/CUDA Torch、SD1.5/AnimateDiff、视频编码、离线识别/VAD 权重、固定版 WebView2、adb/scrcpy 及第三方许可。
- 检查本机路径泄漏、虚拟环境启动器、Python/DLL 搜索路径、外部模型配置、用户数据和凭据排除。
- 组件缺失、模型损坏、构建身份不符或源码过期时拒绝完整包制作，不允许只有文件名就算完整。
- 不安装或替换用户显卡驱动；显卡与云账号要求在 UI 和文档中明确。

### 5. 最终产物验收

复用 `scripts/deliver_release.ps1`、`scripts/delivery_package.py`、`scripts/release_manifest.py`、`scripts/verify_android_release.py`。

1. 修复完成并冻结功能源码后，构建唯一新轮次 PC；有前端/原生变动则重新构建签名 APK。
2. 检查 exe 的 `ok/frozen/round/edition/source_sha256`，核对 APK 版本、签名及实际资源。
3. 按最终文档生成 ZIP，先临时文件再原子发布；独立完整 CRC 回读与 SHA-256。
4. 将该 ZIP 解压到此前不存在的目录，不使用作者数据，不把源码运行当成买家运行。
5. 从解压后的实际 exe 测试：冷启动、无 Key 本地聊天、中文图片/视频、离线预录语音识别、真实在线朗读、偏好与历史重启恢复、功能入口、错误处理。
6. 保存截图、生成样例、解码数据、日志与机器可读验收凭据；失败则修复、重建、重验，不发布已知失败包。

### 6. 文档、清理与 GitHub

- 更新 README、总览、本地图片和视频、桌面运维手册、分发说明、当前交付说明，以及 `闲鱼展示内容/` 下实际发给买家的说明和发货记录。

- 新包验收通过后更新实际桌面和开始菜单快捷方式，读回目标、工作目录、图标，实际启动确认。
- 先列清理清单，再清理确认废弃的旧构建、旧 ZIP、失效收据、临时副本、测试缓存和无引用资源。链接/联接、在用进程、用户数据、密钥、模型源与备份受到保护；清理结果有记录。
- 本地提交保留完整开发内容。公开树只能是最终源码减去商业材料和私密/运行时文件；复用 `public-main` 工作树，校验文件集合、内容与敏感信息后推送到 `origin/main`，回读远端 SHA。不得直接推送含商业历史的开发分支。

## 接手审计（2026-10-25）

逐条核对 Codex 会话 `01a16eca-92b1-7e71-be8f-b9701eede236`、构建日志和盘上产物后，确认未完成项不是“再点一次打包”，而是四处真实缺口：

1. **r126 构建产物早于最后一次视频修改。** `E:\DaiMa\XiaoYeBuild\r126\dist` 的时间是 12:36，视频关键帧代码在 13:14 才改；门禁日志只有 black 一行，PyInstaller 日志只有四行，说明最后一次构建和门禁都在中途结束。r126 交付 ZIP 只有一个被删掉的 `.partial`，从未完成。
2. **视频候选包的视觉检查确实不合格。** 旧流程从逐帧噪声直接采样，出现彩色噪声；新流程（512 px 关键帧 + 低强度动作）在本机 16 帧 / 256×256 / 8 fps 实际出片 162.6 秒，抽帧可辨认红鸟与树枝，无彩色噪声，但仍受 SD1.5/4GB 限制。
3. **人物素材只有 512×512。** 20 个角色的源图集是 1024×1536，制作脚本却缩到 512×512；桌面人物区域约 1000–1300 px，必然模糊。已改为 1024×1024 原生，默认角色基底 4096×4096、表情帧 2048×2048，画布按显示尺寸自适应并按正方形绘制。
4. **新增 `media_download.py` 没有被任何代码调用。** 图片/云端视频仍各自用旧读取逻辑，可能把截断媒体当成功。已接入两条下载路径并补 7 条边界测试；云端视频“重置为出厂默认”也被发现写空串而不是删键，已给 `Preferences.unset()` 并补测试。
