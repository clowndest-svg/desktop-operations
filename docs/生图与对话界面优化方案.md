# 生图与对话界面优化方案（r106）

用户实拍两张：① 生图弹窗里「画一个绿色瘦弱的哥布林」画的是一位动漫美女；② 对话里同一句
画对了，但气泡里那几颗按钮"太丑"，而且**对话框里鼠标不能做一点事** —— 文字拖不选、
右键没菜单，图片也复制不了。要求：参考微信的聊天框，整体排版和外观对比网上大量资源优化，
生图本身能升级的都升级，做完按流程收尾。

这份文档是方案 + 执行结果，数字都是这一轮在真机上量出来的。

---

## 一、先定位：弹窗和对话差的是同一层，不是同一个模型

| 路径 | 送进 `CLIPTextEncode` 的字 | 结果 |
| --- | --- | --- |
| 对话（模型调 `generate_image`） | 模型先把中文扩写成英文标签（r105 工具描述硬性要求） | 绿哥布林 ✅ |
| 生图弹窗（面板直调引擎） | **用户原话，一个字没改** | 动漫美女 ❌ |

代码位置：`jarvis/app/image_gen.py:541` 把 `prompt` 直接塞进工作流。SD1.5 的文本编码器
只认英文标签，中文整句对它约等于噪声 —— 所以这不是参数问题，是**弹窗那条路上没有翻译层**。

**修法**：把展开做在 `ImageService.generate()` 入口（`jarvis/app/image_prompt.py`，新），
面板和工具共用同一层。没有中文就原样返回 —— 模型已经扩写过的英文再被它改一次，
就是外行指导内行。

## 二、真机量出来的三条决定（每种走法 4 个种子，同一台引擎、同一权重、512x512、20 步）

判据不是"看着像不像"，是数像素。第一版只数**整张图**的绿占比，被自己骗了一次：
加了 "dark forest, moonlight" 的那一组分数最高，但那是一整张图被夜色染绿。
于是改成**中心 40% 与外圈分开数** —— 主体绿而背景不绿，才是"哥布林是绿的"。

| 送出去的字 | 中心绿 | 外圈绿 | 中心−外圈 | 判读 |
| --- | --- | --- | --- | --- |
| 画一个绿色瘦弱的哥布林（中文原话） | 0.0000 | 0.0005 | −0.0005 | 樱花下的动漫美女，零绿 |
| green goblin, green skin, thin | 0.05~0.16 | 0.12~0.15 | ≈0 | 有哥布林，绿得不实 |
| green goblin, green skin, **thin goblin** | **0.5212** | 0.1658 | **+0.3554** | 主体绿、背景不绿 ✅ |
| …thin, dark forest, moonlight, fantasy | 0.6897 | **0.7684** | −0.0787 | 整张均匀泛绿 = **背景**被染色 |

由此定下三条，都写进了代码注释和测试：

1. **属性要带着主体再说一遍**（`thin goblin`）—— 这是唯一让"主体本身变绿"的写法，
   所以展开层对前三个属性都这么做；
2. **不替用户编场景和风格** —— 第四行那个"更好"的分数是判据的陷阱，不是画面的进步；
3. **颜色贴着名词前置**（`green goblin`）+ 只对会动的东西补 `green skin`（给一座山写
   皮肤是噪声）。

顺带一条噪声标尺：B、C 两组**发的是同一串字**，4 个种子的中位数仍从 0.1328 到 0.1989。
所以任何"某写法更好"的结论，n=1 一律不算 —— r105 那次"我按 SD1.5 惯例加了质量词"
就是栽在没测就改。

## 三、鼠标这件事的根因不在 WebView2

`frontend/src/styles/hud.css:139` 的 `body { user-select: none }` 是给外壳写的
（拖一下标题栏就把整屏染蓝是灾难），它顺手把对话正文、思考过程、失败原因一起锁了。
手机端早就分开了（`mobile.css` 锁 body、放开输入框），桌面这边照同一条规矩补白名单：
`.chat__text`、`.chat__reasoning-text`、`.chat__art-name`、`pre`、`code` 可拖选。

右键：**pywebview 把 `AreDefaultContextMenusEnabled` 绑在 debug 上**
（`webview/platforms/edgechromium.py:288`），发布版里原生菜单根本没有 ——
所以不是"关掉原生菜单自己做"，是本来就没有。新增 `ContextMenu.vue` +
`composables/useContextMenu.ts`：一个对象一个菜单（微信那条），文字→复制选中/复制这段，
图片→复制图片/打开/所在文件夹/复制路径，文件→同一组。Esc、点外面、失焦都关；
上下键走、回车执行；贴边翻转。

## 四、排版按可量化规则改，不按感觉改

调研（微信 PC / Ant Design X / CopilotKit / Carbon / Material 深色 / WCAG 2.2）之后，
只落地能指到具体抱怨的几条：

| 改了什么 | 依据 |
| --- | --- |
| 附件从"一行名字 + 四颗会换行的按钮"改成一张卡片：角标 + 名字/大小两行 + 一颗主操作 + ⋯ | 微信"一个对象一个菜单"；文件消息右键是"更多打开方式"而不是摊按钮 |
| 小按钮字号 10px → 12px，高度统一走 `--hud-control-h`（26px） | 9–10px 在任何设计体系里都不存在；WCAG 2.5.8 最小命中 24×24 |
| 缩略图 320 → 260px，圆角收成 8/12 两档 | IM 会话内缩略图通行 240–280；圆角多一档就开始像拼凑 |
| 气泡靠说话人那一侧的角收小（`4px 12px 12px` / 镜像） | 微信/iMessage/Ant Design X 的 `shape="corner"` |
| 新增 `--hud-edge`（42% 强调色）与 `--hud-surface`（比背景亮一层的"面"） | 原 `--hud-line` 合成后只有 1.5:1（非文本元素要 3:1）；"层次"原来是黑阴影投在近黑底上 = 没有层次 |
| 用户气泡那两块写死的 cyan 改成 `color-mix(… var(--hud-cyan) …)` | 皮肤只动色相 token，写死一套色会在琥珀/玫瑰皮肤上留下不属于任何皮肤的一块蓝 |
| `.chat__tools` 去掉 `opacity: .75` | 叠在 `--hud-dim` 上约 4.0:1，正好掉在 AA 线下；分层靠字号不靠半透明 |
| 对话正文 `line-height: 1.65`、13px | 对话列是"读"的地方 |

**没做的一条**：微信那种"5 分钟一段"的居中时间戳。`ChatTurn` 里根本没有时间字段，
加一列要迁移对话库 —— 它不在这次的抱怨里，不该顺手改数据结构。

## 五、生图其余的升级

- 面板上写明**引擎实际听见的那句**英文，以及"这几个词没翻出来：X、Y"。
  （r110 更正：这一句当时写的是「原样留下了」，而「原样」= 把汉字逐字拆开拼进提示词，
  等于往引擎耳朵里灌噪声。现在改成**点名但不塞进去**。）
  悄悄改写用户说的话，就算结果更好，也无从调试。
- 等待期间显示"已经等了 N 秒"。引擎只在跑完那一刻给结果，中途没有任何百分比可读，
  所以不假装知道进度 —— 只把"它没死"这件事说出来。这一轮在这台 1650 上连画 24 张，
  实测 24.5~26.6 秒一张；用户那张实拍是 67.1 秒，**为什么慢这一次没量**。
- 附件卡片第二行补了大小与时间，走新门 `artifact_stat`（收束和读图同一道：
  不在软件自己产出的目录里就不给，拒绝时一个数都不漏）。

## 六、验证与还剩的账

- 全部门禁：black / ruff / `mypy --strict`（360 文件 0 错）/ **pytest 3545 passed, 5 skipped** /
  vue-tsc + vite build。
- 变异 `mutate_r106.py` **12 条全杀**。第一版 10/12，两条活着，逐条回源后一条是**等价变异**
  （去掉 `has_chinese` 短路后英文输入的输出完全一样 —— 词典全是中文键，匹配不到就原样退回），
  换成了"颜色不贴着名词"；另一条是**真测试漏了**：`"green mountain" in prompt` 这种
  "含不含"的判据放走了"去重只去完全相同的"，改成钉整串相等才杀掉。
- 打包版真验（CDP，同时只许一个实例）：真派发 mousedown/move/up 拖一次选字、真派发
  `button:'right'` 开菜单、点掉一项后用 ctypes 从 Windows 剪贴板把文字读回来逐字比；
  从页面调 `image_generate('画一个绿色瘦弱的哥布林')`，断言引擎收到的是英文标签，
  再把盘上那张 PNG 的中心/外圈绿像素量出来。

还欠的：

1. **词典覆盖不到的中文**：内置 569 个词（`capabilities()` 现数，界面上那句也是从它读的），
   认不出的在屏上点名、但不进提示词（r110 改的，理由见上一节）。要更全有两条路
   —— 接一个中英提示词库，或在面板上加一颗"让她先扩写"（走模型，本地 4B 那一次要 130~300 秒）。
2. **真模型会不会自己选对工具**：链路是真测的，模型那一下仍没测（要占一张 4GB 卡或你本人的钥匙）。
3. 「跟着手机转」仍欠一次横竖屏测量（第 98 轮起挂着）。
