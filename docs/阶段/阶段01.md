## 3. 架构说明

### 3.1 核心抽象:`LifecycleComponent`(Protocol)

所有子系统(配置、日志、LLM、唤醒词、ASR、TTS、Agent、UI……)统一实现
`name / start() / stop()` 三元契约,由 `Application` 按注册顺序启动、逆序停止。

设计决策:

| 决策 | 理由 |
|---|---|
| 用 `Protocol` 而非 ABC 基类 | 结构化类型,子系统零继承耦合(依赖倒置,符合 Clean Architecture) |
| 启动失败自动回滚已启动组件 | 保证不会留下半启动的僵尸资源(音频流、端口、DB 连接) |
| `stop()` 幂等、逆序、永不抛出 | 关闭路径必须绝对可靠,单组件故障不阻塞整体退出 |
| 组件重名拒绝注册 | 日志与错误定位的唯一性保证 |
| 状态机 `AppState` 五态 | 后续托盘图标/UI 状态展示直接复用 |

### 3.2 入口设计

`__main__.py` 只做三件事:解析 CLI → 装配组件(目前为空)→ 驱动生命周期并返回退出码。
引导期使用标准库 `logging`,阶段四的完整日志系统将以组件形式替换它。
