# 小夜：闲鱼买家版交付与兼容优化方案

版本：2026-10-15；现状基于 r118。本文替代同日首版方案的产品定位、优先级与实施排期。所有新增行为均是待实施设计，不代表当前软件已经具备。

## 1. 产品目标与边界

主目标：作者双击 `D:\AI\闲鱼展示文档\生成交付包.bat`，得到一个通过检验的买家完整包；买家解压后启动，无需安装 Python、Node、Git、ComfyUI 或手工下载基础模型。默认能力不依赖作者账号、作者 API Key、开发机环境变量、网络共享或作者电脑在线。

关键要求：

1. 作者日常使用与买家默认环境物理隔离，采用相同功能内核，但配置、历史、密钥、模型选择、硬件测量、端口、升级渠道分别管理。
2. 同一个默认完整包服务高低配置买家。首次启动自动检测和选择已验证的档位，不让买家先学习显存、模型量化和引擎安装。
3. 本地基础能力随包提供；联网和云端服务属于明确的可选项，使用买家自己的账号和额度。
4. 解压即用承诺覆盖经过验证的系统与硬件，不承诺任意电脑都能本地生视频。无适配显卡也应能启动、聊天、查看作品和理解不可用原因。
5. 作者机器新增模型、缓存、构建、测试内容继续全部进入 D 盘。买家路径采用相对目录与非系统盘策略，不写死作者的 D/E 盘位置。
6. 不新增必须连接作者服务器的激活、账号或在线验证作为首次使用前提；授权系统如以后需要，应独立设计。

建议销售能力按“基础离线对话”“兼容硬件本地生图/视频”“可选联网服务”说明。现有 Edge-TTS 需要联网，离线朗读或音色复刻没有随包可用并实测前，不承诺所有语音功能完全离线。

## 2. 本轮核对出的现状差距

| 现状 | 具体证据 | 需要补足 |
|---|---|---|
| 固定入口已存在 | BAT 调用 `scripts/build_buyer_package.ps1`，再调用 `deliver_release.ps1 -Build` | 保留入口，增加明确的 buyer 构建配置与验收 |
| 有打包、校验和隐私检查 | 现有脚本包含自检、源码指纹、模型检查、ZIP CRC、禁止用户数据文件等 | 继续扩展，不能重新另写一套绕过既有检查 |
| 作者正在用交付构建目录 | 桌面快捷方式指向 `D:\AI\XiaoYe\build\r118\dist\小夜\小夜.exe` | 独立 author 运行目录；生成买家包不能切换作者快捷方式 |
| 环境隔离不完整 | `bundle_data_root` 优先保留外部 JARVIS_HOME，兼顾旧 AppData 数据；媒体服务还会自动找常见端口 | 买家版独立数据策略，不自动接入作者/旧安装目录或未知引擎 |
| 已有模型自适应基础 | `local_server.py` 有 0.6B/1.7B/4B/7B 卡片与内存门槛 | 从内存估算扩展为 CPU 指令、可用 RAM、真实速度与任务成功率 |
| 当前媒体运行时有固定硬件路线 | 引擎源码中的 torch 为 `2.8.0+cu126` | 不能只按显存判断所有 NVIDIA 都兼容；需架构、驱动与小任务实测 |
| WebView2 只检查注册表安装 | `runtime_check.py` 缺失时提示买家自行下载安装 | 为完整包集成随包运行时与对应探测，减少外部安装依赖 |
| 本地真机样本主要来自作者电脑 | GTX1650 4GB、约16GB RAM；高档视频参数有外推 | 为不同配置建立真实兼容矩阵，未实测的不得标认证 |
| 发布产物部分依赖源文件硬链接 | `place_media_engine.py` 优先 `os.link` 复制运行时与引擎文件 | 发布快照不能被可变开发引擎原地写入影响 |
| 翻译与取消存在已复现问题 | 德语误判英文、非英文拉丁文本被当译文接受；新请求清除旧取消位 | 作为买家版发布阻断项修复，详见首版技术审计 |

这些差距不能通过“把自己正在使用的目录压缩发给买家”解决。

## 3. 作者版与买家版隔离设计

### 3.1 共用代码，分别运行

不维护两套容易分叉的功能代码。用不可变的发行元信息区分 author/buyer、版本、源码指纹、资源版本和更新渠道；可写用户设置不能随意把买家版切成作者环境。

| 项目 | 作者日用版 | 买家交付版 |
|---|---|---|
| 使用入口 | 作者专用桌面快捷方式 | 包内“启动小夜”入口；可自行创建买家快捷方式 |
| 运行根目录 | `D:\AI\XiaoYe\author\` 下的独立安装 | 买家自行解压的目录，相对定位 |
| 数据 | 当前原数据目录继续保留，验证后可选迁移 | 本安装的 `用户数据/`；新包首次为空 |
| 密钥和模型设置 | 作者原有设置 | 出厂无密钥、无作者网关、无作者模型偏好 |
| 硬件档位 | 作者机器的测量 | 买家首次测量，禁止复制作者的测量结果 |
| 引擎 | 作者专属实例 | 本安装专属实例，不默认接管作者的8188端口 |
| 更新 | 测试/作者渠道 | 稳定买家渠道 |
| 调试 | 作者主动启用 | 默认不开放调试端口、不显示开发配置 |

作者目录建议：

```text
D:\AI\XiaoYe\
  author\                 作者日用程序、稳定启动入口
  build\buyer\rNN\       构建与打包暂存，不用于作者日常使用
  qa\buyer\rNN\          测试解压副本、回执与脱敏截图
  resources\              作者维护的模型/运行时来源
D:\AI\闲鱼展示文档\
  生成交付包.bat           保持现有入口
  小夜-电脑+手机-rNN.zip   仅通过全部交付检查后生成
  校验-rNN.json
  发货记录.txt
```

路径为设计示意，不要求立即迁移原文件。迁移作者快捷方式之前先验证作者版可读取原数据，原数据不删除。

### 3.2 买家目录与配置

完整包继续保持单次解压。建议逻辑布局如下，可在实现时兼容现有 `小夜/小夜.exe` 路径：

```text
先看我一页.txt
小夜/
  启动小夜.exe             或复用小夜.exe，入口无需Python/PowerShell
  程序/                    主程序及依赖
  模型/                    已验证的随包聊天/翻译模型
  本地引擎/                便携Python、ComfyUI、图片与视频模型
  运行库/WebView2/         固定版本运行时
  用户数据/                首次运行创建，不携带作者数据
  发行清单.json
手机/                      Android APK；与PC版本分别标识
文档/                      买家说明、配置范围、第三方许可
```

买家配置优先级：本安装显式配置→随包 buyer 默认值→硬件检测结果。系统 JARVIS_HOME、开发机缓存变量、旧 AppData 数据和外部模型地址不自动作为导入依据；高级“导入旧数据/外部模型”必须由用户主动选择。

保留 SystemRoot、驱动等必要系统环境；隔离的是应用配置与凭据来源，不是清空整个 Windows 环境。不要为了便携运行改写系统级 PATH 或注册全局 Python。

### 3.3 进程和资源所有权

- 首次运行生成本安装的 instance_id，不在出厂包预生成统一身份。二次启动聚焦已有窗口；不同安装不误认作同一实例。
- 记录自有子进程 PID、创建时间、端口和健康状态，必要时辅以启动随机标记；结束与重启仅作用于自身实例，不能只按进程名杀进程。
- 端口冲突自动换端口并回传实际地址。默认仅监听 loopback；手机配对等需要局域网的能力单独开启并沿用认证设计。
- 同一主机不同版本/作者买家同时运行，数据和状态必须隔离；GPU物理资源仍共用，需要检测冲突、排队或解释，不能声称目录隔离就没有资源竞争。
- 模型可从受控只读资源库复用；配置、缓存、引擎用户目录不能硬链接共享。可变运行时代码不得跨作者/买家硬链接；出货压缩包与验收解压副本必须对应冻结的内容校验值。

## 4. “解压即用”的首次启动

### 4.1 首次启动流程

1. 检查程序完整性和实际解压目录；检测 ZIP 内直接运行、文件缺失、只读路径、受保护目录和空间不足，给具体的下一步。
2. 在初始化会写缓存的第三方库之前确定用户数据、临时文件、WebView2 用户目录和引擎目录。
3. 探测操作系统/架构、CPU指令、可用 RAM、GPU厂商/型号/架构/显存/驱动、磁盘与随包运行时。
4. 先显示轻量界面与可理解状态，后台加载基础能力；每个重模型按需加载，不在启动时同时占满内存。
5. 根据可用内存选择一个已验证的小模型，完成最小健康检查；基础聊天不要求买家注册云账号或填 Key。
6. 媒体引擎第一次使用时执行短小的真实健康检查，再决定本机生图/视频的可用档位；硬件检查失败只降级对应功能，不拖垮主程序。
7. 显示“本机可用功能”页面：可用、需联网、需买家账号、当前不支持。普通用户直接开始聊天，高级硬件参数收起。

首次配置默认无需选择几十个参数。可选创建桌面快捷方式；开机自启、常驻麦克风、局域网服务和遥测上传不作为默认行为。

### 4.2 WebView2 与运行库

为完整包优先评估并集成随包 Fixed Version WebView2，启动时指定其位置。同步修改目前“只看注册表”的检测逻辑，先验证随包运行时能创建窗口，再考虑系统 Evergreen；不能只复制文件就认为完成。

Fixed Version 的维护由软件发行承担，每次出货检查版本与安全更新；需要验证当前 pywebview 集成、运行目录权限以及目标 Windows 的兼容要求。若当前系统或后端仍需额外安装，启动器应在开窗前说明，且该环境不能宣传为已实现纯解压即用。

同样验证 VC++/.NET 等实际依赖，确认是否可按组件条款随包或应用本地部署。GPU驱动、操作系统架构和CPU指令不是随包Python能解决的；不静默安装或降级显卡驱动。

### 4.3 不占系统盘

作者侧所有新增大文件固定 D 盘。买家侧使用解压位置的相对目录，优先要求可写的非系统盘，不假设人人有D盘。若解压到C盘或受保护目录，先提示移动到可写非系统盘；只有C盘的机器，在当前“不占C盘”约束下不能承诺直接运行，需要非系统存储。

用户数据路径与程序版本目录分离，升级不新建一套历史。迁移、重命名、换盘后按相对路径重新定位模型；不可用的旧绝对路径不得导致联网重新下载或退回C盘。

验收范围是应用及其子进程主动写入的数据、模型、缓存和临时文件。Windows日志、页面文件和驱动自身缓存另列，不能承诺Windows运行过程中C盘零变化。

## 5. 高低配置适配策略

### 5.1 分开判断“能启动”和“能完成任务”

启动门槛包括目标Windows、x64、可执行的CPU指令、可写目录、运行库。聊天档位再按可用RAM、上下文预算与短样本速度决定。媒体档位同时考虑CUDA实际可用性、GPU架构与驱动、空闲显存、RAM和工作流健康结果。

检测信息以“实测可用 / 估算建议 / 未通过”区分，硬件阈值是候选策略，不能先写进商品页当兼容承诺。

### 5.2 候选适配矩阵

| 买家配置 | 默认聊天/界面策略 | 本地图片/视频策略 | 上架前要验证的边界 |
|---|---|---|---|
| 低于8GB内存、很老CPU、指令不支持 | 优先诊断与明确提示；不列正式流畅使用承诺 | 不自动起重引擎 | 界面是否能启动、是否有可用CPU运行时 |
| 约8GB RAM，无独显/核显 | 候选0.6B或1.7B、短上下文、简化动画，按空闲RAM决定 | 默认不启动GPU媒体引擎 | 聊天实际速度；不能因能启动就声称视频可用 |
| 约16GB RAM，无适配NVIDIA | 候选1.7B/4B，CPU聊天；翻译单独选经过语义评测的模型 | 图片CPU模式仅实验；视频默认不承诺；云端为可选 | AMD/Intel不误报为CUDA可用，不诱导无Key请求 |
| 约16GB RAM、支持运行时的4GB NVIDIA | 保守模型、短上下文，媒体时限制重任务 | 候选512图像、256短视频；均以真测为准 | 当前1650基线之外还需检查同档其他GPU |
| 约16～32GB RAM、6～8GB兼容NVIDIA | 候选4B，按资源调整上下文 | 实测后开放更高尺寸/帧数/批量 | 不从4GB单锚点直接外推可交付档位 |
| 约32GB以上、12～16GB兼容NVIDIA | 候选4B/7B，按吞吐和质量择优 | 可验证更高档；默认仍先选稳定档 | 新旧GPU架构、运行时编译支持、驱动 |
| 24GB以上兼容NVIDIA或多GPU | 自动检测并明确所选设备 | 高阶模型另做独立资源模块，不假设随包基础模型自动变高清 | 不默认占所有GPU；多卡并非自动合并显存 |

不能只依显存选择运行时。当前 `torch 2.8.0+cu126` 需要对其实际支持的GPU架构和驱动范围建立清单；某些高端新GPU也可能不兼容旧二进制。若确实需要多套运行时，先评估包体积与维护成本，再提供经过认证的兼容模块，禁止首次运行悄悄 pip install 随机版本。

### 5.3 自动策略与用户控制

- 首次按保守配置起步，短测后推荐档位，用户可在简单的“节省资源/均衡/优先质量”中选择。
- 换GPU、驱动、RAM或运行时版本后提示重新检测，不复用作者机器的benchmark.json。
- 配置快照记录实际尺寸、帧数、帧率、步数、模型、峰值资源和耗时；不得显示选择了32秒，实际生成2秒却不说明。
- 高配用户开放已验证档位与高级参数；未测组合清楚标实验。显存变大不意味着当前模型原生支持任意分辨率或长时序。
- OOM后释放任务资源、返回可读错误；本地任务最多一次有说明的降档恢复。付费云端不自动重新创建任务。
- 硬件不足时保留基础功能，不能以“点了按钮才连续崩溃”作为适配方案。

## 6. 买家版基础体验与可靠性

### 6.1 多语言生图/视频

沿用首版已确认问题的修复：保守语言识别、英文输出与完整性验证、长描述预算、数量/否定/位置保护、LoRA与权重语法保护、策略版本缓存。

买家版新增要求：

- 翻译默认选择通过语义测试的随包本地模型，不随聊天切到云端而悄悄联网；实际来源必须正确显示。
- 最小聊天模型能跑不等于翻译质量合格。若低配能承受的模型未通过某语种评测，明确限制并提供买家主动选择的联网翻译，不伪装成“精确翻译”。
- 对话、图片弹窗、视频弹窗走同一翻译服务与评测集；默认直接生成，复杂描述可选先查看译文。
- 网络兜底只在买家启用并具备自己凭据时使用；出厂不携带作者Key。离线且无法可靠翻译时停止提交，保留原文并解释原因。

### 6.2 独立任务与真实进度

每个任务拥有ID、状态和取消令牌；修复“新请求清旧取消位”，拒绝的新请求不能覆盖运行任务状态。统一管理对话和弹窗任务，支持排队、关闭弹窗后继续查看、重试与恢复。

显示真实的翻译/模型加载/采样/编码/下载阶段。ComfyUI事件需关联本任务prompt_id，断线退回查询；没有分母时只显示阶段与已用时。云端区分“停止等待”和“服务商已取消”。

### 6.3 作品和资源

保存必要的任务、译文、种子、参数和版本记录到买家本地；对话与弹窗引用同一作品。大视频使用受限的本地流式播放与Range请求，替代整文件base64传输；检查残缺视频再显示完成。

低配默认降低动画和后台采样负载，隐藏/最小化时减少无效渲染；聊天、翻译、语音、图片视频统一预算CPU/RAM/VRAM。常驻重模型和开机自启均不能作为强制默认。

## 7. 固定BAT入口的发布流水线

继续使用：`D:\AI\闲鱼展示文档\生成交付包.bat`。BAT只调度，不复制业务逻辑；`build_buyer_package.ps1`负责买家配置与步骤，`deliver_release.ps1`及现有Python工具负责构建、落位、校验。

建议默认执行路径：

1. **发布预检**：检测仓库、依赖、已知测试结果、资源清单、手机APK、许可文件和D盘余量。预估构建、解压验收、ZIP与保留旧包的峰值空间，不能只留固定2GB余量。
2. **冻结候选源码**：记录提交号、源码指纹、资源版本；从只读快照构建。未提交功能改动明确报告并阻断默认出货，避免构建过程中改源码导致前后端来自两版。
3. **加载buyer默认配置**：模板来自版本控制下的独立schema；禁止从作者preferences、注册表Key、聊天数据库或已运行dist反推默认值。
4. **构建到buyer暂存目录**：前端→主程序→便携运行时→本地模型→引擎→WebView2→手机APK与买家文档。模型和代码依赖锁定版本与校验值。
5. **静态检查**：源码与资源指纹、路径相对性、必备模块、实际生效buyer标记、私有信息扫描、未配置Key状态。依赖测试夹具使用精确白名单，不能给整个引擎豁免。
6. **隔离自检**：清洗应用环境变量，使用一次性QA数据根；不读作者目录、不改作者环境、不访问作者引擎、不更新作者快捷方式。
7. **压缩到临时产物**：默认一个完整ZIP，包含离线基础模型和必要引擎。手机APK若不变可复用，但必须通过源码指纹、签名身份和版本兼容检查。
8. **独立解压验收**：从ZIP完整解压到新的测试路径，验证路径移动和含中文/空格路径；以解压副本测试启动、买家默认值、双入口与模型发现，不能只测压缩源目录。
9. **独立完整性与隐私回读**：ZIP CRC、逐资源哈希、文件清单、必要买家文档及隐私扫描；最终发布包内不得残留自测产生的用户数据。
10. **原子发布**：所有必需检查通过后将临时ZIP改为正式名称；生成校验回执和发货记录，显示唯一推荐发送的文件。
11. **失败保留上一包**：失败返回非0，临时产物标失败，不显示可发货。取消构建也使用明确的状态，不能让BAT把“没有生成包”显示成成功发货。
12. **最后才清理**：仅清理验证成功后的旧buyer构建与旧交付包，保留当前和一个可回退版本；author目录、原用户数据、作品与资源源库不在清理范围。

当前BAT正常执行仍有输出路径和开始确认提示；优化目标是默认输出固定为指定目录，双击即可按默认buyer流程完成。高级预览/改目录作为可选参数保留，不要求卖家每次手动选择硬件档位。

### 7.1 完整包与更新包

默认首发始终保留完整离线包，买家不需要额外下载才能达到商品说明的基础能力。程序、模型、引擎采用模块化清单，是为了复用与后续更新，不是强迫首装买家拼装多个包。

后续可额外生成小型更新包：只更改程序时不重复传模型；稳定入口、用户数据和作品不跟rNN版本目录走。更新先验证版本兼容、签名/哈希，再切换程序目录；失败回退程序与对应数据库备份。

源文件指纹与SHA256只能校验一致性；更新来源真实性需要可信签名机制，不能把可被一起替换的ZIP与哈希清单当完整来源保护。Windows签名作为发行专项安排，不要求普通买家关闭杀毒软件来使用。

## 8. 交付卫生与售后

### 8.1 交付内容

允许：程序、依赖、经过审查的基础模型、干净引擎、买家默认模板、APK、买家说明、第三方许可、无私密数据的演示样例与发行清单。

禁止：作者聊天与记忆、API Key、私有端点、环境变量快照、配对令牌、注册表导出、作者真实提示词/作品、QA输出、浏览器数据、凭据文件、开发工具缓存、内部定价与销售策略文档。

既有 `BUYER_DOCS` 白名单继续维护；买家许可和使用说明可以进入包，作者内部商业材料不因此全部开放。公开GitHub代码与发货ZIP是不同产物，分别校验公开边界。

### 8.2 买家凭据

可选云端配置只接受买家自己的Key。优先采用Windows当前用户范围加密密文，存于买家数据目录；不把Key写成用户级公共环境变量。跨用户、跨机器移动时重新填写，不误导为密文可直接通用。

### 8.3 售后自助

买家界面提供“本机检测”“查看版本”“导出诊断”“打开数据目录”“恢复默认设置”。诊断包默认只含版本、硬件、引擎与模型状态、路径可写性、错误码和阶段耗时，不含聊天、提示词、音频、Key或签名下载地址。

错误提示给下一步，例如“此GPU不在当前运行时支持范围”“剩余内存不足，已选择小模型”“模型文件不完整，请重新解压”，而非Python堆栈。恢复默认不删除作品与聊天；清除数据单独提供明确预览。

商品说明与每轮发货文档由发行清单和兼容矩阵生成：软件/资源版本、包大小、解压及运行空间、支持系统、已测档位、离线/联网边界、模型来源与限制。具体第三方分发权利逐项核对后再随包，不仅收集文件名。

## 9. 上架前验收矩阵

### 9.1 环境隔离

- 同一Windows用户同时运行author和buyer，故意保留作者JARVIS_HOME、模型地址与常用引擎端口：buyer不得读取作者数据/Key或接管其引擎。
- author生成买家包过程中继续日常使用：买家构建不能改作者模型设置、快捷方式和服务；源码冻结避免边构建边改代码。
- 新Windows用户、无任何开发工具/作者环境变量、从解压ZIP启动；断网测试基础聊天、翻译与目标硬件媒体功能。
- 复制或改名整个安装目录、换非系统盘、路径包含中文和空格；重新定位模型，历史仍可访问。
- 只读路径、C盘解压、无非系统盘、磁盘满、杀软隔离文件、压缩包内直接启动均有明确反馈。

### 9.2 真实硬件

至少建立目标样本：8GB核显、16GB无适配NVIDIA、16GB+4GB NVIDIA、16～32GB+8GB NVIDIA、32GB+12/16GB NVIDIA，以及一台较新架构GPU。Windows11 x64先作为主验收系统；Windows10 x64需单独确认具体版本与运行库后才标支持。

资源限制模拟用于内存/显存分支测试；虚拟机适合干净系统/安装测试；两者都不能代替真实GPU内核和驱动测试。没有设备的格子写“未实测”，可以通过测试用户或后续测试环境补齐，不能直接沿用1650结果。

### 9.3 功能与质量

- 12语种、120条翻译集；每个正式随包翻译模型单独评测；数量、否定、左右、受保护语法关键用例全过，普通样本人工语义合格率目标≥95%。
- 对话/弹窗分别完成图片与视频；两入口混合50轮提交、取消、重试不串任务、不重复创建付费请求。
- 各认证硬件稳定档图片连续20次、短视频10次；至少2小时混合聊天/语音/媒体场景，记录峰值RAM/VRAM、p50/p95耗时及失败恢复。
- 高档参数逐档实测；作者本机只有低档结果时不认证高档。若分辨率/时长受限，界面实际输出必须与说明一致。
- 云端生成与联网翻译有真账号才标端到端验证；只跑假端点的标契约测试。默认基础能力的通过不依赖云端。
- 大视频流式播放、残缺文件、下载中断、退出重开、断电后的临时文件处理、数据库备份恢复均有回归。

### 9.4 发布阻断项

出现以下任一项即不得产生标记为“可发货”的正式新包：

1. 买家包包含作者私密数据、真实凭据、私有服务地址或硬件测量默认值。
2. 基础能力仍依赖开发机目录、系统Python、作者后台服务或临时联网下载。
3. 出货模型/运行时损坏、缺失、来源版本未记录或待核对分发材料未齐。
4. 声称支持的系统/硬件格子没有通过实际验证，或任务取消与翻译已知复现问题未修复。
5. 主程序、前端、资源清单与测试回执不属于同一冻结版本。
6. 新包失败时删掉了上一可用包，或发布过程影响作者日用环境。

## 11. 实施阶段与交付物

|---|---|---|---|
| A：隔离与稳定基线 | author/buyer配置、目录、进程、源码快照；修复翻译与取消 | 4～6 | 同机隔离测试通过，作者原数据和日用入口不受影响 |

| C：买家使用闭环 | 任务进度、作品播放、资源预算、错误恢复与自助诊断 | 4～6 | 双入口与长时间稳定性回归通过 |
| D：一键交付与更新 | 原BAT全流程、完整包验收、隐私检查、模块更新和回退 | 4～6 | 一次双击产出可发货包；失败不伤旧包和作者环境 |

主线约20～30个有效开发工作日。取得不同GPU测试环境、签名、真实云账号等外部等待另计。更大模型、全新语音引擎、账号/激活系统不计入主线，防止影响交付可靠性。

首个可验收里程碑应是“A+B”：作者与买家彻底隔离，同一完整包在已验证的低配与当前1650机器上能离线首次启动并选择正确能力。随后再扩充高配认证范围，而不是先声称覆盖所有电脑。
