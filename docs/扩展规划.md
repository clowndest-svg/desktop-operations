## 2. 方案

每项都写：动机 / 接口 / **爆炸半径** / **代价** / 验收判据。

### 2.1 提醒与日程（#80）

- **动机**：语音助手最日常的用途就是"十分钟后提醒我"。后端 `SchedulerService` 有
  `add_job/list_jobs/remove_job/set_enabled/run_now`，`JobSpec` 已带触发器与启停，
  但没有任何入口。没有它，这个助手只能回答问题。
- **接口**：新增 L4 门面 `jarvis/app/reminder_service.py`
  （`add(text, when)` / `all_reminders()` / `cancel(key)` / `toggle(id, on)` / `stats()`），
  到点动作 = 一条 `action="speak"` 的 job，由工具注册表派给 `Announcer`（出声 + 托盘气泡）；
  桥面 `reminders()` / `reminder_add(text, when)` / `reminder_cancel(key)` /
  `reminder_toggle(id, on)`；工具 `add_reminder`（模型可调用，风险 **SAFE**：只写自己的库，
  不碰机器——原方案的 LOW 被推翻，理由写在 `assistant_tools.py` 的模块注释里）。
- **时间解析**：只支持中文相对/绝对两种写法（`N 分钟/小时后`、`明天 9 点`、ISO），
  **不接模型**——把"解析时间"交给模型会让一条提醒变成一次计费调用，而且它错了没人知道。
  解析不出来就明确拒绝并给出可用写法，不猜。
- **爆炸半径**：1 个新 app 模块 + 1 个新工具 + 桥面 4 个方法 + 弹窗 1 个页签。
  不碰语音链路、不碰清理、不碰权限分档。调度器已在装配表里，只是从 0 任务变成有任务。
- **代价**：APScheduler 是内存态调度器 → **进程死了提醒就没了**。所以每条提醒落库
  （实际做法：**复用 `scheduler_jobs`**，用 `reminder:` 前缀做命名空间，没有新建表——
  一行 job 就是提醒本身，再造一张表就要处理两边同步，那是新的错法），
  启动时把未过期的重新挂上，过期的标成"错过"而不是静默丢弃。
- **验收**：建一条 1 分钟后的提醒 → 到点出声 + 托盘气泡 + 列表里状态变化；
  杀掉进程重启 → 提醒还在且到点仍响；测试覆盖解析（含"解析不出来要拒绝"）。

### 2.2 记忆面板（#81）

- **动机**：`memory` 已经存了 3 条，用户完全不知道它记了什么。**能被看见、能被抹掉**
  是记忆功能的前提，否则它只是一个偷偷长大的库。
- **接口**：桥面 `memory_list()` / `memory_forget(id)` / `memory_forget_all(confirmed)`；
  弹窗「记忆」页：按 kind 分组、显示来源与时间、逐条删 + 全清二次确认。
- **爆炸半径**：只读 + 删除，不写。删除走 `MemoryService.forget()`（已实现已测）。
- **代价**：一次查询渲染，无轮询（弹窗打开才取）。
- **验收**：面板里能看到真实条目；删一条之后 `list_memories()` 少一条；全清要 `confirmed`。

### 2.3 知识库入口（#82）

- **动机**：`knowledge` 有 `ingest/documents/retrieve/answer/forget/stats`，界面 0 入口；
  而且对话回答**不告诉用户它引用了哪几篇**——引用不可见，用户就没法判断它是在查还是
  在编。
- **接口**：桥面 `knowledge_stats()` / `knowledge_ingest(path)` / `knowledge_forget(doc_id)` /
  `knowledge_probe(query)`（返回命中片段与分数）；弹窗「知识库」页：文档表 + 添加路径 +
  命中测试框 + 删除。对话气泡底部加一行"引用：文件名 ×N"（有引用才显示）。
- **爆炸半径**：ingest 只读用户给的路径（不递归越界：目录走已有 `ingest_directory`，
  它有大小上限）；删除只删知识库里的记录，**绝不删磁盘文件**（UI 文案要写死这一句）。
- **代价**：ingest 会算 embedding（当前引擎是 hashing，本地、免费、快）。
- **验收**：加一个目录 → 文档表出现它 → 命中测试能搜到里面的一句话 → 删掉后搜不到。

### 2.4 全局热键（#83）

- **动机**：免点击唤醒是"在私人电脑上喊"；办公室/外放场合需要**按键**。
- **接口**：`jarvis/ui/hotkeys.py`，`RegisterHotKey` + 自己的消息循环节程；
  `Ctrl+Alt+K` = `voice.talk()`（开一轮免唤醒对话），`Ctrl+Alt+H` = 主界面显隐。
- **隐私边界（重要）**：只用 `RegisterHotKey` 注册**这两个组合键**，系统只在它们被按下
  时给我们一条 WM_HOTKEY。**不装键盘钩子、不读任何其他按键**——这是"能按出来说话"和
  "看着你打字"之间的线，写在模块 docstring 里。
- **爆炸半径**：新线程 + 两个注册；注册失败（被别的程序占了）只写日志，不影响启动。
- **代价**：一个空闲消息循环节程（几乎不耗 CPU）。
- **验收**：真机按一次 K 能进入"听你说"状态（日志 + 界面 turn 变化）。

### 2.5 开机自启（#84）

- **动机**：既然 X 不再退出、麦克风常驻，那"开机就在我身边"是同一件事的下一步。
- **接口**：托盘菜单一项「开机自启」勾选，读写
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的一个值（指向当前 exe）。
  **勾选状态从注册表回读**，不自己另记一份——两份真相迟早打架。
- **边界**：只写 HKCU（当前用户，不需要管理员），**绝不写 HKLM**；卸载 = 删那一个值。
- **爆炸半径**：一个注册表值；默认关。
- **验收**：勾上之后注册表里能看到那条、取消之后消失。

| 项 | 为什么不做 |

| 工作流编辑器 | `workflow.definitions()` 现在恒为空——缺的是"定义从哪来"的设计，不是界面。**而且这条链本来就是断的**：`jarvis/workflow/service.py:341` 给调度器写的 `action=definition.name`，注册表里没有任何地方按工作流的名字注册工具（`__main__.py` 里 `.register(` 全是组件，没有动态注册），所以 cron 工作流一旦到点就会以"未知动作"失败。要做界面，得先决定这个名字怎么落地 |
