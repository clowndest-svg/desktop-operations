# AI 能力扩展方案（2026-10-02）

> 前提：这是一份**先给结论再动手**的方案。里面每条都标了"页面现在有什么 / 模型能不能用 /
> 要改哪几个文件 / 怎么验收"，验收写不出来的条目一律不进实施。

## 0. 问题陈述

这个软件是 AI 桌面助手，但**页面和模型是两套眼睛**。

实测对照（同一台机器、同一个构建）：

| 能力 | 桥面（页面） | 工具注册表（模型） |
| --- | --- | --- |
| 方法/工具总数 | **60 个**桥面方法 | **18 个**工具 |
| 遥测快照 | `snapshot` | `system_report` ✅ |
| 负载趋势历史 | `activity_log` | ❌ 模型看不到 |
| Token 用量/缓存命中 | `usage_summary` | ❌ |
| 进程排行 | 面板有 | ❌ 无工具 |
| 结束进程 | `process_kill`（二次确认） | ❌ |
| 垃圾扫描 | `disk_scan` | `disk_scan` ✅ |
| 删除 | `disk_delete`（永不给模型） | ❌ **故意的，保持** |
| 清理建议 | `disk_advice`（AI 分析） | ❌ 只有页面按钮能触发 |
| 记忆 | `memory_list/forget/...` | ❌ 模型不能主动查/写 |
| 知识库 | `knowledge_state/probe/...` | ❌ 模型不能主动检索 |
| 会话管理 | `chat_sessions/new/switch/...` | ❌ |
| 音色选择 | `tts_voices/pick/preview` | ❌ |
| 设置读写 | `settings_get/apply` | ❌ |
| 窗口/宠物/托盘 | `window_hide/pet_toggle` | ❌ |
| 提醒 | `reminder_*` | ✅ 增删查，**没有开关** |
| 桌面控制 | — | ✅ 6 个（pyautogui 本轮才补上） |
| 命令行 | — | ✅ `run_powershell`（档位授权） |

还有一条更隐蔽的：**记忆和知识是"推"给模型的，不是模型"拉"的**。
`ChatService` 在每次提问时把 `memory.profile_block()` 塞进系统提示、把
`knowledge.retrieve(原始问题)` 塞进用户消息（`chat_service.py:478-501`）。
这意味着：

* 一旦对话进入多轮、或者模型中途调了工具拿到了新关键词，它**没法再查一次**知识库；
* 检索用的是用户原话，用户说"接着上次那个说"时，检索词就是"接着上次那个说"——**必然查不到**；
* 模型想"记住这件事"只能等回合结束后 `_observe()` 去猜，它自己说不上话。

所以"只能对话"不是错觉，是**接口面只连了一半**。

## 1. 不动的原则（先划红线）

1. **删除类永不给模型**：`disk_delete`、`delete_path` 保持只能人在界面上确认。
   `confirmed` 永远不能成为模型可填的参数（已经立过这条）。
2. **结束进程要给，但只给"看得见 + 打得开"**：模型可以列进程、可以提议结束哪个，
   真按下去要走和清理同一套二次确认 + 审计。
3. **改自己的设置要给，但要能看见**：模型可以改温度/上下文轮数/音色，
   但每次改都要回话"我把 X 从 A 改成 B"，并且设置面板上显示"这一项是 AI 改的"。
4. **档位不变**：命令行、键鼠这两条授权轴继续由人用手拨，模型只能读当前档位。
5. **不占 C 盘、不用你的 key 做演示、密钥只进环境变量**——照旧。
6. 每加一个工具都要过分层门禁（`ui` 不许被 `tools` 依赖，跨层用本地 `Protocol`）。

## 2. 方案（按"值不值"排序）

### P0-1 让模型能查自己的记忆和资料（`memory_search` / `remember` / `knowledge_search`）

* **为什么第一**：这是现在最容易被感知到的"她根本不记得我"。
* **接口**：`jarvis/tools/builtins/assistant_tools.py` 加三个 SAFE 工具，
  分别接 `MemorySurface.recall()` / `MemoryService.remember()` / `KnowledgeService.retrieve()`。
  参数：`query: str`、`limit: int`（默认 5）。返回带出处（`hit.citation()`）。
* **爆炸半径**：1 个工具文件 + `tools/service.py` 多两个注入参数 + `__main__.py` 传对象。
  不碰 `chat_service` 的注入逻辑（保留，两者互补）。
* **验收**：
  1. 真问一个只有知识库里有的事实 → `tools_used` 里必须出现 `knowledge_search`（而不是靠注入命中）；
  2. 说"记住我用的 JDK 是 Temurin 17" → 下一轮**新会话**里问"我用的 JDK 啥版本"能答对；
  3. 单测：三个工具的参数校验 + 服务没接时不注册（沿用本轮 `run_shell` 的教训）。

### P0-2 让模型看得见统计面板（`activity_log` / `usage_summary` / `list_processes`）

* **为什么**：页面已经画了趋势曲线和 Token 统计，模型却回答不了"我刚才卡不卡"
  "这个月花了多少钱"。数据全在库里，只是没接线。
* **接口**：新建 `jarvis/tools/builtins/insight_tools.py`，三个 SAFE 只读工具：
  * `system_trend(minutes=10, metric="cpu|memory|net")` → 读遥测采样历史；
  * `usage_stats(month="current")` → 读 `llm_usage`（含缓存命中、按 provider 分）；
  * `list_processes(sort_by="cpu|memory", limit=10)` → 读 `SystemMonitor` 现成的 top 列表。
* **爆炸半径**：1 个新工具模块 + 注册表注入 3 个 provider；服务侧零改动（方法都已存在）。
* **验收**：`--ask "最近十分钟 CPU 高不高，哪个进程最吃内存"` →
  答案里的数字必须和同一时刻面板上的读数一致（**数字对不上就算失败**）。

### P0-3 结束进程开放给模型，但停在确认那一步

* **接口**：`propose_kill_process(pid, name)` —— 工具本身**不杀**，它把候选写进
  一个待确认队列，桥面把它渲染成界面上那条已有的二次确认条；人点确认才真执行。
  这条复用的是 #77 已经建好的 `ProcessService` + 审计，不新造机制。
* **为什么不是直接给 `process_kill`**：给了就等于让模型能杀 `csrss.exe`。
  保护名单在删除侧已经有一套，进程侧要同一套（系统进程、安全软件、输入法、她自己）。
* **验收**：让模型"关掉记事本" → 界面出现待确认条 → 人点确认 → 进程真没了 + 审计落一行；
  让模型杀 `explorer.exe` → **在提议阶段就被拒**，且拒得说出原因。

### P1-4 看一眼屏幕（承接 #75）

* **前置探测**（半天，先做这个再决定要不要做后面）：写一个脚本用当前 provider 发一张
  截图问"图里有什么"，确认 `qwen3.8-flash` 到底吃不吃图。**吃不了就整条搁置**，
  不要接一个永远失败的工具（本轮 `run_shell` 的教训）。
* **接口**：`screen_capture(region="full|window", window_title=None)` → 返回图片句柄给多模态消息，
  或 OCR 后返回文字（`vision` extra 里 rapidocr 已经在）。
* **风险**：caution；截图可能拍到隐私内容 → 默认只拍**指定窗口**，全屏要人确认。

### P1-5 让模型能安排事，而不只是提醒（修 cron 断链）

* **实测到的断链**：`jarvis/workflow/service.py:341` 给调度器写的 `action=definition.name`
  （工作流自己的名字），而注册表里**没有任何地方**按工作流名注册工具 →
  cron 工作流一到点必然以"未知动作"失败。今天看不出来只因为定义数是 0。
* **做法二选一（要先定）**：① 工作流注册成工具（名字冲突、风险档怎么定都要设计）；
  ② 调度器的 action 允许 `workflow:<name>` 前缀，由组合根分发。
  **我倾向 ②**：改动小，不往注册表里塞动态工具。
* **配套工具**：`add_schedule(cron, action, args)`（caution，需人确认第一次）。
* **验收**：建一条"每天 09:00 报一下磁盘剩余"，`run_now` 一次 → 日志里能看到真的执行了动作，
  而不是 `未注册的工具`。

### P1-6 让它管得动自己（会话 / 设置 / 音色）

* `chat_search(query)`：跨会话搜历史（数据在 `chat_messages`，页面已有会话列表）；
* `settings_read()` / `settings_apply(key, value)`：**只开白名单键**
  （`tts.voice`、`telemetry.interval_ms`、`llm.max_history_turns`、思考强度），
  改完回话并标"AI 改的"；
* `voice_pick(name)`：换音色，用现成 `tts_voices` 的列表校验。

### P2 更多 AI 功能（有价值但不是接线问题，单独立项再评）

| 想法 | 一句话 | 卡在哪 |
| --- | --- | --- |
| 每日小结 | 09:00 播报"昨天跑了什么、清了多少、花了多少钱" | 依赖 P0-2 + P1-5 |
| 成本管家 | 缓存命中率掉了/某 provider 变贵就主动说 | 依赖 P0-2 |
| 屏幕问答 | "我这个表格里第三列是什么" | 依赖 P1-4 探测结果 |
| 语音可打断的确认流 | 它要杀进程时**用说的**问你一句 | 现链路有 barge-in，可行；但要先有 P0-3 |
| 长任务计划 | 已有 `planner`（max_steps=12）但界面零入口 | 缺 UI，不是缺能力 |

## 3. 明确不做

| 不做 | 为什么 |
| --- | --- |
| 给模型直接删除/格盘/改注册表 | 不可逆，且"AI 误删"是这个产品最贵的失败模式 |
| 让模型自己调档位（键鼠/命令行） | 授权必须由人给，否则档位形同虚设 |
| 键盘钩子式的"全程看着屏幕" | 那是键盘记录器的形态，隐私代价不对等 |
| 一次把 60 个桥面方法全变成工具 | 工具越多模型选错越多；只接"它自己看不到就会答错"的那些 |
