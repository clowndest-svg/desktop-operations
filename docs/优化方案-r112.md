## 一、这一轮只有一件事：用户说生图画错了

用户原话：

> 生图现在还有很大的问题你看看吧，我说的是"生成一张在月光下偏偏起舞的猪头人"，
> 它生成的图二明显有很大的问题，你优化一下吧，不要有问题

得到的是一团粉紫色块。**这不是"画得不够好"，是提示词根本没送对。**

### 现场是从那张 PNG 里读出来的，不是猜的

ComfyUI 把它收到的那张图直接存进输出 PNG 的 `prompt` tEXt 块。
`reports/read_image_prompt.py` 把那一块解出来，进 `CLIPTextEncode` 的原话是：

```
pink pig, pink skin, glowing pig, fiery pig, stars, moonlight, dreamlike,
头 人 起 舞 头 饰 随 舞 动 背 景 温 暖 篝 周 围 点 缀 为 童 话
```

两个错叠在一起：

1. **模型把用户那句话译错了，而且没人纠正它。** 用户说的是「猪头人」，
   模型译成了一头**粉色的猪**（`pink pig`），还把「翩翩起舞」整个丢了。
   `jarvis/app/image_prompt.py` 里有一张对着 anythingV3 调过的词典，
   对同一句给的是 `pig head, anthropomorphic pig, humanoid` —— 但**对话这条路从来没调过它**。
2. **21 个汉字被逐字送进了文本编码器。** SD1.5 的 CLIP 一个汉字都不认，
   真英文标签只有 7 个 —— 噪声占四分之三。画出来是一团认不出的东西，**还报了成功**。

### 最刺眼的一条：这些判据当时全是绿的

r110 已经为**这一句**写过一整个通过的测试类
（`tests/test_app_image_prompt.py` 的 `TestNothingUntranslatedReachesTheEngine`，
fixture 就是「生成一张在月光下偏偏起舞的猪头人」）。
它绿着，图还是错的 —— 因为它量的是 `expand(用户原话)`，而对话那条路**根本不走这一步**。

**量错了对象比量错值更危险：判据全绿，功能全坏。**

## 二、改了什么（五个点，每个都有实测支撑）

### 1. 把用户原话顺着递到词典那一层 【E】

`generate_image` 工具的表多了一个 `zh` 参数，**用户原话原封不动往下递**；
`ImageService.generate()` 收到之后先展开原话，再和模型写的英文合并。

`zh` **不是必填** —— 这一条是踩出来的：第一版写成必填，对话立刻报
`工具 generate_image 执行失败：参数不合法：缺少必填参数 zh`，
模型漏给参数时**一张图都出不来**。现在漏了只是那张表用不上，图照画
（`tests/test_app_image_gen.py::TestTheUsersOwnWordsReachTheEngine::test_a_model_that_forgets_zh_still_gets_its_picture`）。

### 2. `merge()`：**主体归词典，其余归模型** 【E】

不能一刀切，两种情况都是真的：

- 猪那一句里，模型的 `pink pig, glowing pig, fiery pig` 和词典的 `pig head, humanoid`
  拼在一起，四个"猪"的说法压过三个"猪头人"的说法 —— 画出来还是一头猪。**模型抢主体的标签必须死。**
- 但「画一台赛博朋克风格的摩托车」里，模型的 `neon lights, rain, night city` 比词典丰富得多，
  而且主体（摩托车）它根本没搞错。**整份丢掉就是把能画的变成画不了。**

所以分的线是"**有没有在抢同一个主体**"。这条线本身也修过一次：
第一版写的是"认出主体就整份用词典那份"，被上面那个摩托车用例当场抓住（丢掉了 `neon lights, rain, night city`）。

### 3. 认不出来就回空串，不把原话回出去 【E】

`expand()` 原来在"一个词都没匹配上"时**把 `raw` 原样回出去**。
理由当时写的是"不许拼半句英文糊弄"—— 顾虑是对的，**选的解法是错的**：
回原话等于把汉字当提示词交给只认英文的编码器。

现在回空串，上层说"这句话我一个词都没翻成英文标签"，而不是交一张噪声再管它叫成功。

### 4. 模型自己写的颜色，不许画在用户没上色的主体上 【E】

`pink skin` 不含主体词，所以第一版 `merge` 放它过去了 —— 可它和 `pink pig`
是**同一个误读生出来的同一层东西**：用户原话里一个颜色都没有。

**量过才改的**（同一批 4 个种子，`reports/measure_r112_pinkness.py` 逐像素数出来的）：

| 进引擎的那一串 | 粉色像素占比 | 平均饱和度 |
|---|---|---|
| 用户报的那张坏图 | 64.6% | 0.259 |
| 三个主体标签（含 `pink skin`） | **56.3%** | **0.325** |
| 同上 + `solo` | 53.8% | 0.320 |
| 同上 + `solo` + `fully clothed` | 54.2% | 0.320 |
| **去掉 `pink skin`** | **35.8%** | **0.209** |
| 去掉 `pink skin` + `solo` | 31.0% | 0.198 |

**4 个种子里带 `pink skin` 的那一组每一张都比去掉的高。** 而用户报的原话就是「粉色的一团」。

规则收得很窄：只剥**长在主体身上**的颜色（`{颜色} {skin/fur/hair/...}`）——
那个形状正是词典自己给会动的主体说颜色时用的（`image_prompt.py` 里 `if living` 那一段），
所以那个位置本来就归词典。用户真说了颜色（「画一只绿猫」）时这一条不开火；
`blue moonlight` 这种场景的色也不碰。

### 5. 主体标签改成加权的一条：`(pig head:1.4), humanoid` 【E】

r110 量过「猪头人」不能翻成自造的 `pig-headed humanoid`（4 个种子 0/4），
翻成它见过的三个标签（3/4）。**但那个 3/4 里失败的样子是"粉发少女头上顶一个猪头帽"**——
anythingV3 对 `anthropomorphic` 的理解是兽耳娘。

这一轮只动主体那一截、其余一个字不改，重跑 N=4（`reports/renders/r112-{A,B,C,D,E,F,G,H}-*.png`）：

| 主体那一截 | 4 个种子里画成**猪头人身** |
|---|---|
| `pig head, anthropomorphic pig, humanoid`（r110 原样重测） | 2/4 |
| 同上 + `solo` | 3/4 |
| 同上 + `solo` + `fully clothed` | 2/4 |
| 去掉 `pink skin` 后的三标签 | 2/4 |
| 去掉 `pink skin` + `solo` | 1/4 |
| 三标签**去掉 `anthropomorphic pig`**（不加权） | **0/4** |
| **去掉 `anthropomorphic pig` + `(pig head:1.4)`** | **4/4** |
| 加权重但**保留** `anthropomorphic pig` | 3/4 |

留下来的是 **4/4 的那一串**，而且 `tests/test_app_image_prompt.py` 里钉了一条
**把整串逐字钉死的锚**（`test_the_shipped_prompt_is_byte_for_byte_the_string_that_was_measured`）：
线上真正跑的和量过的必须是同一个字符串。

> `马头人`／`狼头人`／`鸟头人`／`猫头人` 四个**没动**，保持 r110 的三标签形状 ——
> 加权重那一轮只跑了猪这一句，照搬到别的动物上就是猜。

## 三、明确不做的（都是量完之后否掉的）

| 想做 | 为什么没做 |
|---|---|
| 加 `solo`（只画一个） | 颜色上零效果（56.3% → 53.8%），主体命中在 N=4 下 3/4→1/4 属于噪声。而且「画一群人」会被它毁掉 —— 用户没说的东西不许替她决定 |
| 加 `fully clothed` | 和对照组**分毫不差**（53.8% → 54.2%）。画出来是泳装，不是衣服 |
| 给「月光」补一个 `moon` | 4 个种子里**猪头从 4/4 掉到 2/4**，月亮只有 1/4 真画出来 —— 拿最重要的去换最不重要的。见 §五 |
| 改负面提示词去压"兽耳娘" | `image_gen.py:561` 那个留空是 r105 量出来的，注释写明"要再动这两个参数，先按 N>=4 个种子重测"。这一轮**没动它** |
| 修掉"某个种子还是画出兽耳少女" | **改不掉。** 见 §五 |

## 四、验收口径

- **E**：改动前后各 4 个种子、同一台引擎、同一个权重、同一个尺寸步数、**同一个种子**、
  负面词同样留空，两边出图对比（`reports/render_r112_compare.py`）。
  改之前那张**复现了用户报的缺陷**（粉色色块、没有猪头、没有月光、没在跳舞）；
  改之后是**猪头人身、全身构图、在星空月光下跳舞**。
- **E**：`(pig head:1.4)` 这个写法引擎真的吃 —— 加权与不加权的图肉眼可分（F vs G），
  而且**多一个 `anthropomorphic pig` 也会画得不一样（G vs H）**，说明权重语法确实被解析了。
- **E**：全量门禁 `reports/gates-r112.json`。
- **U**：没有在**真实对话**里端到端跑过一次（那要本地 7B 模型真的决定去调 `generate_image`，
  有随机性）。走的是集成判据：工具处理器 + 引擎面替身，
  钉"面板看到的是用户原话而不是模型写的那串"。

## 五、留下的边界（写在这里，不写成通过）

**"猪头人身"不是 4/4 的必然结果。** 8 组 × 4 个种子 = 32 张里，
最好的一组（现在上线的这一串）是 4/4，但**换一批种子不敢保证还是 4/4**。
anythingV3 是 512×512 的小动漫模型，「兽头人身的人形」对它是分布外的东西，
`anthropomorphic` 这个词在它那儿天然带"兽耳娘"的先验。

**能保证的是**：以前是**提示词送错了**（模型译错 + 21 个汉字当噪声），
现在是提示词**对着量过的表拼出来的**，而且**上线的那一串就是量出 4/4 的那一串**。
"某个种子会画出兽耳少女"是模型的先验，不是提示词的错 —— 这一条改不掉，
只能靠多抽几张。`solo` 和 `fully clothed` 试过了，量下来没用。

**「月光」那一半也不是每张都看得见月亮。** 把 36 张摆一起才发现的：上线的那一串里
`moonlight` 在，可 4 个种子的背景都是暗的、没有月亮圆盘（反倒是带 `pink skin` 的那几组有）。
词典里「月亮」是 `moon`、「月光」是 `moonlight`，两个词不是一回事 ——
但用户看到「月光下」的时候，要看的多半是月亮本身。所以单独量了一轮加 `moon`
（`reports/measure_r112_moon.py`）：

| 主体那一截 | 猪头人身 | 看得见月亮 |
|---|---|---|
| `(pig head:1.4), humanoid, moonlight, …`（上线这串） | **4/4** | 0/4 |
| 同上 + `moon` | 2/4 | 1/4 |

**用主体换月亮不划算，所以没加。** 留下的诚实说法是：「月光下」这一层现在只保证光，
不保证天上有一轮月亮；想要月亮就自己说「月亮」，那会走进 `moon` 那条。
