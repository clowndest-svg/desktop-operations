# 常驻待命与免点击冷唤醒（设计）

> 状态：**拆成两半**。§「免点击」这一半已经在 2026-10-01 落地——记住那一次按压，
> 之后开机自己回到待唤醒（实现见 `jarvis/app/preferences.py` 与
> `VoiceService.arm_if_remembered()`，操作口径见 `docs/桌面运维手册.md` §7）。
> 剩下的**常驻待命**（关窗后继续听、不打开界面也能被唤醒、一级廉价检测器、角落 pill）
> 仍是**纸面设计**，且实现位置在 `jarvis/**`（WorkBuddy 的管辖区）。见
> [[coordination-with-workbuddy]]。

## 1. 要解决的问题

用户的原话诉求：**「我直接对电脑说'你好小夜'它直接被唤醒启动和我沟通互动」**。

现在的真实行为是：开机 → 打开窗口 → 点「启用语音」→ 等约 2 分钟 → 才进入待唤醒。
这不算语音唤醒，这算"先按按钮再喊名字"。三个具体障碍，各自独立：

| 障碍 | 根因 | 量级 |
|---|---|---|
| 必须先点一下 | 麦克风只在 `VoiceService.enable()` 后才打开（这是刻意的隐私设计） | —— |
| 等 2 分钟 | 一级唤醒和二级识别被绑成同一件事：为了"听见有人叫我"，把 SenseVoice(~900 MB)、agent、TTS 全加载了 | 本机实测 2.0–2.5 分钟 |
| 不能后台 | 桌面壳没有托盘、没有全局热键，且 `关窗即退` 是写死的策略 | pywebview 无此 API |

**结论：这三条不能用"把加载提前"来糊。** 那只是把 2 分钟的等待从"点完按钮"挪到"开机"，
并且把 2.4 GB 常驻和空转开销从第一天就开始付。正确解法是业界通用的**两级唤醒**。

## 2. 业界怎么做（带出处的数字）

**桌面本地派其实大多不做唤醒词，做按住说话**：ChatGPT macOS 用 Option+空格直接唤起、
Superwhisper / Raycast AI Dictation / OpenWhispr 都是 hold-to-talk + 浮动 pill 实时波形，
**刻意不常驻监听**。这条路体验很好，但不满足用户"喊名字"的诉求，记在这里是为了说明
"常驻监听"在业界是少数派做法，需要额外的隐私代价来换。

**系统/音箱派用两级**：

- **Apple**：一级 32 神经元跑在常驻低功耗协处理器上，二级 192 神经元在主 CPU 上校验并做
  说话人个性化；公开目标是**误唤醒约每周一次**。
- **Windows MVA（Media Voice Activation）平台规范**：区分 SW KWS（主机 CPU）与 HW KWS（DSP 卸载）；
  detector armed 之后由硬件自持 FIFO、不打断 CPU；检出后 burst 回灌。规范**强制保留关键词前
  ≥1.6 秒**音频、驱动侧至少 5 秒缓冲；Wake-on-Voice 在 Modern Standby 下走"低功耗监听"态，
  唤醒延迟 ≤1 秒。
  → 这条直接告诉我们**预滚缓冲要做多大**（见 §4）。
- **Home Assistant**：microWakeWord（ESP32 一级）→ openWakeWord（主机二级），目的就是降 CPU 与误唤醒。

**一级引擎选型（这是能不能常驻的关键）**：

| 方案 | 体积 | 常驻 CPU | 内存 | 中文 | 授权 |
|---|---|---|---|---|---|
| **onnx-wakeword** | 130–167 KB | **<1%** | ~20 MB | 现成中文模型，且能用 TTS 合成语料一键训自定义 2–6 字词 | Apache 2.0 |
| openWakeWord | —— | 桌面约 2%（Kiwi Voice 实测） | —— | 需自训 | 开源 |
| Porcupine | —— | 厂商称 RPi3 上比竞品快 6.5×、准 11× | —— | 中文词需 Console 训练 | **商业授权** |

**推荐 onnx-wakeword 做一级**：它是表里唯一同时满足「常驻 CPU <1%」「中文可用」「无授权费」
三个条件的。Porcupine 更快更准，但要为个人项目引入商业授权和厂商训练流程，不划算。

误唤醒率参考：onnx-wakeword 安静环境 **<1 次/24 小时**；openWakeWord 目标 <0.5 次/小时。

## 3. 目标架构

```
开机
 └─ 只起 wake daemon（一级，<30 MB，CPU <1%）        ← 状态：dormant
      麦克风常开，但**只出布尔量**，不出转写、不出音频、不上传
        │ 检出「你好小夜」近似
        ▼
     预滚缓冲回放（关键词前 2 秒一起交给二级）        ← 状态：listening
        │
        ▼
     懒加载 SenseVoice → 转写 → 语义确认（必须含近似关键词） ← 状态：thinking
        │ 确认通过（挡住误唤醒的最后一道）
        ▼
     agent → TTS 回答；语音栈**保活 N 分钟**再卸载      ← 状态：speaking → armed
```

**二级语义确认我们其实已经有了**：`AsrWakeWordEngine` 就是"转写后在文本里找关键词"，
`normalize_for_match()` 还带同音变体折叠（`你好小夜/小叶/晓叶/业`）。所以二级确认不是新功能，
是把现有逻辑挪到一级之后当闸门——**误唤醒会再降一个量级**，因为一级只负责"像不像"，
二级负责"到底是不是"。

## 4. 预滚缓冲：别让第一句话丢掉

按 MVA 规范留 **≥1.6 秒**，我们取 **2 秒环形缓冲**。这决定了
`AudioSource` 必须能在检出后把"关键词之前的那段"一起交出来——否则用户说
「你好小夜 今天星期几」，一级在"夜"字后才触发，二级听到的开头是「今天星期几」，
前半句永久丢失。现有"唤醒语和指令一句话说完"的能力会因此静默退化，**必须一起实现**。

## 5. 那 2 分钟到底消没消失？（诚实回答）

**没有完全消失，但被挪到了不该感知的地方**：

- 开机后**立刻**可以喊名字（一级已就绪），这一点是真正的"免点击冷唤醒"。
- 但**当天第一次**喊它，仍要现场加载二级 → 第一次交互会等约 2 分钟。
- 之后语音栈保活（建议 10 分钟空闲再卸载），再喊就是秒级。

三个可选补法，按代价排：
1. **空闲预热**：开机后若 60 秒内没有任何交互，后台偷偷把二级加载好。代价是把 2.4 GB
   和空转开销提前付了——和我们正在查的 CPU 问题叠加，**不推荐默认开**。
2. **保活时间可调**：`voice.warm_keepalive_s`，默认 600。
3. **接受第一次慢**，但**必须在 pill 上如实显示进度**。这是推荐做法：不假装快，但给反馈。

## 6. 后台形态：角落 pill，不是全屏透明 HUD

pywebview **既没有托盘也没有全局热键** API，需要额外做：
- 托盘/图标：`pystray` 或自己 `Shell_NotifyIcon`
- 全局热键：`RegisterHotKey`
- 保活：`window.hide()` 可以让进程活着
- **WebView2 的透明窗口支持有限** → 不要做全屏透明 HUD，做**角落小 pill + 按需展开大窗**。
  这也正好是业界（Superwhisper / Raycast）验证过的形态。

## 7. 隐私：这条决策被推翻后，代价怎么还

**原决策**（已记录）：不做托盘、关窗即退。理由是"窗口没了但麦克风还开着是隐私缺陷"。

用户现在要常驻待命，**这个理由不会因此消失**，只能换成另一套机制来兑现同一个承诺。
业界的做法是"让用户始终可感知 + 能一键硬断"：iOS/macOS 的橙绿点、Win11 托盘麦克风图标、
Home Assistant Voice PE 的多色 LED 环加**物理静音开关**、豆包桌面悬浮球三态。

我们要做的四条，缺一不可：

1. **一级不出解码内容**。KWS 只输出布尔量；2 秒环形缓冲若未升级为唤醒即丢弃。
   全部离线、不上传（现状本就离线），这一条要写进对外文档而不是只写在代码里。
2. **状态必须可感知，且与真实状态成比例**：dormant（只有一级在跑）/ armed / listening /
   thinking / speaking 各自不同视觉与（可选）声音。声核 `VoiceCore` 就是为这个做的，
   见 [[hud-redesign]]。
3. **一个热键真正释放麦克风流**——是关闭采集设备，不是置一个 muted 标志位。
   这两者的区别在崩溃/卡死时才见分晓：标志位会随进程僵死而失效，关设备不会。
4. **唤醒后 TTS 应一声「我在」**。让人听见它确实开始听了，比任何指示灯都直接。

**残余风险要说清楚**：常驻麦克风的风险只能被降低，不能被归零。所以
**`voice.always_on` 默认关**，由用户在配置或界面里显式打开；没打开时行为退回今天这样
（点「启用语音」才开）。第一次上线这个功能就默认开，是不负责任的。

## 8. 顺带解决空转 CPU

现在"一级和二级混在一起常驻"的形态，正是空转开销的来源：为了听一句"你好小夜"，
每 32 ms 都在跑 SenseVoice 级别的东西。两级拆开后，常驻只剩 <1% CPU / ~20 MB 的一级。

⚠️ 但**不要引用"省了多少倍"这种数字**：本机的进程 CPU 测量在部分环境下是坏的
（详见 `docs/桌面运维手册.md` §7 末与 [[windows-script-env-pitfalls]] 第 11 条）。
这条收益必须在干净机器上按 PID 重测后才允许写进对外材料。

## 9. 需要 WorkBuddy 提供的接口（契约）

实现位置在它的管辖区，所以这里给出**它需要暴露什么**，前端与文档按此对接：

| 接口 | 说明 |
|---|---|
| `wakeword.engine: onnx` | 一级 KWS 引擎；保留 `asr` 作为纯二级方案 |
| `wakeword.onnx.model` / `.threshold` | 模型路径与灵敏度 |
| `wakeword.preroll_ms: 2000` | 预滚缓冲，喂给二级的音频必须含关键词前 2 秒 |
| `voice.always_on: false` | **默认关**，见 §7 |
| `voice.warm_keepalive_s: 600` | 二级保活时长 |
| `VoiceService.arm(always: bool)` | 生命周期：dormant → armed → awake → cooling |
| `mic_level`（0..1 RMS，随 pipeline 事件推） | **声核要画成真波形就必须靠它**。没有它，前端只能画状态几何体，绝不能自己编一条假波形冒充电平 |
| 托盘图标 + 全局热键（硬断麦克风） | 桌面壳层，pystray / RegisterHotKey |

## 10. 验收门槛（不达标就不合）

1. 开机后**不点任何东西**，喊「你好小夜」→ 进入 listening，延迟 ≤1 s（对齐 MVA 指标）。
2. 「你好小夜 今天星期几」一句说完 → 二级拿到的音频含完整前半句（预滚生效）。
3. 一级常驻 CPU 实测 **<1%**（干净机器、按 PID 量，方法见 §8 警告）。
4. 误唤醒：安静环境连续 24 小时 **<1 次**。
5. `scripts/verify_wake_words.py` 仍 **24/24**（这条测的是二级，一级不应把它挡掉）。
6. `voice.always_on=false` 时，行为与今天完全一致（默认关这个承诺必须可验证）。
